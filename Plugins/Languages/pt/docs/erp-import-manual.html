Importação de encomendas ERP – Manual

O que é a importação de encomendas ERP?

Sistemas ERP externos entregam encomendas ao Klacks como ficheiros XML. Existem três formas de transferência:

  • Drop-Point (recolha): O ERP coloca os ficheiros no armazenamento de ficheiros do Drop-Point – consoante a instalação, uma pasta no servidor Klacks (padrão) ou um armazenamento de objetos compatível com S3. O Klacks recolhe os ficheiros automaticamente de acordo com o calendário configurado.
  • Envio direto (Push): O ERP envia o ficheiro por HTTP POST para /api/erp-import/upload e autentica-se com um token de importação ERP como Bearer Token. São permitidos no máximo 50 MB por ficheiro.
  • Carregamento manual: Os administradores arrastam ficheiros XML diretamente para a zona de depósito nesta página (ou clicam na zona para selecionar um ficheiro). Após o carregamento, a importação é iniciada automaticamente e arranca dentro de um minuto; o botão Importar agora também a inicia a qualquer momento.

Drop-Point

O Drop-Point é a caixa de correio central para todos os ficheiros de importação. O Klacks gere-o automaticamente – ninguém tem de o criar ou configurar. A página mostra o seu conteúdo como uma vista de ficheiros com três áreas: Entrada (aguarda a próxima execução de importação), Processado (arquivo) e Erros (ficheiros ilegíveis ou inválidos, incluindo o motivo do erro). Os ficheiros com erro podem ser movidos de volta para a entrada através do botão Importar novamente.

  • Interruptor ativo (importação ativa) – pausa a importação automática; os ficheiros já depositados mantêm-se.
  • Indicador de estado – hora da última recolha e, se aplicável, o último erro.

Tokens de acesso

  • Para a entrega por Push, os administradores podem criar tokens de acesso — necessários apenas quando um sistema ERP externo entrega ficheiros via HTTPS. Cada token começa com o prefixo klacks_erp_.
  • O período de validade é configurável (1 a 730 dias, padrão 365 dias).
  • O texto do token é apresentado apenas uma vez, no momento da criação. Depois disso já não pode ser consultado – copie-o de imediato e guarde-o em segurança.
  • Um token de importação ERP é deliberadamente válido apenas para o endpoint de importação. Se um token cair em mãos erradas junto do prestador de serviços ERP, não é possível qualquer outro acesso à API do Klacks com ele.
  • Os tokens podem ser revogados a qualquer momento; o acesso termina de imediato.

Calendário

A recolha do Drop-Point segue uma expressão Cron (padrão 0 * * * * = de hora a hora) no fuso horário selecionado. Ambos são configurados nesta página. Uma expressão Cron inválida interromperia a importação – por isso a entrada é validada e valores inválidos não são guardados.

Formato XML (referência)

O elemento raiz é ErpOrderImport com os atributos obrigatórios schemaVersion (atualmente 1) e sourceSystemId. O sourceSystemId identifica o sistema de origem dentro dos ficheiros e garante a atribuição estável de clientes ao longo de todas as entregas – deve permanecer constante e permanente por sistema de origem. Cada encomenda é colocada num elemento <Order> próprio. Um ficheiro pode conter qualquer número de encomendas.

Elemento Obrigatório Formato Significado
ExternalOrderReference Sim Texto Referência de encomenda única do sistema ERP.
Description Não Texto Texto livre sobre a encomenda (p. ex. indicações de serviço); é apresentado na encomenda.
Customer Sim Elemento Dados do cliente da encomenda (ver subelementos).
Customer/ExternalCustomerReference Não (recomendado) Texto Referência externa do cliente; assegura a atribuição estável do cliente ao longo de todas as importações.
Customer/Company Sim Texto Nome da empresa do cliente.
Customer/Address/Street Sim Texto Rua e número de porta.
Customer/Address/Zip Sim Texto Código postal.
Customer/Address/City, Customer/Address/State, Customer/Address/Country Não Texto Localidade, cantão/região e país.
FromDate Sim yyyy-MM-dd Início da encomenda.
UntilDate Não yyyy-MM-dd Fim da encomenda; em falta ou vazio = sem prazo definido.
StartTime, EndTime Sim HH:mm Hora de início e de fim do serviço.
IsTimeRange Não true/false (padrão false) true = janela temporal dentro da qual se trabalha; false = turno fixo de StartTime até EndTime. Com true, Duration é obrigatório.
Duration Se IsTimeRange=true Elemento com <Hours> e <Minutes> (números inteiros) Duração do serviço individual, p. ex. 0 h 20 min para um serviço de 20 minutos na janela temporal 08:00–15:00. Opcional em turno fixo; se o elemento faltar, aplica-se a duração de StartTime até EndTime.
Quantity Não Número inteiro (padrão 1) Número de serviços.
SumEmployees Não Número inteiro (padrão 1) Número de colaboradores necessários.
Weekdays Sim Atributos monday … sunday, cada um true/false Dias da semana da encomenda; pelo menos um dia da semana tem de ser true, um atributo em falta conta como false. Encomendas sem dia da semana são rejeitadas.

Nota: Os nomes dos elementos são sensíveis a maiúsculas/minúsculas. Um ficheiro de exemplo completo pode ser obtido através do botão Descarregar ficheiro de exemplo por cima deste manual.

Atribuição de clientes

O Klacks atribui cada encomenda a um cliente:

  • Primeiro através da combinação do ID do sistema de origem com a referência externa do cliente – uma vez atribuída, esta referência permanece sempre associada ao mesmo cliente.
  • Sem referência externa, na primeira ocorrência a pesquisa é feita por empresa + código postal + rua; maiúsculas/minúsculas e espaços são ignorados.
  • Se não for encontrada nenhuma correspondência, o Klacks cria automaticamente um novo cliente.

Processamento & ciclo de vida

  • As encomendas importadas surgem como rascunho e têm de ser verificadas e seladas por planeadores ou administradores. Nesse momento, o planeador acrescenta também eventuais requisitos de qualificação — o ERP pode fornecê-los como indicação no campo Description.
  • Se o ERP entregar mais tarde uma versão alterada de uma encomenda já selada, o Klacks encerra automaticamente a encomenda antiga através da data de fim e cria uma nova versão em rascunho ligada à anterior. Os serviços futuros já planeados e não bloqueados da encomenda antiga são removidos e os planeadores são notificados.
  • Entregas repetidas e inalteradas (p. ex. uma exportação completa noturna) não desencadeiam nada.

Tratamento de erros & arquivo

  • Os ficheiros processados são movidos, no armazenamento de ficheiros, para a subpasta processed/ (arquivo, sem eliminação); aparecem na página de importação na área Processado.
  • Ficheiros ilegíveis ou inválidos são movidos para a subpasta error/ e aparecem na área Erros; a partir daí podem ser movidos de volta para a entrada através de Importar novamente.
  • Encomendas incompletas ou inválidas são rejeitadas (p. ex. sem dia da semana, com UntilDate anterior a FromDate ou com ExternalOrderReference duplicada no mesmo ficheiro); as restantes encomendas do mesmo ficheiro são, ainda assim, importadas.
  • Se um ficheiro contiver pelo menos uma encomenda rejeitada, é movido com o motivo da rejeição para a área Erros — as encomendas já importadas mantêm-se.
  • Os erros são registados e os administradores são notificados.
