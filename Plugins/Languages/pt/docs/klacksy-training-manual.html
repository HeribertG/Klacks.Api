Klacksy Formação - Manual

O que é a ferramenta de formação?

A ferramenta de formação controla a navegação interna da página do chatbot Klacksy. Quando um utilizador diz ou escreve "Klacksy, mostra-me os endereços", o Klacksy navega para a página correspondente e desloca-se até à secção correspondente.

Para que isto funcione, o Klacksy precisa, para cada âncora numa página, de uma lista de sinónimos em cada idioma (por exemplo, "endereços", "clientes", "contactos" para o destino addresses).

Separador "Destinos"

Lista de todas as âncoras encontradas no frontend (atributos HTML data-klacksy-target). Filtro de estado:

  • pending: a âncora existe, mas ainda não tem sinónimos
  • generated: os sinónimos foram gerados automaticamente e precisam de revisão
  • reviewed: sinónimos aprovados por um administrador
  • needs-review: marcado para nova revisão

Ao clicar num destino abre-se o editor de sinónimos por baixo. Aí é possível adicionar sinónimos, eliminá-los e aprová-los com "Guardar como revisto".

Separador "Feedback"

Mostra as entradas de utilizadores que o Klacksy não conseguiu associar (não foi encontrado nenhum sinónimo correspondente). Com base nesta lista é possível identificar quais sinónimos ainda estão em falta.

Separador "Métricas"

Vista geral de todos os destinos por estado. Ajuda a acompanhar o progresso da formação.

Pipeline de build (CLI)

Quando os templates recebem novas âncoras data-klacksy-target, é necessário regenerar o manifesto e os sinónimos iniciais. Os comandos seguintes também correm automaticamente no CI e no Husky pre-commit: 

cd C:\SourceCode\Klacks.Ui

# 1. Analisar templates → navigation-targets.json com todas as âncoras
npm run scan:targets

# 2a. Gerar sinónimos iniciais (todos os 4 core + 22 idiomas de plugin, ~2,5 h)
npm run generate:synonyms

# 2b. Apenas idiomas core (de/en/fr/it) — rápido, aprox. 9 min
npm run generate:synonyms -- --core-only

# 2c. Apenas preencher idiomas de plugin em falta — aprox. 45 min
npm run generate:synonyms -- --plugins-only

# 3. Verificar consistência da wake-word
npm run wake-word-lint

Importante: em npm run tem de estar presente --, para que as opções sejam passadas ao script. Sem --, o npm engole o parâmetro e o script corre no modo padrão.

Alternativa sem npm: npx tsx tools/generate-synonyms.ts --core-only.

Chave da API

A chave da API do LLM é procurada pela seguinte ordem:

  1. Variável de ambiente SYNONYM_LLM_API_KEY
  2. Tabela da BD llm_providers (fornecedor deepseek, is_enabled = true) — automaticamente através de uma chamada psql
  3. Caso contrário, mensagem de erro

O fornecedor padrão é o DeepSeek. Um fornecedor diferente pode ser definido através de SYNONYM_LLM_PROVIDER_ID=anthropic (ou outro fornecedor LLM configurado nas definições).

Passo 1 - scan:targets

Percorre todos os templates Angular à procura de atributos data-klacksy-target e gera o manifesto Application/Skills/Definitions/navigation-targets.json. Cada nova âncora surge depois no separador "Destinos" com o estado pending.

Passo 2 - generate:synonyms

Gera sinónimos iniciais para cada nova âncora a partir do data-klacksy-label-key e da categoria. Estado resultante: generated (tem de ser revisto por um administrador).

O script grava pontos de verificação do manifesto a cada 5 destinos, para que uma interrupção não perca os dados já gerados.

Passo 3 - wake-word-lint

Verifica a consistência da variante da wake-word (Olá Klacksy / Ei Klacksy / ...) em todos os idiomas. Evita que os sinónimos substituam a wake-word.

Modo de voz

O ícone do microfone no chat ativa o modo de voz. Assim que estiver ativo:

  • O microfone escuta continuamente e transcreve
  • Após um curto silêncio → envio automático da transcrição atual

Importante: assim que começar a escrever no campo de texto, o modo de voz é terminado automaticamente — caso contrário, o microfone sobreporia o texto que está a escrever com as suas próprias transcrições e enviaria a mensagem prematuramente.

Ciclo de formação típico

  1. Adicionar a âncora no template: 
    <div data-klacksy-target="addresses"
     data-klacksy-label-key="nav.addresses"
     data-klacksy-route="/workplace/client">
  2. npm run scan:targets && npm run generate:synonyms
  3. Reiniciar a API (a cache é recarregada no arranque)
  4. Abrir o separador "Destinos" → os novos destinos aparecem com o estado generated
  5. Rever/completar os sinónimos → "Guardar como revisto" → estado reviewed
  6. Testar com o Klacksy, por exemplo "Klacksy, mostra-me os endereços"
  7. Se o Klacksy não encontrar correspondência → separador "Feedback" → adicionar o sinónimo em falta
  8. Acompanhar o separador "Métricas" até tudo estar reviewed
