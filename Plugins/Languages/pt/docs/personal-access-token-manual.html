Manual dos Tokens de Acesso Pessoal

O que são os Tokens de Acesso Pessoal?

Os Personal Access Tokens (PATs) são chaves de API de longa duração que permitem a ferramentas e serviços externos um acesso seguro ao Klacks — sem nome de utilizador e palavra-passe.

Casos de utilização típicos:

  • MCP (Model Context Protocol) — permite que assistentes de IA como o Claude Desktop acedam diretamente às skills do Klacksy
  • Scripts de automação e pipelines de CI/CD
  • Ferramentas externas de monitorização e integração

Conceito de segurança

O Klacks nunca guarda o token em texto simples. Após a criação, é armazenado na base de dados exclusivamente um hash SHA-256 do token. O próprio token é apresentado apenas uma vez, imediatamente após a criação, e depois deixa de poder ser consultado.

Nota: Anote ou copie o token imediatamente após a criação. Em caso de perda, é necessário criar um novo token e revogar o antigo.

Criar um token

Passo a passo

  • Navegue até Configuração → Personal Access Tokens
  • Clique em Criar novo token
  • Atribua um nome descritivo (por exemplo, Claude Desktop ou CI-Pipeline)
  • Escolha o período de validade pretendido (1–730 dias, padrão: 365 dias)
  • Clique em Criar
  • Copie de imediato o token apresentado — é mostrado apenas uma vez

Formato do token

klacks_pat_<sequência de caracteres aleatória>

Cada token começa com o prefixo klacks_pat_, seguido de uma sequência de caracteres aleatória criptograficamente segura.

Período de validade

DuraçãoUtilização recomendada
1–30 diasTestes e desenvolvimento de curto prazo
90–180 diasPipelines de CI/CD com rotação regular
365 dias (padrão)Integrações permanentes (por exemplo, Claude Desktop)
730 diasIntegrações de sistemas de longo prazo

Utilizar o token

Bearer token no cabeçalho HTTP

O token é transmitido como Bearer token no cabeçalho Authorization de cada pedido à API:

Authorization: Bearer klacks_pat_...

Configurar o MCP com o Claude Desktop

O endpoint MCP (/mcp) permite que assistentes de IA como o Claude Desktop acedam diretamente a todas as skills do Klacksy — consultar dados de colaboradores, planear turnos, gerir grupos e muito mais.

Configuração na aplicação Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<o-seu-dominio-klacks>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

Substitua <o-seu-dominio-klacks> pelo endereço da sua instalação do Klacks e klacks_pat_... pelo token que criou.

Pedido direto à API (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<o-seu-dominio-klacks>/api/clients

Gestão e segurança

Visão geral dos tokens

Em Configuração → Personal Access Tokens pode ver todos os seus tokens, com nome, data de criação, data de expiração e última utilização. O token em texto simples nunca é apresentado nesta vista.

Revogar um token

Um token pode ser revogado a qualquer momento. Após a revogação, todos os pedidos com esse token são rejeitados de imediato. Revogue os tokens de imediato quando:

  • O token foi partilhado por engano
  • Um dispositivo ou serviço deixou de ser utilizado
  • Detetar atividades suspeitas

Expiração

Os tokens expirados são rejeitados automaticamente. O Klacks mostra na visão geral os tokens que expiram nos próximos 30 dias, para que possa criar novos tokens atempadamente.

Dicas de segurança

  • Utilize um token separado por serviço ou ferramenta
  • Escolha nomes descritivos para poder identificar claramente os tokens
  • Nunca guarde tokens em texto simples em sistemas de controlo de versões
  • Faça a rotação regular dos tokens, especialmente em utilização com CI/CD
  • Revogue os tokens de imediato em caso de suspeita de utilização indevida

Cada token está associado à sua conta de utilizador e possui as mesmas permissões que a sua conta. Trate os tokens com o mesmo cuidado que a sua palavra-passe.
