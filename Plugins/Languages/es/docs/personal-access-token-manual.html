Manual de tokens de acceso personal

¿Qué son los tokens de acceso personal?

Los Personal Access Tokens (PAT) son claves de API de larga duración que permiten a herramientas y servicios externos un acceso seguro a Klacks — sin nombre de usuario ni contraseña.

Casos de uso típicos:

  • MCP (Model Context Protocol) — permite a asistentes de IA como Claude Desktop acceder directamente a las skills de Klacksy
  • Agentes y asistentes de IA que trabajan con Klacks a través de MCP

Concepto de seguridad

Klacks nunca almacena el token en texto plano. Tras la creación, solo se guarda en la base de datos un hash SHA-256 del token. El token en sí se muestra una única vez, justo después de crearlo, y después ya no puede recuperarse.

Nota: Anote o copie el token inmediatamente después de crearlo. Si se pierde, debe crear un nuevo token y revocar el antiguo.

Crear un token

Paso a paso

  • Vaya a Configuración → Personal Access Tokens
  • Haga clic en Crear nuevo token
  • Asigne un nombre descriptivo (p. ej. Claude Desktop o Agente de IA planificación)
  • Seleccione el período de validez deseado (1–730 días, por defecto: 365 días)
  • Haga clic en Crear
  • Copie de inmediato el token mostrado — solo se muestra una vez

Formato del token

klacks_pat_<cadena aleatoria>

Cada token comienza con el prefijo klacks_pat_ seguido de una cadena aleatoria criptográficamente segura.

Período de validez

DuraciónUso recomendado
1–30 díasPruebas a corto plazo y desarrollo
90–180 díasAgentes de IA con rotación regular
365 días (por defecto)Integraciones permanentes (p. ej. Claude Desktop)
730 díasIntegraciones de sistemas a largo plazo

Modo de acceso

Al crear el token, usted decide qué puede hacer un agente externo con él:

  • Solo lectura (predeterminado) — el agente solo ve y utiliza herramientas de lectura. Cualquier intento de modificar datos se rechaza.
  • Lectura y escritura — el agente también puede modificar datos sin que una persona apruebe cada cambio. Elija este modo solo para agentes a los que confíe cambios.

El modo se muestra en la lista de tokens y no se puede cambiar después; si es necesario, cree un token nuevo. Los tokens existentes y los emitidos mediante un inicio de sesión OAuth (p. ej., un conector MCP) tienen el modo «Lectura y escritura».

Usar el token

Bearer-Token en el encabezado HTTP

El token se transmite como Bearer-Token en el encabezado Authorization de cada solicitud MCP al endpoint /mcp:

Authorization: Bearer klacks_pat_...

Configurar MCP con Claude Desktop

El endpoint MCP (/mcp) permite a asistentes de IA como Claude Desktop acceder directamente a todas las skills de Klacksy — consultar datos de empleados, planificar turnos, gestionar grupos y mucho más.

Configuración en la app Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<su-dominio-klacks>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Sustituya <su-dominio-klacks> por la dirección de su instalación de Klacks y klacks_pat_... por el token que ha creado.

Nota: Los tokens solo sirven para el acceso MCP de agentes de IA (endpoint /mcp). La API REST de Klacks (p. ej. /api/clients) no los acepta; exige el token de inicio de sesión.

Gestión y seguridad

Resumen de tokens

En Configuración → Personal Access Tokens puede ver todos sus tokens con nombre, fecha de creación, fecha de caducidad y último uso. El token en texto plano nunca se muestra en esta vista.

Revocar un token

Un token puede revocarse en cualquier momento. Tras la revocación, todas las solicitudes con ese token se rechazan de inmediato. Revoque los tokens inmediatamente si:

  • El token se ha compartido por error
  • Un dispositivo o servicio ya no se utiliza
  • Detecta actividades sospechosas

Caducidad

Los tokens caducados se rechazan automáticamente. Klacks muestra en el resumen los tokens que caducan en los próximos 30 días, para que pueda crear nuevos tokens a tiempo.

Consejos de seguridad

  • Utilice un token independiente por cada servicio o herramienta
  • Elija nombres descriptivos para poder identificar los tokens con claridad
  • Nunca guarde tokens en texto plano en sistemas de control de versiones
  • Rote los tokens con regularidad
  • Revoque los tokens de inmediato ante sospecha de uso indebido

Cada token está vinculado a su cuenta de usuario. A través de MCP dispone de los permisos de su cuenta, pero limitados como máximo al nivel de supervisor: aunque su cuenta sea de administrador, el token nunca tiene derechos de administrador. Además, el modo de acceso limita lo que el agente puede hacer: con «Solo lectura» solo utiliza funciones de lectura; con «Lectura y escritura» realiza cambios sin ninguna confirmación adicional. Trate los tokens con el mismo cuidado que su contraseña.
