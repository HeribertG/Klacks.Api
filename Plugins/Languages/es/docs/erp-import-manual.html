Importación de pedidos ERP – Manual

¿Qué es la importación de pedidos ERP?

Los sistemas ERP externos entregan pedidos como archivos XML a Klacks. Para la transferencia existen tres vías:

  • Drop-Point (recogida): El ERP deposita los archivos en el almacenamiento del Drop-Point – según la instalación, un directorio en el servidor de Klacks (estándar) o un almacenamiento de objetos compatible con S3. Klacks recoge los archivos automáticamente según el horario configurado.
  • Carga directa (Push): El ERP envía el archivo mediante HTTP POST a /api/erp-import/upload y se autentica con un token de importación ERP como Bearer-Token. Por archivo se permiten como máximo 50 MB.
  • Carga manual: Los administradores arrastran archivos XML directamente a la zona de carga en esta página (o hacen clic en la zona para seleccionar un archivo). Tras la carga, la importación se inicia automáticamente y comienza en menos de un minuto; el botón Importar ahora también la inicia en cualquier momento.

Drop-Point

El Drop-Point es el buzón central para todos los archivos de importación. Klacks lo gestiona automáticamente – nadie tiene que crearlo ni configurarlo. La página muestra su contenido como una vista de archivos con tres áreas: Entrada (a la espera de la próxima ejecución de importación), Procesado (archivo) y Error (archivos ilegibles o inválidos junto con el motivo del error). Los archivos con error pueden devolverse a la entrada mediante el botón Reintentar importación.

  • Interruptor de activación (Importación activa) – pausa la importación automática; los archivos ya depositados se conservan.
  • Indicador de estado – hora de la última recogida y, si existe, el último error.

Token de acceso

  • Para la entrega mediante Push, los administradores pueden crear tokens de acceso — necesarios solo cuando un sistema ERP externo entrega archivos vía HTTPS. Cada token comienza con el prefijo klacks_erp_.
  • El período de validez es configurable (de 1 a 730 días, por defecto 365 días).
  • El texto en claro del token se muestra solo una vez, al crearlo. Después ya no se puede recuperar – cópielo de inmediato y guárdelo de forma segura.
  • Un token de importación ERP es válido únicamente para el endpoint de importación, de forma intencionada. Si un token cae en manos equivocadas en el proveedor de ERP, no es posible ningún otro acceso a la API de Klacks con él.
  • Los tokens pueden revocarse en cualquier momento; el acceso finaliza de inmediato.

Horario

La recogida del Drop-Point sigue una expresión Cron (por defecto 0 * * * * = cada hora) en la zona horaria seleccionada. Ambos parámetros se configuran en esta página. Una expresión Cron inválida detendría la importación – por ello la entrada se valida y los valores inválidos no se guardan.

Formato XML (referencia)

El elemento raíz es ErpOrderImport con los atributos obligatorios schemaVersion (actualmente 1) y sourceSystemId. El sourceSystemId identifica el sistema emisor dentro de los archivos y garantiza la asignación estable del cliente en todas las entregas – debe permanecer constante de forma permanente por cada sistema origen. Cada pedido se encuentra en su propio elemento <Order>. Un archivo puede contener cualquier cantidad de pedidos.

Customer Sí Elemento Datos del cliente del pedido (véase los subelementos).
Customer/ExternalCustomerReference No (recomendado) Texto Referencia externa del cliente; garantiza la asignación estable del cliente en todas las importaciones.
Customer/Company Sí Texto Nombre de la empresa del cliente.
Customer/Address/Street Sí Texto Calle y número.
Customer/Address/Zip Sí Texto Código postal.
Customer/Address/City, Customer/Address/State, Customer/Address/Country No Texto Localidad, cantón/región y país.
FromDate Sí yyyy-MM-dd Inicio del pedido.
UntilDate No yyyy-MM-dd Fin del pedido; si falta o está vacío = indefinido.

Nota: Los nombres de los elementos distinguen mayúsculas y minúsculas. Un archivo de ejemplo completo puede obtenerse mediante el botón Descargar archivo de ejemplo sobre este manual.

Asignación de clientes

Klacks asigna cada pedido a un cliente:

  • Primero mediante la combinación de ID del sistema origen y referencia externa del cliente – una vez asignada, esta referencia permanece vinculada de forma permanente al mismo cliente.
  • Sin referencia externa, en la primera aparición se busca por empresa + código postal + calle; en este caso se ignoran las mayúsculas/minúsculas y los espacios.
  • Si no se encuentra ninguna coincidencia, Klacks crea el cliente automáticamente.

Procesamiento y ciclo de vida

  • Los pedidos importados se crean como borrador y deben ser revisados y sellados por planificadores o administradores. En este proceso, el planificador también añade los posibles requisitos de cualificación — el ERP puede incluirlos como indicación en el campo Description.
  • Si el ERP entrega posteriormente una versión modificada de un pedido ya sellado, Klacks cierra automáticamente el pedido antiguo mediante una fecha de fin y crea una nueva versión de borrador vinculada. Las asignaciones futuras ya planificadas y no bloqueadas del pedido antiguo se eliminan y se notifica a los planificadores.
  • Las entregas repetidas sin cambios (p. ej. una exportación completa nocturna) no desencadenan ninguna acción.

Gestión de errores y archivo

  • Los archivos procesados se mueven en el almacenamiento a la subcarpeta processed/ (archivo, sin eliminación); aparecen en la página de importación en el área Procesado.
  • Los archivos ilegibles o inválidos se mueven a la subcarpeta error/ y aparecen en el área Error; desde allí pueden devolverse a la entrada mediante Reintentar importación.
  • Los pedidos incompletos o inválidos son rechazados (p. ej. sin día de la semana, con UntilDate anterior a FromDate o con ExternalOrderReference duplicada en el mismo archivo); el resto de los pedidos del mismo archivo se importan de todos modos.
  • Si un archivo contiene al menos un pedido rechazado, se mueve con el motivo del rechazo al área Error — los pedidos ya importados se conservan.
  • Los errores se registran y se notifica a los administradores.
