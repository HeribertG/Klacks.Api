Klacksy Training - Guía

¿Qué es la herramienta de entrenamiento?

La herramienta de entrenamiento controla la navegación dentro de la página del chatbot Klacksy. Cuando un usuario dice o escribe "Klacksy, muéstrame las direcciones", Klacksy navega a la página correspondiente y se desplaza hasta la sección correspondiente.

Para que esto funcione, Klacksy necesita para cada ancla de una página una lista de sinónimos en cada idioma (p. ej. "direcciones", "clientes", "contactos" para el destino addresses).

Pestaña "Destinos"

Lista de todas las anclas encontradas en el frontend (atributos HTML data-klacksy-target). Filtro de estado:

  • pending: el ancla existe, pero todavía no tiene sinónimos
  • generated: los sinónimos se generaron automáticamente, necesitan revisión
  • reviewed: sinónimos aprobados por un administrador
  • needs-review: marcado para una nueva revisión

Al hacer clic en un destino se abre el editor de sinónimos debajo. Allí se pueden añadir sinónimos, eliminarlos y aprobarlos con "Guardar como revisado".

Pestaña "Comentarios"

Muestra las entradas de usuario que Klacksy no pudo asignar (no se encontró ningún sinónimo adecuado). A partir de esta lista se puede detectar qué sinónimos faltan todavía.

Pestaña "Métricas"

Vista general de todos los destinos según su estado. Ayuda a hacer seguimiento del progreso del entrenamiento.

Pipeline de compilación (CLI)

Cuando las plantillas reciben nuevas anclas data-klacksy-target, hay que regenerar el manifiesto y los sinónimos iniciales. Los siguientes comandos también se ejecutan automáticamente en CI y en el pre-commit de Husky: 

cd C:\SourceCode\Klacks.Ui

# 1. Escanear plantillas → navigation-targets.json con todas las anclas
npm run scan:targets

# 2a. Generar sinónimos iniciales (los 4 idiomas core + 22 locales de plugin, ~2.5 h)
npm run generate:synonyms

# 2b. Solo los idiomas core (de/en/fr/it) — rápido, aprox. 9 min
npm run generate:synonyms -- --core-only

# 2c. Solo completar los locales de plugin faltantes — aprox. 45 min
npm run generate:synonyms -- --plugins-only

# 3. Comprobar la consistencia de la palabra de activación
npm run wake-word-lint

Importante: en npm run debe incluirse -- para que las opciones se pasen al script. Sin --, npm se traga el flag y el script se ejecuta en modo estándar.

Alternativa sin npm: npx tsx tools/generate-synonyms.ts --core-only.

Clave de API

La clave de API del LLM se busca en este orden:

  1. Variable de entorno SYNONYM_LLM_API_KEY
  2. Tabla de base de datos llm_providers (proveedor deepseek, is_enabled = true) — automáticamente mediante llamada psql
  3. De lo contrario, mensaje de error

El proveedor por defecto es DeepSeek. Otro proveedor mediante SYNONYM_LLM_PROVIDER_ID=anthropic (o cualquier otro proveedor LLM configurado en los ajustes).

Paso 1 - scan:targets

Recorre todas las plantillas de Angular en busca de atributos data-klacksy-target y genera el manifiesto Application/Skills/Definitions/navigation-targets.json. Cada ancla nueva aparece después en la pestaña "Destinos" con estado pending.

Paso 2 - generate:synonyms

Genera para cada ancla nueva sinónimos iniciales a partir de data-klacksy-label-key y la categoría. Estado resultante: generated (debe ser revisado por un administrador).

El script escribe puntos de control del manifiesto cada 5 destinos, de modo que una interrupción no pierde los datos ya generados.

Paso 3 - wake-word-lint

Comprueba la consistencia de la variante de la palabra de activación (Hola Klacksy / Hey Klacksy / ...) en todos los idiomas. Evita que los sinónimos sobrescriban la palabra de activación.

Modo de voz

El icono de micrófono en el chat activa el modo de voz. Una vez activo:

  • El micrófono escucha y transcribe de forma continua
  • Ante un breve silencio → envío automático de la transcripción realizada hasta ese momento

Importante: en cuanto empiezas a escribir en el campo de texto, el modo de voz se finaliza automáticamente — de lo contrario, el micrófono sobrescribiría tu texto escrito con sus propias transcripciones y lo enviaría antes de tiempo.

Ciclo de entrenamiento típico

  1. Añadir el ancla en la plantilla: 
    <div data-klacksy-target="addresses"
     data-klacksy-label-key="nav.addresses"
     data-klacksy-route="/workplace/client">
  2. npm run scan:targets && npm run generate:synonyms
  3. Reiniciar la API (la caché se vuelve a leer al iniciar)
  4. Abrir la pestaña "Destinos" → los nuevos destinos aparecen con estado generated
  5. Revisar/completar los sinónimos → "Guardar como revisado" → estado reviewed
  6. Probar con Klacksy, p. ej. "Klacksy, muéstrame las direcciones"
  7. Si Klacksy no encuentra una coincidencia → pestaña "Comentarios" → añadir el sinónimo que falta
  8. Supervisar la pestaña "Métricas" hasta que todo esté reviewed
