Handleiding Persoonlijke Toegangstokens

Wat zijn Personal Access Tokens?

Personal Access Tokens (PAT's) zijn langlevende API-sleutels die externe tools en diensten veilige toegang tot Klacks geven — zonder gebruikersnaam en wachtwoord.

Typische toepassingen:

  • MCP (Model Context Protocol) — geeft AI-assistenten zoals Claude Desktop directe toegang tot Klacksy-skills
  • Automatiseringsscripts en CI/CD-pipelines
  • Externe monitoring- en integratietools

Beveiligingsconcept

Klacks slaat het token nooit in platte tekst op. Na het aanmaken wordt uitsluitend een SHA-256-hash van het token in de database opgeslagen. Het token zelf wordt slechts één keer, direct na het aanmaken, weergegeven en kan daarna niet meer worden opgehaald.

Opmerking: Noteer of kopieer het token onmiddellijk na het aanmaken. Bij verlies moet een nieuw token worden aangemaakt en het oude worden ingetrokken.

Token aanmaken

Stap voor stap

  • Navigeer naar Configuratie → Persoonlijke Toegangstokens
  • Klik op Nieuw token aanmaken
  • Geef een betekenisvolle naam op (bijv. Claude Desktop of CI-Pipeline)
  • Kies de gewenste geldigheidsduur (1–730 dagen, standaard: 365 dagen)
  • Klik op Aanmaken
  • Kopieer het weergegeven token onmiddellijk — het wordt maar één keer getoond

Tokenformaat

klacks_pat_<willekeurige tekenreeks>

Elk token begint met het voorvoegsel klacks_pat_ gevolgd door een cryptografisch veilige willekeurige tekenreeks.

Geldigheidsduur

DuurAanbevolen gebruik
1–30 dagenKortstondige tests en ontwikkeling
90–180 dagenCI/CD-pipelines met regelmatige rotatie
365 dagen (standaard)Permanente integraties (bijv. Claude Desktop)
730 dagenLangdurige systeemintegraties

Token gebruiken

Bearer-token in de HTTP-header

Het token wordt als bearer-token in de Authorization-header van elk API-verzoek meegestuurd:

Authorization: Bearer klacks_pat_...

MCP configureren met Claude Desktop

Het MCP-eindpunt (/mcp) geeft AI-assistenten zoals Claude Desktop directe toegang tot alle Klacksy-skills — medewerkersgegevens opvragen, diensten plannen, groepen beheren en nog veel meer.

Configuratie in de Claude Desktop-app (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<uw-klacks-domein>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

Vervang <uw-klacks-domein> door het adres van uw Klacks-installatie en klacks_pat_... door uw aangemaakte token.

Direct API-verzoek (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<uw-klacks-domein>/api/clients

Beheer en beveiliging

Overzicht van tokens

Onder Configuratie → Persoonlijke Toegangstokens ziet u al uw tokens met naam, aanmaakdatum, vervaldatum en laatste gebruik. Het token in platte tekst wordt in deze weergave nooit getoond.

Token intrekken

Een token kan op elk moment worden ingetrokken. Na het intrekken worden alle verzoeken met dit token onmiddellijk geweigerd. Trek tokens onmiddellijk in wanneer:

  • Het token per ongeluk is doorgegeven
  • Een apparaat of dienst niet meer wordt gebruikt
  • U verdachte activiteiten opmerkt

Verval

Verlopen tokens worden automatisch geweigerd. Klacks toont in het overzicht tokens die binnen de komende 30 dagen verlopen, zodat u tijdig nieuwe tokens kunt aanmaken.

Beveiligingstips

  • Gebruik per dienst of tool een apart token
  • Kies betekenisvolle namen zodat tokens eenduidig te herkennen zijn
  • Bewaar tokens nooit in platte tekst in versiebeheersystemen
  • Roteer tokens regelmatig, vooral bij gebruik in CI/CD
  • Trek tokens onmiddellijk in bij vermoeden van misbruik

Elk token is gekoppeld aan uw gebruikersaccount en beschikt over dezelfde rechten als uw account. Behandel tokens met dezelfde zorgvuldigheid als uw wachtwoord.
