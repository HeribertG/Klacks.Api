Henkilökohtaisten käyttöoikeustunnusten (Personal Access Tokens) käsikirja

Mitä henkilökohtaiset käyttöoikeustunnukset ovat?

Henkilökohtaiset käyttöoikeustunnukset (Personal Access Tokens, PAT) ovat pitkäikäisiä API-avaimia, jotka mahdollistavat ulkoisille työkaluille ja palveluille turvallisen pääsyn Klacksiin — ilman käyttäjätunnusta ja salasanaa.

Tyypilliset käyttötapaukset:

  • MCP (Model Context Protocol) — mahdollistaa tekoälyavustajille, kuten Claude Desktopille, suoran pääsyn Klacksy-taitoihin
  • Tekoälyagentit ja avustajat, jotka työskentelevät Klacksin kanssa MCP:n kautta

Tietoturvakonsepti

Klacks ei koskaan tallenna tokenia selkokielisenä. Luomisen jälkeen tietokantaan tallennetaan ainoastaan tokenin SHA-256-tiiviste. Itse token näytetään vain kerran välittömästi luomisen jälkeen, eikä sitä voi enää sen jälkeen noutaa.

Huomio: Kirjoita tai kopioi token muistiin heti luomisen jälkeen. Jos se katoaa, on luotava uusi token ja mitätöitävä vanha.

Tokenin luominen

Vaihe vaiheelta

  • Siirry kohtaan Määritykset → Personal Access Tokens
  • Napsauta Luo uusi token
  • Anna kuvaava nimi (esim. Claude Desktop tai Tekoälyagentti suunnittelu)
  • Valitse haluttu voimassaoloaika (1–730 päivää, oletus: 365 päivää)
  • Napsauta Luo
  • Kopioi näytetty token heti — se näytetään vain kerran

Tokenin muoto

klacks_pat_<satunnainen merkkijono>

Jokainen token alkaa etuliitteellä klacks_pat_, jota seuraa kryptografisesti turvallinen satunnainen merkkijono.

Voimassaoloaika

KestoSuositeltu käyttö
1–30 päivääLyhytaikaiset testit ja kehitys
90–180 päivääTekoälyagentit säännöllisellä rotaatiolla
365 päivää (oletus)Pysyvät integraatiot (esim. Claude Desktop)
730 päivääPitkäaikaiset järjestelmäintegraatiot

Käyttötila

Tunnusta luodessasi päätät, mitä ulkoinen agentti saa sillä tehdä:

  • Vain luku (oletus) — agentti näkee ja käyttää ainoastaan lukevia työkaluja. Jokainen yritys muuttaa tietoja hylätään.
  • Luku ja kirjoitus — agentti voi lisäksi muuttaa tietoja ilman, että ihminen hyväksyy jokaisen muutoksen erikseen. Valitse tämä tila vain agenteille, joille uskot muutokset.

Tila näkyy tunnusluettelossa, eikä sitä voi muuttaa jälkikäteen; luo tarvittaessa uusi tunnus. Olemassa olevilla tunnuksilla ja OAuth-kirjautumisen (esim. MCP-liittimen) kautta myönnetyillä tunnuksilla on tila ”Luku ja kirjoitus”.

Tokenin käyttäminen

Bearer-token HTTP-otsikossa

Token välitetään Bearer-tokenina jokaisen /mcp-päätepisteeseen lähetettävän MCP-pyynnön Authorization-otsikossa:

Authorization: Bearer klacks_pat_...

MCP:n määrittäminen Claude Desktopissa

MCP-päätepiste (/mcp) mahdollistaa tekoälyavustajille, kuten Claude Desktopille, suoran pääsyn kaikkiin Klacksy-taitoihin — työntekijätietojen kyselyt, vuorojen suunnittelu, ryhmien hallinta ja paljon muuta.

Määritys Claude Desktop -sovelluksessa (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<teidän-klacks-verkkotunnus>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Korvaa <teidän-klacks-verkkotunnus> Klacks-asennuksenne osoitteella ja klacks_pat_... luomallanne tokenilla.

Huomautus: Tokenit toimivat vain tekoälyagenttien MCP-käytössä (päätepiste /mcp). Klacksin REST-rajapinta (esim. /api/clients) ei hyväksy niitä; se vaatii kirjautumistokenin.

Hallinta ja tietoturva

Tokenien yleiskatsaus

Kohdassa Määritykset → Personal Access Tokens näet kaikki tokenisi nimen, luontipäivän, vanhenemispäivän ja viimeisimmän käytön kera. Selkokielistä tokenia ei koskaan näytetä tässä näkymässä.

Tokenin mitätöiminen

Token voidaan mitätöidä milloin tahansa. Mitätöinnin jälkeen kaikki tällä tokenilla tehdyt pyynnöt hylätään välittömästi. Mitätöi tokenit heti, jos:

  • Token on vahingossa joutunut vääriin käsiin
  • Laitetta tai palvelua ei enää käytetä
  • Havaitset epäilyttävää toimintaa

Vanheneminen

Vanhentuneet tokenit hylätään automaattisesti. Klacks näyttää yleiskatsauksessa tokenit, jotka vanhenevat seuraavien 30 päivän aikana, jotta ehdit luoda uudet tokenit ajoissa.

Tietoturvavinkit

  • Käytä erillistä tokenia jokaiselle palvelulle tai työkalulle
  • Valitse kuvaavat nimet, jotta tokenit voidaan tunnistaa yksiselitteisesti
  • Älä koskaan tallenna tokeneita selkokielisenä versionhallintajärjestelmiin
  • Rotaa tokenit säännöllisesti
  • Mitätöi tokenit heti, jos epäilet väärinkäyttöä

Jokainen token on sidottu käyttäjätiliisi. MCP:n kautta token saa tilisi käyttöoikeudet, mutta enintään Supervisor-tasoisina: vaikka tilisi olisi ylläpitäjä, token ei koskaan saa ylläpitäjän oikeuksia. Käyttötila rajoittaa lisäksi sitä, mitä agentti saa tehdä: tilassa ”Vain luku” se käyttää vain lukutoimintoja; tilassa ”Luku ja kirjoitus” se tekee muutokset ilman erillistä vahvistusta. Käsittele tokeneita samalla huolellisuudella kuin salasanaasi.
