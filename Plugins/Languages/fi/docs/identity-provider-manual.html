Identiteetintarjoajan käsikirja

Johdanto

Identiteetintarjoajat mahdollistavat käyttäjien todennuksen ulkoisten hakemistopalveluiden kuten LDAP:n, Active Directoryn tai OAuth2/OpenID Connectin kautta.

Tuetut tarjoajatyypit:

  • LDAP - Lightweight Directory Access Protocol
  • Active Directory - Microsoft Active Directory
  • OAuth2 - OAuth 2.0 -valtuutuskehys
  • OpenID Connect - Identiteettikerros OAuth 2.0:n päällä

Asiakastuonti

Kun "Käytä asiakastuontiin" on aktivoitu, seuraavat tiedot tuodaan:

  • Sukunimi - sn (sukunimi) tai displayName
  • Etunimi - givenName
  • Titteli - title (ammattinimike)
  • Yritys - company
  • Osoite - street/streetAddress, postalCode, l (kaupunki), st (lääni), c (maa)
  • Sukupuoli - personalTitle-kentästä (Herra/Rouva) Active Directoryssa

Huomautus: OpenLDAP:ssa sukupuoli on oletuksena "Neutraali" ja se voidaan korjata manuaalisesti.

Kirjautuminen hakemistopalvelun kautta

Kun "Käytä tunnistautumiseen" on otettu käyttöön ja tallennettu, henkilöt voivat kirjautua Klacksiin hakemistopalvelun salasanallaan. Kukaan ei saa pääsyä automaattisesti: ylläpitäjä hyväksyy jokaisen henkilön Kirjautumisen hyväksyntä -välilehdellä.

  • Välilehti luettelee hakemistotilit (enintään 1000; rajaa luetteloa haulla).
  • Tilin valinta luo uuden Klacks-tilin ilman roolia ja ilman salasanaa. Olemassa olevia Klacks-tilejä ei koskaan oteta haltuun: jos sähköpostiosoite on jo Klacks-tilin käytössä, riviä ei voi valita. Poista ensin kyseinen tili tai vaihda sen sähköpostiosoite käyttäjähallinnassa.
  • Valinnan poistaminen poistaa Klacks-tilin käytöstä; uusi valinta ottaa sen uudelleen käyttöön, kunhan tilillä ei ole roolia. Käytöstä poistettu tili, jolla on edelleen rooleja, otetaan uudelleen käyttöön käyttäjähallinnassa.
  • Poistuvat henkilöt: kun joku lähtee, poista valinta myös Klacksissa. Tilin poistaminen käytöstä hakemistossa estää uudet kirjautumiset, mutta jo käynnissä olevat istunnot jatkuvat, kunnes ne vanhenevat.
  • Tiliä, jolla ei ole sähköpostiosoitetta hakemistossa, ei voi hyväksyä.
  • Omaa tiliä ei voi muuttaa tällä välilehdellä.
  • Henkilö, jolla on oikeat hakemiston tunnukset mutta ei hyväksyntää, saa ilmoituksen, että tiliä ei ole hyväksytty ja että hänen tulee ottaa yhteyttä ylläpitäjään.

Klacks hakee henkilön bind-käyttäjällä ja tarkistaa sitten salasanan hakemistopalvelusta, joten kirjautumisnimen ei tarvitse vastata sähköpostiosoitetta.

Salaus

Pelkkä LDAP portissa 389 lähettää salasanat salaamattomina; lomake näyttää varoituksen LDAP-tarjoajalle ilman SSL:ää. Käytä LDAPS:ää ("Käytä SSL:ää", portti 636) aina, kun hakemistoa käytetään kirjautumiseen.

Active Directory: kirjautuminen vain LDAPS:n kautta

Klacks kirjaa henkilöt sisään Active Directoryyn vain LDAPS:n kautta (portti 636). Ilman SSL:ää lomake näyttää varoituksen, kukaan ei voi kirjautua ja Kirjautumisen hyväksyntä -välilehti pysyy suljettuna. Ilman SSL:ää asiakastuonti ja yhteyden testaus toimivat vain, kun Klacks toimii suoraan Windows-ympäristössä; Docker-ympäristössä (Linux) Active Directory vaatii LDAPS:n kaikkeen.

  • Isäntä: täysin määritelty nimi (FQDN) täsmälleen siinä muodossa kuin se on toimialueohjaimen varmenteessa, esim. dc01.example.local. IP-osoite ei kelpaa, koska varmenteen tarkistus vertaa nimeä.
  • Luota CA:han: Klacksia ajavan tietokoneen on luotettava varmentajaan, joka on myöntänyt toimialueohjaimen varmenteen. Windows: tuo CA-varmenne tietokoneen Luotetut juurivarmentajat (Trusted Root Certification Authorities) -varastoon, esim. certutil -addstore Root ca.cer (järjestelmänvalvojana).
  • Nimenselvitys: jos FQDN-nimeä ei voi selvittää DNS:n kautta, lisää hosts-merkintä (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: liitä CA-varmenne PEM-tiedostona API-konttiin, aseta ympäristömuuttuja LDAPTLS_CACERT osoittamaan sen polkuun ja lisää FQDN asetuksella extra_hosts, jos DNS ei selvitä sitä. Jos toimialueohjain ei lähetä CA-varmennetta (itse allekirjoitettu varmenne), sen oma varmenne PEM-tiedostona toimii luottamusankkurina. Ilman luotettua varmennetta yhteys evätään ja siitä ilmoitetaan yhteysvirheenä.
  • Bind-tili: anna se käyttäjän päänimenä (UPN), esim. svc-klacks@example.local.

Mitkä tilit tuodaan

  • Käytöstä poistettuja tilejä ja Active Directoryn järjestelmätilejä ei koskaan tuoda eikä luetteloida.
  • Rajaa palvelutilit pois käyttäjäsuodattimella, esim. vain yhden ryhmän jäsenet: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Vinkkejä

Synology NAS LDAP-palvelimena

Synology NAS:ia voidaan käyttää LDAP-palvelimena. Tätä varten on asennettava "LDAP Server" -paketti tai Docker-kontti OpenLDAP:lla.

  • Tarjoajatyyppi: "LDAP" (ei "Active Directory")
  • Käyttäjäsuodatin: (objectClass=inetOrgPerson)
  • Käyttäjät kirjautuvat uid-tunnuksellaan tai sähköpostiosoitteellaan
  • Suosi LDAPS:ää (portti 636)

Yhteyden testaaminen

Käytä "Testaa yhteys" -painiketta asetusten tarkistamiseen. Se näyttää käyttäjäsuodattimen löytämien aktiivisten tilien määrän (käytöstä poistettuja tilejä ja järjestelmätilejä ei lasketa) sekä joitakin esimerkkikäyttäjänimiä. Määrän perässä oleva "+" tarkoittaa, että hakemistopalvelin pysähtyi tulosrajaansa, joten tilejä on enemmän.
