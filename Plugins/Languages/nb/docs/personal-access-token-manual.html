Håndbok for personlige tilgangstokener

Hva er personlige tilgangstokener?

Personal Access Tokens (PAT-er) er langlevde API-nøkler som gir eksterne verktøy og tjenester sikker tilgang til Klacks — uten brukernavn og passord.

Typiske bruksområder:

  • MCP (Model Context Protocol) — gir KI-assistenter som Claude Desktop direkte tilgang til Klacksy-ferdigheter
  • KI-agenter og assistenter som arbeider med Klacks via MCP

Sikkerhetskonsept

Klacks lagrer aldri tokenet i klartekst. Etter opprettelse lagres kun en SHA-256-hash av tokenet i databasen. Selve tokenet vises bare én gang, rett etter opprettelsen, og kan deretter ikke hentes frem igjen.

Merk: Skriv ned eller kopier tokenet umiddelbart etter opprettelsen. Ved tap må et nytt token opprettes og det gamle tilbakekalles.

Opprette token

Steg for steg

  • Naviger til Konfigurasjon → Personlige tilgangstokener
  • Klikk på Opprett nytt token
  • Gi tokenet et beskrivende navn (f.eks. Claude Desktop eller KI-agent planlegging)
  • Velg ønsket gyldighetstid (1–730 dager, standard: 365 dager)
  • Klikk på Opprett
  • Kopier tokenet som vises, umiddelbart — det vises kun én gang

Token-format

klacks_pat_<tilfeldig tegnstreng>

Hvert token starter med prefikset klacks_pat_ etterfulgt av en kryptografisk sikker, tilfeldig tegnstreng.

Gyldighetstid

VarighetAnbefalt bruk
1–30 dagerKorttidstesting og utvikling
90–180 dagerKI-agenter med regelmessig rotasjon
365 dager (standard)Permanente integrasjoner (f.eks. Claude Desktop)
730 dagerLangsiktige systemintegrasjoner

Tilgangsmodus

Når du oppretter tokenet, bestemmer du hva en ekstern agent kan gjøre med det:

  • Kun lesing (standard) — agenten ser og bruker utelukkende lesende verktøy. Ethvert forsøk på å endre data avvises.
  • Lesing og skriving — agenten kan i tillegg endre data uten at en person godkjenner hver enkelt endring. Velg denne modusen bare for agenter du betror endringer.

Modusen vises i tokenoversikten og kan ikke endres i etterkant; opprett et nytt token ved behov. Eksisterende tokens og tokens utstedt via en OAuth-pålogging (f.eks. en MCP-kobling) har modusen «Lesing og skriving».

Bruke token

Bearer-token i HTTP-header

Tokenet sendes som et bearer-token i Authorization-headeren for hver MCP-forespørsel til endepunktet /mcp:

Authorization: Bearer klacks_pat_...

Konfigurere MCP med Claude Desktop

MCP-endepunktet (/mcp) gir KI-assistenter som Claude Desktop direkte tilgang til alle Klacksy-ferdigheter — spørre etter ansattdata, planlegge vakter, administrere grupper og mye mer.

Konfigurasjon i Claude Desktop-appen (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<ditt-klacks-domene>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Erstatt <ditt-klacks-domene> med adressen til din Klacks-installasjon og klacks_pat_... med tokenet du har opprettet.

Merk: Tokener fungerer bare for MCP-tilgangen til AI-agenter (endepunkt /mcp). REST-API-et til Klacks (f.eks. /api/clients) godtar dem ikke; det krever innloggingstokenet.

Administrasjon og sikkerhet

Oversikt over tokener

Under Konfigurasjon → Personlige tilgangstokener ser du alle tokenene dine med navn, opprettelsesdato, utløpsdato og siste bruk. Tokenet i klartekst vises aldri i denne visningen.

Tilbakekalle token

Et token kan tilbakekalles når som helst. Etter tilbakekallingen avvises alle forespørsler med dette tokenet umiddelbart. Tilbakekall tokener umiddelbart når:

  • Tokenet er delt ved en feil
  • En enhet eller tjeneste ikke lenger brukes
  • Du oppdager mistenkelig aktivitet

Utløp

Utløpte tokener avvises automatisk. Klacks viser i oversikten tokener som utløper i løpet av de neste 30 dagene, slik at du kan opprette nye tokener i tide.

Sikkerhetstips

  • Bruk et separat token per tjeneste eller verktøy
  • Velg beskrivende navn slik at tokenene kan identifiseres entydig
  • Lagre aldri tokener i klartekst i versjonskontrollsystemer
  • Roter tokener regelmessig
  • Tilbakekall tokener umiddelbart ved mistanke om misbruk

Hvert token er knyttet til brukerkontoen din. Via MCP har tokenet rettighetene til kontoen din, men høyst på supervisornivå: Selv om kontoen din er administrator, har tokenet aldri administratorrettigheter. I tillegg begrenser tilgangsmodusen hva agenten kan gjøre: med «Kun lesing» bruker den bare lesefunksjoner; med «Lesing og skriving» utfører den endringer uten ytterligere bekreftelse. Behandle tokener med samme aktsomhet som passordet ditt.
