Identitetsleverandør - Manual

Innledning

Ved bruk av identitetsleverandører kan brukerautentisering utføres via eksterne katalogtjenester som LDAP, Active Directory, OAuth2/OpenID Connect.

Støttede leverandørtyper:

  • LDAP - Standard Lightweight Directory Access Protocol
  • Active Directory - Microsoft Active Directory
  • OAuth2 - OAuth 2.0-autorisasjonsrammeverk
  • OpenID Connect - Identitetslag over OAuth 2.0

Klientimport

Hvis "Bruk for klientimport" er aktivert, importeres følgende data:

  • Etternavn - sn (etternavn) eller displayName
  • Fornavn - givenName
  • Stilling - title (stillingstittel)
  • Firma - company
  • Adresse - street/streetAddress, postalCode, l (by), st (fylke), c (land)
  • Kjønn - For Active Directory, hentes fra personalTitle (Herr/Frau)

Merk: For OpenLDAP settes kjønn som standard til "Nøytral" og kan korrigeres manuelt.

Innlogging via katalogen

Når "Bruk for autentisering" er aktivert og lagret, kan brukere logge inn i Klacks med katalogpassordet sitt. Ingen får tilgang automatisk: administratoren godkjenner hver enkelt person i fanen Godkjenning av innlogging.

  • Fanen viser katalogkontoene (maksimalt 1000; bruk søket for å begrense listen).
  • Når du huker av for en konto, opprettes en ny Klacks-konto uten rolle og uten passord. Eksisterende Klacks-kontoer blir aldri overtatt: hvis e-postadressen allerede brukes av en Klacks-konto, kan raden ikke hukes av. Slett den kontoen eller endre e-postadressen i brukeradministrasjonen først.
  • Når du fjerner haken, deaktiveres Klacks-kontoen; hvis du huker av igjen, reaktiveres den, så lenge den ikke har noen rolle. En deaktivert konto som fortsatt har roller, reaktiveres i brukeradministrasjonen.
  • Avslutning av ansettelse: når noen slutter, fjern haken i Klacks også. Hvis kontoen deaktiveres i katalogen, blokkeres nye innlogginger, men økter som allerede kjører, fortsetter til de utløper.
  • En konto uten e-postadresse i katalogen kan ikke godkjennes.
  • Din egen konto kan ikke endres i denne fanen.
  • En person med riktig legitimasjon i katalogen, men uten godkjenning, får meldingen om at kontoen ikke er godkjent og at vedkommende bør kontakte administratoren.

Klacks slår opp personen med bind-brukeren og kontrollerer deretter passordet mot katalogen, slik at innloggingsnavnet ikke trenger å samsvare med e-postadressen.

Kryptering

Vanlig LDAP på port 389 sender passord ukryptert; skjemaet viser en advarsel for en LDAP-leverandør uten SSL. Bruk LDAPS ("Bruk SSL", port 636) når katalogen brukes til innlogging.

Active Directory: innlogging bare via LDAPS

Klacks logger personer inn i Active Directory bare via LDAPS (port 636). Uten SSL viser skjemaet en advarsel, ingen kan logge inn, og fanen for godkjenning av innlogging forblir lukket. Uten SSL fungerer klientimport og tilkoblingstest bare når Klacks kjører direkte på Windows; i Docker (Linux) krever Active Directory LDAPS for alt.

  • Vert: det fullstendige navnet (FQDN) nøyaktig slik det står i sertifikatet til domenekontrolleren, f.eks. dc01.example.local. En IP-adresse fungerer ikke, fordi sertifikatkontrollen sammenligner navnet.
  • Stol på CA-en: datamaskinen som kjører Klacks, må stole på sertifiseringsinstansen som utstedte sertifikatet til domenekontrolleren. Windows: importer CA-sertifikatet til datamaskinens Klarerte rotsertifiseringsinstanser, f.eks. certutil -addstore Root ca.cer (som administrator).
  • Navneoppslag: hvis FQDN-et ikke kan løses opp via DNS, legg til en hosts-oppføring (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: monter CA-sertifikatet som en PEM-fil i API-containeren, sett miljøvariabelen LDAPTLS_CACERT til stien, og legg til FQDN-et med extra_hosts hvis DNS ikke løser det opp. Hvis domenekontrolleren ikke sender noe CA-sertifikat (selvsignert sertifikat), fungerer dets eget sertifikat som PEM-fil som tillitsanker. Uten et klarert sertifikat blir tilkoblingen avvist og rapportert som en tilkoblingsfeil.
  • Bind-konto: angi den som user principal name (UPN), f.eks. svc-klacks@example.local.

Hvilke kontoer importeres

  • Deaktiverte kontoer og systemkontoer i Active Directory importeres aldri og vises aldri i listen.
  • Utelat tjenestekontoer med brukerfilteret, f.eks. bare medlemmer av én gruppe: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Tips

Bruk av Synology NAS som LDAP-server

Du kan bruke en Synology NAS som LDAP-server. I så fall må du installere "LDAP Server"-pakken eller en Docker-container med OpenLDAP.

  • Leverandørtype: "LDAP" (ikke "Active Directory")
  • Brukerfilter: (objectClass=inetOrgPerson)
  • Brukerne logger inn med uid eller e-postadresse
  • Foretrekk LDAPS (port 636)

Test av tilkobling

Bruk knappen "Test tilkobling" for å bekrefte konfigurasjonen. Den viser antall aktive kontoer som brukerfilteret finner (deaktiverte kontoer og systemkontoer telles ikke) og noen eksempelbrukernavn. Et "+" etter tallet betyr at katalogserveren stoppet ved resultatgrensen, slik at det finnes flere kontoer.
