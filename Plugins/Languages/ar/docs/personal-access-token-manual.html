دليل Personal Access Tokens

ما هي Personal Access Tokens؟

Personal Access Tokens (PATs) هي مفاتيح API طويلة الأمد تتيح للأدوات والخدمات الخارجية الوصول الآمن إلى Klacks — دون اسم مستخدم وكلمة مرور.

حالات الاستخدام النموذجية:

  • MCP (Model Context Protocol) — يتيح لمساعدي الذكاء الاصطناعي مثل Claude Desktop الوصول المباشر إلى مهارات Klacksy
  • نصوص الأتمتة وخطوط أنابيب CI/CD
  • أدوات مراقبة وتكامل خارجية

مفهوم الأمان

لا يخزّن Klacks أبدًا الرمز بصيغته الصريحة. بعد الإنشاء، يُخزَّن في قاعدة البيانات فقط تجزئة SHA-256 للرمز. يُعرض الرمز نفسه مرة واحدة فقط مباشرة بعد إنشائه، ولا يمكن استرجاعه بعد ذلك.

ملاحظة: دوّنوا أو انسخوا الرمز فورًا بعد إنشائه. في حال فقدانه يجب إنشاء رمز جديد وإلغاء الرمز القديم.

إنشاء رمز

خطوة بخطوة

  • انتقلوا إلى الإعدادات ← Personal Access Tokens
  • انقروا على إنشاء رمز جديد
  • أدخلوا اسمًا واضحًا (مثال: Claude Desktop أو CI-Pipeline)
  • اختاروا مدة الصلاحية المطلوبة (1–730 يومًا، الافتراضي: 365 يومًا)
  • انقروا على إنشاء
  • انسخوا الرمز المعروض فورًا — يُعرض مرة واحدة فقط

صيغة الرمز

klacks_pat_<سلسلة أحرف عشوائية>

يبدأ كل رمز بالبادئة klacks_pat_ متبوعة بسلسلة أحرف عشوائية آمنة تشفيريًا.

مدة الصلاحية

المدةالاستخدام الموصى به
1–30 يومًااختبارات وتطوير قصير الأمد
90–180 يومًاخطوط أنابيب CI/CD مع تدوير منتظم
365 يومًا (الافتراضي)تكاملات دائمة (مثال: Claude Desktop)
730 يومًاتكاملات نظام طويلة الأمد

استخدام الرمز

رمز Bearer في ترويسة HTTP

يُرسَل الرمز كرمز Bearer في ترويسة Authorization لكل طلب API:

Authorization: Bearer klacks_pat_...

إعداد MCP مع Claude Desktop

تتيح نقطة النهاية MCP (/mcp) لمساعدي الذكاء الاصطناعي مثل Claude Desktop الوصول المباشر إلى جميع مهارات Klacksy — الاستعلام عن بيانات الموظفين، تخطيط المناوبات، إدارة المجموعات وأكثر من ذلك.

الإعداد في تطبيق Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<نطاق-Klacks-الخاص-بكم>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

استبدلوا <نطاق-Klacks-الخاص-بكم> بعنوان تثبيت Klacks الخاص بكم وklacks_pat_... بالرمز الذي أنشأتموه.

طلب API مباشر (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<نطاق-Klacks-الخاص-بكم>/api/clients

الإدارة والأمان

نظرة عامة على الرموز

تحت الإعدادات ← Personal Access Tokens تشاهدون جميع رموزكم مع الاسم وتاريخ الإنشاء وتاريخ الانتهاء وآخر استخدام. لا يُعرض الرمز الصريح أبدًا في هذا العرض.

إلغاء رمز

يمكن إلغاء الرمز في أي وقت. بعد الإلغاء، تُرفض فورًا جميع الطلبات التي تستخدم هذا الرمز. ألغوا الرموز فورًا عند:

  • تسريب الرمز عن طريق الخطأ
  • عدم استخدام جهاز أو خدمة بعد الآن
  • ملاحظة أنشطة مشبوهة

الانتهاء

تُرفض الرموز المنتهية الصلاحية تلقائيًا. يعرض Klacks في نظرة عامة الرموز التي ستنتهي صلاحيتها خلال الثلاثين يومًا القادمة، حتى تتمكنوا من إنشاء رموز جديدة في الوقت المناسب.

نصائح أمنية

  • استخدموا رمزًا منفصلًا لكل خدمة أو أداة
  • اختاروا أسماء واضحة لتتمكنوا من تمييز الرموز بدقة
  • لا تخزّنوا الرموز أبدًا بصيغتها الصريحة في أنظمة التحكم بالإصدارات
  • دوّروا الرموز بانتظام، خاصة عند الاستخدام مع CI/CD
  • ألغوا الرموز فورًا عند الاشتباه بسوء استخدام

كل رمز مرتبط بحساب المستخدم الخاص بكم ويتمتع بنفس الصلاحيات التي يتمتع بها حسابكم. تعاملوا مع الرموز بنفس الحرص الذي تتعاملون به مع كلمة المرور الخاصة بكم.
