دليل مزود الهوية

مقدمة

تتيح مزودات الهوية مصادقة المستخدمين عبر خدمات الدليل الخارجية مثل LDAP وActive Directory أو OAuth2/OpenID Connect.

أنواع المزودات المدعومة:

  • LDAP - بروتوكول الوصول الخفيف للدليل القياسي
  • Active Directory - Microsoft Active Directory
  • OAuth2 - إطار تفويض OAuth 2.0
  • OpenID Connect - طبقة هوية فوق OAuth 2.0

استيراد العملاء

عند تفعيل "استخدام لاستيراد العملاء"، يتم استيراد البيانات التالية:

  • اسم العائلة - sn (اسم العائلة) أو displayName
  • الاسم الأول - givenName
  • المسمى الوظيفي - title (المسمى الوظيفي)
  • الشركة - company
  • العنوان - street/streetAddress وpostalCode وl (المدينة) وst (الولاية) وc (الدولة)
  • الجنس - من خلال personalTitle (السيد/السيدة) في Active Directory

ملاحظة: في OpenLDAP يكون الجنس افتراضياً "محايد" ويمكن تصحيحه يدوياً.

تسجيل الدخول عبر الدليل

عندما يكون خيار "استخدام للمصادقة" مفعّلًا ومحفوظًا، يمكن للأشخاص تسجيل الدخول إلى Klacks بكلمة مرور الدليل الخاصة بهم. لا أحد يحصل على الوصول تلقائيًا: يوافق المسؤول على كل شخص في علامة التبويب الموافقة على تسجيل الدخول.

  • تعرض علامة التبويب حسابات الدليل (بحد أقصى 1000؛ استخدم البحث لتضييق القائمة).
  • يؤدي تحديد حساب إلى إنشاء حساب Klacks جديد دون دور ودون كلمة مرور. لا يتم أبدًا تبنّي حسابات Klacks الموجودة: إذا كان عنوان البريد الإلكتروني مستخدمًا بالفعل في حساب Klacks، فلا يمكن تحديد الصف. احذف ذلك الحساب أولًا أو غيّر بريده الإلكتروني في إدارة المستخدمين.
  • تؤدي إزالة التحديد إلى تعطيل حساب Klacks؛ وإعادة التحديد تعيد تفعيله ما دام ليس له دور. أما الحساب المعطّل الذي ما زال له أدوار فيُعاد تفعيله في إدارة المستخدمين.
  • ترك العمل: عندما يغادر شخص ما، أزل التحديد في Klacks أيضًا. تعطيل الحساب في الدليل يمنع عمليات تسجيل الدخول الجديدة، لكن الجلسات الجارية بالفعل تستمر إلى أن تنتهي صلاحيتها.
  • لا يمكن الموافقة على حساب ليس له عنوان بريد إلكتروني في الدليل.
  • لا يمكن تغيير حسابك الخاص في علامة التبويب هذه.
  • الشخص الذي يملك بيانات اعتماد صحيحة في الدليل لكن دون موافقة يتلقى رسالة تفيد بأن الحساب غير موافَق عليه وبأن عليه التواصل مع المسؤول.

أسماء تسجيل الدخول

النوعأسماء تسجيل الدخول المقبولة
Active DirectorysAMAccountName أو userPrincipalName أو عنوان البريد الإلكتروني
LDAPuid أو عنوان البريد الإلكتروني

يبحث Klacks عن الشخص باستخدام مستخدم Bind ثم يتحقق من كلمة المرور في الدليل، لذلك لا يلزم أن يطابق اسم تسجيل الدخول عنوان البريد الإلكتروني.

التشفير

يرسل LDAP العادي على المنفذ 389 كلمات المرور دون تشفير؛ ويعرض النموذج تحذيرًا لمزود LDAP بدون SSL. استخدم LDAPS ("استخدام SSL"، المنفذ 636) كلما استُخدم الدليل لتسجيل الدخول.

Active Directory: تسجيل الدخول عبر LDAPS فقط

يسجّل Klacks دخول الأشخاص إلى Active Directory عبر LDAPS فقط (المنفذ 636). بدون SSL يعرض النموذج تحذيرًا، ولا يمكن لأحد تسجيل الدخول، وتبقى علامة تبويب الموافقة على تسجيل الدخول مغلقة. بدون SSL لا يعمل استيراد العملاء واختبار الاتصال إلا عندما يعمل Klacks مباشرة على Windows؛ أما في Docker (Linux) فيتطلب Active Directory استخدام LDAPS في كل شيء.

  • المضيف: الاسم المؤهل بالكامل (FQDN) تمامًا كما يظهر في شهادة وحدة تحكم النطاق، مثل dc01.example.local. عنوان IP لا يعمل، لأن فحص الشهادة يقارن الاسم.
  • الثقة بمرجع التصديق: يجب أن يثق الكمبيوتر الذي يشغّل Klacks بمرجع التصديق الذي أصدر شهادة وحدة تحكم النطاق. في Windows: استورد شهادة مرجع التصديق إلى مخزن مراجع التصديق الجذر الموثوق بها الخاص بالكمبيوتر، مثل certutil -addstore Root ca.cer (بصلاحيات المسؤول).
  • تحليل الأسماء: إذا تعذّر تحليل FQDN عبر DNS، فأضف إدخالًا إلى ملف hosts (في Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: اربط شهادة مرجع التصديق كملف PEM داخل حاوية API، واضبط متغير البيئة LDAPTLS_CACERT على مسارها، وأضف FQDN باستخدام extra_hosts إذا لم يحلّله DNS. إذا لم ترسل وحدة تحكم النطاق شهادة مرجع تصديق (شهادة موقّعة ذاتيًا)، فإن شهادتها نفسها كملف PEM تعمل كمرتكز للثقة. بدون شهادة موثوق بها يُرفض الاتصال ويُبلَّغ عنه كخطأ اتصال.
  • حساب Bind: أدخله بصيغة اسم المستخدم الأساسي (UPN)، مثل svc-klacks@example.local.

الحسابات التي يتم استيرادها

  • لا يتم أبدًا استيراد الحسابات المعطّلة وحسابات النظام في Active Directory ولا عرضها.
  • استبعد حسابات الخدمة باستخدام فلتر المستخدمين، مثل أعضاء مجموعة واحدة فقط: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

نصائح

استخدام Synology NAS كخادم LDAP

يمكن استخدام جهاز Synology NAS كخادم LDAP. لهذا الغرض، يجب تثبيت حزمة "LDAP Server" أو حاوية Docker تحتوي على OpenLDAP.

  • نوع المزود: "LDAP" (وليس "Active Directory")
  • فلتر المستخدمين: (objectClass=inetOrgPerson)
  • يسجّل المستخدمون الدخول باستخدام uid أو عنوان البريد الإلكتروني
  • يُفضَّل LDAPS (المنفذ 636)

اختبار الاتصال

استخدم زر "اختبار الاتصال" للتحقق من الإعدادات. يعرض عدد الحسابات النشطة التي يجدها فلتر المستخدمين (لا تُحتسب الحسابات المعطّلة وحسابات النظام) وبعض أسماء المستخدمين كأمثلة. وتعني علامة "+" بعد الرقم أن خادم الدليل توقف عند حد النتائج، وأن هناك حسابات أكثر.
