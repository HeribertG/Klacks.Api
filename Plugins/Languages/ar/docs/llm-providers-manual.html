البحث عن مزوّدي LLM — الدليل

ما الغرض من هذه الوظيفة؟

تقترح عليك هذه الشاشة مزوّدي نماذج لغوية (LLM) لم تُضفهم بعد إلى قائمتك، وتضيف المحدَّد منها بنقرة واحدة. بذلك لا تحتاج إلى إدخال الاسم وعنوان URL الأساسي يدوياً. يتم اقتراح مزوّدي واجهات برمجة تطبيقات متوافقة مع OpenAI حصراً — أي بالضبط نوع الخدمات التي يستخدمها مزوّدوك المُهيَّؤون مسبقاً.

أعمدة الجدول

اسم المزوّد

اسم العرض الخاص بالمزوّد (مثلاً "OpenRouter"، "xAI (Grok)").

عنوان URL الأساسي

عنوان API الذي يتم من خلاله التواصل مع المزوّد (مثلاً https://api.x.ai/v1/). سيُستخدم هذا العنوان بالضبط لاحقاً عند الإنشاء.

المصدر

يوضّح من أين جاء الاقتراح:

  • الكتالوج — من قائمة ثابتة ومُتحقَّق منها لمزوّدين معروفين. عناوين URL الأساسية موثَّقة وبالتالي موثوقة.
  • الويب — تم العثور عليها عبر بحث إنترنت وتحليلها تلقائياً. تظهر هذه الإدخالات فقط إذا كان بحث الويب مُهيَّأً في الإعدادات. وهي مفيدة، لكن في حال الشك يُستحسن التحقق من عنوان URL الأساسي بسرعة.

إمكانية الوصول

قبل العرض، يتم اختبار كل اقتراح مباشرةً (استدعاء نقطة النهاية /models):

  • يمكن الوصول إليه — تستجيب الواجهة البرمجية، والمزوّد يعمل.
  • يمكن الوصول إليه (يتطلب مفتاحاً) — الواجهة البرمجية موجودة، لكنها تتطلب مفتاح API. أي أن العنوان صحيح.
  • لا يمكن الوصول إليه — لا يستجيب العنوان. لا يمكن اختيار مثل هذه الإدخالات.

إضافة مزوّد

ضع علامة اختيار عند مزوّد واحد أو أكثر، ثم انقر أدناه على "إضافة التحديد". يتم إنشاء المزوّدين المختارين معطَّلين وبدون مفتاح API. المزوّدون الموجودون مسبقاً لا يتم اقتراحهم من الأساس.

الخطوات التالية بعد الإضافة

المزوّد المُضاف حديثاً ليس نشطاً بعد. افتحه من القائمة، وأدخل مفتاح API ثم قم بتفعيله. بعد ذلك سيعمل تماماً مثل بقية مزوّديك. تستمر في إدارة النماذج الفردية لكل مزوّد بشكل منفصل عبر إدارة النماذج.
