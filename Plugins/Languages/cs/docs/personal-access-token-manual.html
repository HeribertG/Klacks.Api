Příručka pro osobní přístupové tokeny

Co jsou osobní přístupové tokeny?

Personal Access Tokens (PAT) jsou dlouhodobě platné klíče API, které externím nástrojům a službám umožňují bezpečný přístup ke Klacks — bez uživatelského jména a hesla.

Typické případy použití:

  • MCP (Model Context Protocol) — umožňuje AI asistentům jako Claude Desktop přímý přístup ke skillům Klacksy
  • AI agenti a asistenti, kteří s Klacks pracují přes MCP

Bezpečnostní koncept

Klacks nikdy neukládá token v prostém textu. Po vytvoření se v databázi uloží výhradně hash SHA-256 tokenu. Samotný token se zobrazí pouze jednou, ihned po vytvoření, a poté už jej nelze znovu zobrazit.

Poznámka: Token si ihned po vytvoření poznamenejte nebo zkopírujte. Při ztrátě je nutné vytvořit nový token a starý odvolat.

Vytvoření tokenu

Postup krok za krokem

  • Přejděte na Konfigurace → Personal Access Tokens
  • Klikněte na Vytvořit nový token
  • Zadejte výstižný název (např. Claude Desktop nebo AI agent plánování)
  • Zvolte požadovanou dobu platnosti (1–730 dní, výchozí: 365 dní)
  • Klikněte na Vytvořit
  • Zobrazený token okamžitě zkopírujte — zobrazí se pouze jednou

Formát tokenu

klacks_pat_<náhodný řetězec znaků>

Každý token začíná prefixem klacks_pat_, za nímž následuje kryptograficky bezpečný náhodný řetězec znaků.

Doba platnosti

DobaDoporučené použití
1–30 dníKrátkodobé testy a vývoj
90–180 dníAI agenti s pravidelnou rotací
365 dní (výchozí)Trvalé integrace (např. Claude Desktop)
730 dníDlouhodobé systémové integrace

Režim přístupu

Při vytváření určíte, co smí externí agent s tokenem dělat:

  • Pouze čtení (výchozí) — agent vidí a používá výhradně nástroje pro čtení. Každý pokus o změnu dat je odmítnut.
  • Čtení a zápis — agent může navíc měnit data, aniž by každou jednotlivou změnu schvaloval člověk. Tento režim volte jen pro agenty, kterým svěřujete změny.

Režim se zobrazuje v přehledu tokenů a dodatečně jej nelze změnit; v případě potřeby vytvořte nový token. Stávající tokeny a tokeny vydané přihlášením OAuth (např. konektorem MCP) mají režim „Čtení a zápis“.

Použití tokenu

Bearer token v HTTP hlavičce

Token se přenáší jako Bearer token v hlavičce Authorization každého požadavku MCP na endpoint /mcp:

Authorization: Bearer klacks_pat_...

Konfigurace MCP s Claude Desktop

Koncový bod MCP (/mcp) umožňuje AI asistentům jako Claude Desktop přímý přístup ke všem skillům Klacksy — dotazování na údaje o zaměstnancích, plánování směn, správu skupin a mnoho dalšího.

Konfigurace v aplikaci Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<vaše-doména-klacks>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Nahraďte <vaše-doména-klacks> adresou vaší instalace Klacks a klacks_pat_... vaším vytvořeným tokenem.

Poznámka: Tokeny fungují pouze pro přístup AI agentů přes MCP (endpoint /mcp). REST API Klacks (např. /api/clients) je nepřijímá; vyžaduje přihlašovací token.

Správa a bezpečnost

Přehled tokenů

V nabídce Konfigurace → Personal Access Tokens vidíte všechny své tokeny s názvem, datem vytvoření, datem vypršení platnosti a posledním použitím. Token v prostém textu se v tomto zobrazení nikdy nezobrazuje.

Odvolání tokenu

Token lze kdykoli odvolat. Po odvolání jsou všechny požadavky s tímto tokenem okamžitě odmítnuty. Tokeny okamžitě odvolejte, pokud:

  • Byl token omylem zpřístupněn třetí straně
  • Zařízení nebo služba se již nepoužívá
  • Zaznamenáte podezřelou aktivitu

Vypršení platnosti

Tokeny s prošlou platností jsou automaticky odmítnuty. Klacks v přehledu zobrazuje tokeny, jejichž platnost vyprší v následujících 30 dnech, abyste mohli včas vytvořit nové tokeny.

Bezpečnostní tipy

  • Pro každou službu nebo nástroj používejte samostatný token
  • Volte výstižné názvy, aby bylo možné tokeny jednoznačně přiřadit
  • Nikdy neukládejte tokeny v prostém textu do systémů správy verzí
  • Tokeny pravidelně rotujte
  • Při podezření na zneužití tokeny okamžitě odvolejte

Každý token je vázán na váš uživatelský účet. Přes MCP má token oprávnění vašeho účtu, nejvýše však na úrovni Supervisora: i když je váš účet administrátorský, token nikdy nemá práva administrátora. Přístupový režim navíc omezuje, co smí agent dělat: v režimu „Pouze čtení“ používá výhradně funkce pro čtení; v režimu „Čtení a zápis“ provádí změny bez dalšího potvrzení. Zacházejte s tokeny se stejnou péčí jako se svým heslem.
