Příručka poskytovatele identity

Úvod

Poskytovatelé identity umožňují ověřování uživatelů prostřednictvím externích adresářových služeb, jako jsou LDAP, Active Directory nebo OAuth2/OpenID Connect.

Podporované typy poskytovatelů:

  • LDAP - Lightweight Directory Access Protocol
  • Active Directory - Microsoft Active Directory
  • OAuth2 - Autorizační framework OAuth 2.0
  • OpenID Connect - Vrstva identity nad OAuth 2.0

Import klientů

Když je aktivováno "Použít pro import klientů", importují se následující údaje:

  • Příjmení - sn (příjmení) nebo displayName
  • Jméno - givenName
  • Titul - title (pracovní pozice)
  • Firma - company
  • Adresa - street/streetAddress, postalCode, l (město), st (kraj), c (země)
  • Pohlaví - Z personalTitle (Pan/Paní) v Active Directory

Poznámka: V OpenLDAP je pohlaví standardně nastaveno na "Neutrální" a může být ručně opraveno.

Přihlášení přes adresář

Je-li možnost "Použít pro ověření" zapnutá a uložená, mohou se lidé do Klacks přihlašovat heslem ze svého adresáře. Nikdo nezíská přístup automaticky: správce schvaluje každou osobu na kartě Schválení přihlášení.

  • Karta zobrazuje účty z adresáře (nejvýše 1000; seznam zúžíte vyhledáváním).
  • Zaškrtnutím účtu se vytvoří nový účet Klacks bez role a bez hesla. Existující účty Klacks se nikdy nepřebírají: pokud e-mailovou adresu už používá nějaký účet Klacks, řádek nelze zaškrtnout. Nejprve tento účet smažte nebo změňte jeho e-mailovou adresu ve správě uživatelů.
  • Odebráním zaškrtnutí se účet Klacks deaktivuje; opětovným zaškrtnutím se znovu aktivuje, pokud nemá žádnou roli. Deaktivovaný účet, který ještě má role, se znovu aktivuje ve správě uživatelů.
  • Odchod zaměstnance: když někdo odchází, odeberte zaškrtnutí i v Klacks. Zakázání účtu v adresáři zablokuje nová přihlášení, ale již běžící relace pokračují, dokud nevyprší.
  • Účet bez e-mailové adresy v adresáři nelze schválit.
  • Vlastní účet nelze na této kartě změnit.
  • Osoba se správnými přihlašovacími údaji z adresáře, ale bez schválení, dostane zprávu, že účet není schválen a že se má obrátit na správce.

Klacks osobu vyhledá pomocí uživatele Bind a poté ověří heslo v adresáři, takže přihlašovací jméno se nemusí shodovat s e-mailovou adresou.

Šifrování

Prostý LDAP na portu 389 posílá hesla nešifrovaně; formulář pro poskytovatele LDAP bez SSL zobrazí varování. Kdykoli se adresář používá pro přihlášení, použijte LDAPS ("Použít SSL", port 636).

Active Directory: přihlášení pouze přes LDAPS

Klacks přihlašuje osoby do Active Directory pouze přes LDAPS (port 636). Bez SSL formulář zobrazí varování, nikdo se nemůže přihlásit a karta schválení přihlášení zůstane zavřená. Bez SSL fungují import klientů a test připojení jen tehdy, když Klacks běží přímo ve Windows; v Dockeru (Linux) vyžaduje Active Directory LDAPS pro všechno.

  • Host: plně kvalifikovaný název (FQDN) přesně tak, jak je uveden v certifikátu řadiče domény, např. dc01.example.local. IP adresa nefunguje, protože kontrola certifikátu porovnává název.
  • Důvěra v CA: počítač, na kterém běží Klacks, musí důvěřovat certifikační autoritě, která vydala certifikát řadiče domény. Windows: importujte certifikát CA do úložiště počítače Důvěryhodné kořenové certifikační autority, např. certutil -addstore Root ca.cer (jako správce).
  • Překlad názvů: pokud se FQDN nepodaří přeložit přes DNS, přidejte záznam do souboru hosts (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: připojte certifikát CA jako soubor PEM do kontejneru API, nastavte proměnnou prostředí LDAPTLS_CACERT na jeho cestu a pokud DNS FQDN nepřeloží, přidejte ho pomocí extra_hosts. Pokud řadič domény neposílá certifikát CA (self-signed certifikát), poslouží jako kotva důvěry jeho vlastní certifikát jako soubor PEM. Bez důvěryhodného certifikátu je připojení odmítnuto a hlášeno jako chyba připojení.
  • Účet Bind: zadejte ho jako user principal name (UPN), např. svc-klacks@example.local.

Které účty se importují

  • Zakázané účty a systémové účty Active Directory se nikdy neimportují ani nezobrazují.
  • Servisní účty vyloučíte filtrem uživatelů, např. pouze členové jedné skupiny: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Tipy

Synology NAS jako LDAP server

Synology NAS lze použít jako LDAP server. K tomu je nutné nainstalovat balíček "LDAP Server" nebo Docker kontejner s OpenLDAP.

  • Typ poskytovatele: "LDAP" (ne "Active Directory")
  • Filtr uživatelů: (objectClass=inetOrgPerson)
  • Uživatelé se přihlašují pomocí uid nebo e-mailové adresy
  • Doporučeno LDAPS (port 636)

Testování připojení

Pomocí tlačítka "Testovat připojení" ověřte konfiguraci. Zobrazí počet aktivních účtů, které filtr uživatelů najde (zakázané a systémové účty se nepočítají), a několik ukázkových uživatelských jmen. Znaménko "+" za číslem znamená, že se server adresáře zastavil na svém limitu výsledků, takže účtů je více.
