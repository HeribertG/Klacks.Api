設定 Signal 訊息服務

先決條件

若要透過 Klacks 傳送 Signal 訊息，您需要一個自行架設的 signal-cli-rest-api 執行個體。這是一個 開放原始碼專案，讓 Signal 可透過 REST 介面存取。

  • 伺服器上必須安裝 Docker
  • 一個要在 Signal 上註冊的電話號碼（建議使用專用號碼）
  • Docker 映像檔：bbernhard/signal-cli-rest-api

重要：Signal 串接僅適用於傳送訊息。 Klacks 不會接收傳入的 Signal 訊息。

步驟 1 — 設定 signal-cli-rest-api

  1. 使用 Docker 啟動容器： 
    docker run -d --name signal-cli-rest-api \
  --restart=unless-stopped \
  -p 8080:8080 \
  -v signal-cli-config:/home/.local/share/signal-cli \
  -e MODE=normal \
  bbernhard/signal-cli-rest-api
  2. 透過 QR 連結程序將您的 Signal 號碼建立關聯： 在瀏覽器中開啟 
    http://localhost:8080/v1/qrcodelink?device_name=klacks
    並使用已註冊該號碼的手機上的 Signal 應用程式掃描顯示的 QR 碼 （設定 → 已連結的裝置 → 連結裝置）。 此容器即會作為次要裝置與該號碼建立連結。
  3. 您也可以選擇透過 API 自行註冊該號碼 — 詳細說明請參閱該專案的說明文件。
  4. 透過健康檢查測試此 API： 
    curl http://localhost:8080/v1/about

提示：關於設定的更多細節，請參閱 signal-cli-rest-api 說明文件。

步驟 2 — 在 Klacks 中設定 Signal

  1. 前往設定 → 訊息服務提供者。
  2. 點擊新增。
  3. 依照以下方式填寫欄位：
欄位說明範例
名稱內部使用的唯一名稱signal-main
顯示名稱將顯示於介面中Signal
提供者類型選擇 SignalSignal
Signal 號碼已註冊的電話號碼，需為國際格式+41791234567
Signal-CLI API 網址signal-cli-rest-api 容器的網址。若此容器與 Klacks 運行於同一伺服器，可填入 http://localhost:8080。http://localhost:8080
已啟用開啟/關閉此提供者是
  1. 點擊儲存。
  2. 透過提供者清單中的測試按鈕測試連線。 測試會檢查該號碼是否已在容器中註冊。

提示：Klacks 透過容器的 POST /v2/send 端點 傳送訊息。

步驟 3 — 透過聊天機器人（Klacksy）傳送訊息

一旦 Signal 提供者設定完成並啟用，聊天機器人 Klacksy 便可 傳送訊息。您不需要知道電話號碼 — 只需 使用員工或客戶的姓名即可： 

「傳送訊息給王小明：您的預約時間是明天下午 2 點。」
「傳一則 Signal 訊息給陳小華：班次已經調換。」
「通知李大同，他星期一的班次取消了。」

Klacksy 會自動尋找收件人所登記的行動電話號碼，並 使用已設定的 Signal 提供者傳送。整個傳送過程對您而言完全透明 — 您只需輸入姓名，其餘交給 Klacksy 處理。

先決條件：收件人必須在 Klacks 中登記行動電話號碼 （於地址 → 聯絡資料中設定），且需為國際格式（例如 +41791234567）。 即使是廣播訊息，Signal 傳送功能也會使用所登記的行動電話號碼。

傳入訊息

Signal 串接不支援接收訊息 — 對已傳送訊息的回覆 不會傳送給 Klacks。因此，訊息收件匣不會顯示 此提供者的任何傳入訊息。

疑難排解

問題可能原因解決方式
連線測試失敗 容器無法連線 請檢查 Docker 容器是否正在運行（docker ps），以及 API 網址是否正確
連線測試失敗 號碼未在容器中註冊 請重新透過 QR 連結程序建立關聯
訊息無法送達 收件人未使用 Signal 或號碼錯誤 請確認收件人已安裝 Signal，且號碼以 +{國碼}{號碼} 格式登記
連結遺失 裝置已在 Signal 應用程式中解除連結 請透過 QR 連結重新建立容器連結
容器無法啟動 連接埠 8080 已被佔用 請改用其他連接埠：-p 9090:8080，並在 Klacks 中調整 API 網址
