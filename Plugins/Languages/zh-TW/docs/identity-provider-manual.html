身分提供者手冊

簡介

透過使用身分提供者，您可以透過LDAP、Active Directory、OAuth2/OpenID Connect等 外部目錄服務進行使用者身分驗證。

支援的提供者類型：

  • LDAP - 標準輕量級目錄存取協定
  • Active Directory - Microsoft Active Directory
  • OAuth2 - OAuth 2.0 授權框架
  • OpenID Connect - 基於OAuth 2.0的身分層

客戶匯入

啟用「用於客戶匯入」後，將匯入以下資料：

  • 姓名 - sn（姓氏）或 displayName
  • 名字 - givenName
  • 職位 - title（職位名稱）
  • 公司 - company
  • 地址 - street/streetAddress、postalCode、l（城市）、st（省/州）、c（國家）
  • 性別 - Active Directory情況下，從personalTitle（Herr/Frau）取得

注意：使用OpenLDAP時，性別預設為「中性」，可手動修正。

透過目錄登入

啟用並儲存「用於認證」後，使用者即可使用其目錄密碼登入Klacks。 不會自動授予任何人存取權限：管理員需在 登入核准索引標籤上逐一核准使用者。

  • 該索引標籤列出目錄帳戶（最多1000個；可使用搜尋來縮小清單範圍）。
  • 勾選某個帳戶會建立一個沒有角色、沒有密碼的新Klacks帳戶。現有的Klacks 帳戶絕不會被接管：如果該電子郵件地址已被某個Klacks帳戶使用，則該列無法 勾選。請先在使用者管理中刪除該帳戶或變更其電子郵件地址。
  • 取消勾選會停用該Klacks帳戶；再次勾選會重新啟用，前提是該帳戶沒有角色。 仍然擁有角色的已停用帳戶需在使用者管理中重新啟用。
  • 人員離職：有人離開時，請同時在Klacks中取消勾選。在目錄中停用該帳戶 會阻止新的登入，但已在執行的工作階段會持續有效，直至過期。
  • 在目錄中沒有電子郵件地址的帳戶無法被核准。
  • 無法在此索引標籤上變更您自己的帳戶。
  • 目錄憑證正確但未獲核准的使用者會收到提示：該帳戶 尚未獲得核准，請聯絡管理員。

登入名稱

類型可接受的登入名稱
Active DirectorysAMAccountName、userPrincipalName或電子郵件地址
LDAPuid或電子郵件地址

Klacks使用繫結使用者查找該使用者，然後向目錄驗證密碼，因此 登入名稱不必與電子郵件地址一致。

加密

389連接埠上的一般LDAP會以未加密方式傳送密碼；對於未啟用SSL的LDAP提供者，表單會顯示警告。 只要目錄用於登入，請使用LDAPS（「使用SSL」，636連接埠）。

Active Directory：僅透過LDAPS登入

Klacks僅透過LDAPS（636連接埠）讓使用者登入Active Directory。沒有SSL時，表單會顯示警告， 任何人都無法登入，登入核准索引標籤保持關閉。沒有SSL時，客戶匯入和連線測試 僅在Klacks直接執行於Windows上時可用；在Docker（Linux）中，Active Directory的 所有操作都需要LDAPS。

  • 主機：網域控制站憑證中所示的完整網域名稱（FQDN）， 例如dc01.example.local。IP位址無法使用，因為憑證檢查會比對名稱。
  • 信任CA：執行Klacks的電腦必須信任簽發網域控制站憑證的 憑證授權單位。Windows：將CA憑證匯入電腦的 受信任的根憑證授權單位存放區，例如certutil -addstore Root ca.cer （以系統管理員身分）。
  • 名稱解析：如果無法透過DNS解析該FQDN，請新增hosts項目 （Windows：C:\Windows\System32\drivers\etc\hosts）。
  • Docker：將CA憑證以PEM檔案形式掛載到API容器中， 將環境變數LDAPTLS_CACERT設定為其路徑，如果DNS無法解析， 則透過extra_hosts新增該FQDN。如果網域控制站不傳送CA 憑證（自我簽署憑證），則可將其自身的憑證以PEM檔案形式用作信任錨。 沒有受信任的憑證時，連線會被拒絕，並回報為連線錯誤。
  • 繫結帳戶：請以使用者主體名稱（UPN）輸入，例如 svc-klacks@example.local。

匯入哪些帳戶

  • 已停用的帳戶和Active Directory系統帳戶絕不會被匯入，也絕不會被列出。
  • 使用使用者篩選器排除服務帳戶，例如僅限某個群組的成員： (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

提示

使用Synology NAS作為LDAP伺服器

您可以使用Synology NAS作為LDAP伺服器。在這種情況下，需要安裝「LDAP Server」軟體套件 或使用基於OpenLDAP的Docker容器。

  • 提供者類型：「LDAP」（而非「Active Directory」）
  • 使用者篩選器：(objectClass=inetOrgPerson)
  • 使用者以其uid或電子郵件地址登入
  • 建議優先使用LDAPS（636連接埠）

測試連線

請使用「測試連線」按鈕來驗證設定。它會顯示使用者篩選器找到的作用中帳戶數量 （已停用帳戶和系統帳戶不計入）以及一些範例使用者名稱。數字後面的「+」表示目錄伺服器在其結果上限處停止， 即還有更多帳戶。
