Klacksy 訓練 - 使用說明

訓練工具是什麼？

訓練工具控制著聊天機器人 Klacksy 的頁內導覽功能。當使用者 說出或輸入「Klacksy，帶我看看地址」時，Klacksy 會導覽到對應的頁面 並捲動到相應的區塊。

為了讓此功能正常運作，Klacksy 需要為頁面上每個錨點 在各種語言中準備一份同義詞清單（例如目標 addresses 對應「地址」、「客戶」、「聯絡人」）。

「目標」分頁

顯示前端中找到的所有錨點（HTML 屬性 data-klacksy-target）的 清單。狀態篩選：

  • pending：錨點已存在，但尚無同義詞
  • generated：同義詞已自動產生，需要審核
  • reviewed：同義詞已由管理員核准
  • needs-review：已標記需要重新審核

點擊某個目標會在下方開啟同義詞編輯器。在該處可以 新增、刪除同義詞，並透過「儲存為已審核」進行核准。

「回饋」分頁

顯示 Klacksy 無法對應的使用者輸入內容（找不到符合的 同義詞）。透過此清單可以看出哪些同義詞仍然缺少。

「指標」分頁

依狀態顯示所有目標的總覽。有助於追蹤訓練進度。

建置流程（CLI）

當範本新增了 data-klacksy-target 錨點時，必須重新產生 清單與初始同義詞。以下指令也會在 CI 以及 Husky 的 pre-commit 中自動執行： 

cd C:\SourceCode\Klacks.Ui

# 1. 掃描範本 → 產生包含所有錨點的 navigation-targets.json
npm run scan:targets

# 2a. 產生初始同義詞（全部 4 種核心語言 + 22 種外掛語言，約 2.5 小時）
npm run generate:synonyms

# 2b. 僅核心語言（de/en/fr/it）— 速度快，約 9 分鐘
npm run generate:synonyms -- --core-only

# 2c. 僅補齊缺少的外掛語言 — 約 45 分鐘
npm run generate:synonyms -- --plugins-only

# 3. 檢查喚醒詞的一致性
npm run wake-word-lint

重要：使用 npm run 時必須加上 --， 才能將選項傳遞給指令碼。若沒有 --，npm 會吞掉該旗標， 指令碼便會以標準模式執行。

不使用 npm 的替代方式：npx tsx tools/generate-synonyms.ts --core-only。

API 金鑰

LLM API 金鑰會依以下順序尋找：

  1. 環境變數 SYNONYM_LLM_API_KEY
  2. 資料庫表格 llm_providers（提供者 deepseek， is_enabled = true）— 透過 psql 呼叫自動取得
  3. 否則顯示錯誤訊息

預設提供者為 DeepSeek。可透過 SYNONYM_LLM_PROVIDER_ID=anthropic（或設定中已設定的其他 LLM 提供者）更換。

步驟 1 - scan:targets

搜尋所有 Angular 範本中的 data-klacksy-target 屬性，並 產生清單 Application/Skills/Definitions/navigation-targets.json。 每個新的錨點之後都會以狀態 pending 出現在「目標」分頁中。

步驟 2 - generate:synonyms

為每個新的錨點，根據 data-klacksy-label-key 與其類別 產生初始同義詞。之後狀態為：generated（需要由管理員審核）。

此指令碼每 5 個目標便會寫入一次清單檢查點，因此中途中斷 也不會遺失已產生的資料。

步驟 3 - wake-word-lint

檢查所有語言中喚醒詞變體（Hallo Klacksy / Hey Klacksy / ...）的 一致性。防止同義詞覆蓋喚醒詞。

語音模式

聊天視窗中的麥克風圖示可啟用語音模式。一旦啟用：

  • 麥克風會持續聆聽並連續轉錄
  • 短暫靜音後 → 自動送出目前為止的轉錄內容

重要：一旦你開始在文字欄位中輸入，語音模式會 自動結束 — 否則麥克風會用自己的轉錄內容覆蓋你輸入的 文字，並提前送出。

典型的訓練循環

  1. 在範本中新增錨點： 
    <div data-klacksy-target="addresses"
     data-klacksy-label-key="nav.addresses"
     data-klacksy-route="/workplace/client">
  2. npm run scan:targets && npm run generate:synonyms
  3. 重新啟動 API（快取會在啟動時重新讀取）
  4. 開啟「目標」分頁 → 新目標會以狀態 generated 顯示
  5. 檢查/補充同義詞 → 「儲存為已審核」 → 狀態 reviewed
  6. 用 Klacksy 測試，例如「Klacksy，帶我看看地址」
  7. 如果 Klacksy 無法對應 → 「回饋」分頁 → 補充缺少的同義詞
  8. 監控「指標」分頁，直到全部都是 reviewed
