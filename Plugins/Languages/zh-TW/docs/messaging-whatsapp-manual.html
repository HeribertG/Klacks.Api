設定 WhatsApp

先決條件

若要透過 WhatsApp 與 Klacks 傳送及接收訊息，您需要一個 Meta 開發者帳號，以及一個已啟用 WhatsApp 產品的 Meta 應用程式。Klacks 傳送訊息時使用 Meta Business 平台的 WhatsApp Cloud API，接收訊息時則使用 Meta Webhooks。

提示：設定與測試皆不會產生費用。建立應用程式時， Meta 會自動免費提供一組測試電話號碼。

重要 — 寄件號碼並非您的私人號碼。 已在一般 WhatsApp 應用程式中使用的電話號碼無法註冊至 Cloud API，而已註冊的號碼也無法再與 WhatsApp Messenger 一併使用。因此請使用 Meta 提供的測試號碼，或使用一組僅供商務用途的自有號碼。 您手機上的私人 WhatsApp 在測試時是作為收件人 — 而非寄件人。

步驟 1 — 建立 Meta 應用程式

  1. 開啟 developers.facebook.com/apps，點擊 Create app。
  2. 使用情境選擇 Other，應用程式類型選擇 Business。
  3. 在 Dashboard 中於 WhatsApp 產品處點擊 Set up。 此時系統會自動產生並註冊一組測試電話號碼。
  4. 在左側導覽中切換至 WhatsApp → API Setup。
  5. 記下 Phone number ID，並透過 Generate access token 產生一組存取權杖。
  6. 在 App settings → Basic 下記下 App Secret — 驗證傳入訊息的簽章時會需要它。

注意 — 兩個相似的 ID：在 API Setup 面板中，Phone number ID 與 WhatsApp Business Account ID 上下緊鄰排列。Klacks 需要的是 Phone number ID。若填入錯誤的 ID，連線測試仍會回報成功，但每次傳送都會失敗。

注意 — 權杖的有效期限：透過 Generate access token 產生的 權杖是臨時測試權杖，很短時間後便會失效。若要長期使用， 請在 Meta Business Manager 中透過系統使用者產生永久權杖。

步驟 2 — 開通收件號碼

測試號碼僅能傳送給事先開通的收件人。請在 API Setup 面板中的 To → Manage phone number list 下新增您的 WhatsApp 號碼。 Meta 會傳送一組確認碼至該號碼，您必須輸入此確認碼。

若未完成此步驟，Meta 會拒絕所有傳送至該號碼的訊息。日後當您改用自有且已驗證的商務號碼時， 便不再需要開通。

步驟 4 — 24 小時視窗

在這一點上，WhatsApp 與 Telegram 或 Slack 有根本上的差異。企業只有在客服視窗 開啟期間，才能傳送自由文字訊息。此視窗由收件人開啟，也就是由對方主動傳訊息給您的 WhatsApp 號碼。視窗會維持開啟 24 小時，收件人每多傳送一則訊息便會再延長。

在此視窗之外，Meta 僅允許使用事先核准的訊息範本。Klacks 目前僅傳送自由文字 訊息，因此無法主動開啟對話。

這對您代表什麼：請讓您的員工先向 Klacks 的 WhatsApp 號碼傳送一次訊息。 之後便可在 24 小時內傳送訊息，且每一次回覆都會延長此視窗。若視窗已關閉，傳送會回報錯誤 — 這並非設定問題，而是 WhatsApp 的規定。

若您必須在不受此視窗限制的情況下聯絡員工，則 Telegram 或 Signal 是更合適的提供者 — 它們沒有這項限制。

步驟 5 — 透過聊天機器人（Klacksy）傳送訊息

一旦 WhatsApp 提供者設定完成並啟用，聊天機器人 Klacksy 便可 透過 WhatsApp 傳送訊息。請使用員工姓名： 

「傳送訊息給王小明：您的預約時間是明天下午 2 點。」
「傳一則訊息給陳小華：班次已經調換。」

收件人是以國際格式表示的電話號碼，不含開頭的 0，也不含加號 （例如 41791234567，代表 079 123 45 67）。 整個傳送過程對您而言完全透明 — 您只需輸入姓名，其餘交給 Klacksy 處理。

先決條件：該 WhatsApp 號碼必須與對應的 Klacks 聯絡人建立關聯（於地址 → 聯絡資料中設定），且步驟 4 的 24 小時視窗必須為開啟狀態。

步驟 6 — 接收傳入訊息（Webhooks）

若要在 Klacks 中顯示傳入的 WhatsApp 訊息，必須設定 Meta 應用程式的 Webhook。 請務必先在 Klacks 中儲存並啟用此提供者，再輸入 Callback URL — Meta 會立即以一個 驗證請求檢查該網址，而 Klacks 會依據驗證權杖自動回應。

  1. 開啟您的 Meta 應用程式，並前往 WhatsApp → Configuration。
  2. 在 Webhook 處點擊 Edit，並填入：
    • Callback URL：Klacks 中顯示的 Webhook 網址 
      https://{您的網域}/api/messaging/webhook/whatsapp
    • Verify token：與您於步驟 3 在驗證權杖欄位中 填寫的值完全相同
  3. 點擊 Verify and save。
  4. 在 Webhook fields 下訂閱欄位 messages。
  5. 傳入的訊息現在會即時顯示於訊息收件匣中。 Klacks 會使用已登記的應用程式密鑰驗證每個請求的簽章（X-Hub-Signature-256）。

Callback URL 必須可從外部透過 HTTPS 存取。若安裝於沒有公開位址的公司內部網路， 傳送功能仍可運作，但無法接收訊息。

問題可能原因解決方式
連線測試失敗 存取權杖已失效 臨時測試權杖很短時間後便會失效 — 請在 API Setup 面板中重新產生，或設定一組永久權杖
連線測試成功，但每次傳送都失敗 填入的是 Business Account ID 而非電話號碼 ID 請從 API Setup 面板中採用 Phone number ID，而非 WhatsApp Business Account ID
錯誤訊息提及 24 小時或需重新聯繫 客服視窗已關閉 收件人必須先傳送一則訊息至您的 WhatsApp 號碼 — 請參閱步驟 4
傳送至某個特定號碼失敗 該收件人尚未在測試號碼下開通 請在 Manage phone number list 下新增該號碼，並以驗證碼確認
