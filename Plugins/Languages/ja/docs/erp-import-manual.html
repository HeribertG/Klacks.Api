ERP受注インポート – マニュアル

ERP受注インポートとは

外部のERPシステムは、受注データをXMLファイルとしてKlacksに送信します。 データ転送には3つの方法があります。

  • ドロップポイント（取得方式）： ERP側がドロップポイントのファイル置き場に ファイルを配置します。インストール形態により、Klacksサーバー上のディレクトリ（標準） またはS3互換のオブジェクトストレージのいずれかになります。Klacksは設定されたスケジュールに 従って自動的にファイルを取得します。
  • 直接アップロード（プッシュ方式）： ERP側がHTTP POSTで /api/erp-import/upload にファイルを送信し、その際にERPインポートトークンを ベアラートークンとして認証に使用します。1ファイルあたり最大50 MBまで許可されます。
  • 手動アップロード： 管理者がこのページ上でXMLファイルを直接ドロップゾーンに ドラッグするか（またはドロップゾーンをクリックしてファイルを選択）します。アップロード後、 インポートは自動的に開始され、1分以内に実行されます。今すぐインポートボタンで いつでも追加で実行することもできます。

ドロップポイント

ドロップポイントは、すべてのインポートファイルを受け取る中央の受け口です。Klacksが自動的に 管理するため、作成や設定を行う必要はありません。このページでは、その内容がファイルビューとして 3つの領域に分けて表示されます。受信（次回のインポート実行を待っている状態）、 処理済み（アーカイブ）、エラー（読み取り不能または無効な ファイルとそのエラー理由）です。エラーファイルは、再インポートボタンで受信フォルダーに 戻すことができます。

  • 有効スイッチ（インポート有効） – 自動インポートを一時停止します。すでに 配置されているファイルはそのまま保持されます。
  • ステータス表示 – 最終取得日時、および存在する場合は最後に発生したエラー。

アクセストークン

  • プッシュ方式での配信のために、管理者はアクセストークンを作成できます。これは外部のERP システムがHTTPS経由でファイルを送信する場合にのみ必要です。各トークンは klacks_erp_ というプレフィックスで始まります。
  • 有効期間は選択可能です（1日から730日まで、標準は365日）。
  • トークンの平文は作成時に一度だけ表示されます。その後は取得できなくなる ため、すぐにコピーして安全に保管してください。
  • ERPインポートトークンは、意図的にインポートエンドポイントに限定して有効 となっています。トークンがERP委託業者側で第三者の手に渡った場合でも、Klacksへのそれ以外の APIアクセスは不可能です。
  • トークンはいつでも失効させることができ、失効すると即座にアクセスが遮断されます。

スケジュール

ドロップポイントの取得は、選択したタイムゾーンにおけるCron式 （標準は0 * * * * = 毎時）に従って実行されます。両方の設定はこのページで行います。 無効なCron式を指定するとインポートが停止してしまうため、入力内容は検証され、無効な値は 保存されません。

XML形式（リファレンス）

ルート要素はErpOrderImportで、必須属性としてschemaVersion （現在は1）とsourceSystemIdを持ちます。sourceSystemId はファイル内で送信元システムを識別し、すべての配信を通じて安定した顧客の 紐付けを保証します。そのため、この値は送信元システムごとに恒久的に一定であることが必要です。 各受注は個別の<Order>要素として記述します。1ファイルには任意の数の受注を 含めることができます。

要素 必須 形式 意味
ExternalOrderReference 要 テキスト ERPシステム側の一意な受注参照番号。
Description 不要 テキスト 受注に関する自由記述（例：作業に関する補足事項）。受注画面に表示されます。
Customer 要 要素 受注に紐づく顧客データ（サブ要素を参照）。
Customer/ExternalCustomerReference 不要（推奨） テキスト 外部顧客参照番号。すべてのインポートを通じて安定した顧客の紐付けを保証します。
Customer/Company 要 テキスト 顧客の会社名。
Customer/Address/Street 要 テキスト 番地・通り名。
Customer/Address/Zip 要 テキスト 郵便番号。
Customer/Address/City、Customer/Address/State、Customer/Address/Country 不要 テキスト 市区町村、州・地域、国。
FromDate 要 yyyy-MM-dd 受注の開始日。
UntilDate 不要 yyyy-MM-dd 受注の終了日。指定なしまたは空欄の場合は無期限。
StartTime、EndTime 要 HH:mm 作業の開始時刻と終了時刻。
IsTimeRange 不要 true/false（標準はfalse） true = 作業を行う時間帯（タイムウィンドウ）を表す。false = StartTimeからEndTimeまでの 固定シフトを表す。trueの場合、Durationは必須です。
Duration IsTimeRange=trueの場合 <Hours>と<Minutes>（整数）を持つ要素 個々の作業の所要時間。例：08:00～15:00のタイムウィンドウ内で20分間の作業を行う場合は 0時間20分。固定シフトの場合は任意項目で、要素が省略された場合はStartTimeからEndTime までの時間が所要時間として扱われます。
Quantity 不要 整数（標準は1） 作業の回数。
SumEmployees 不要 整数（標準は1） 必要な従業員数。
Weekdays 要 monday～sundayの各属性（true/false） 受注が対象とする曜日。少なくとも1つの曜日をtrueにする必要があり、属性が省略された 場合はfalseとして扱われます。曜日が1つも指定されていない受注は拒否されます。

注意：要素名は大文字・小文字を区別します。サンプルファイルをダウンロード ボタン（本マニュアルの上部にあります）から、完全なサンプルファイルを入手できます。

顧客の紐付け

Klacksは、それぞれの受注を次の方法で顧客に紐付けます。

  • まず、送信元システムIDと外部顧客参照番号の組み合わせによって紐付けを試みます。一度 紐付けが行われると、この参照番号は恒久的に同一の顧客に割り当てられたままとなります。
  • 外部参照番号がない場合は、初回登場時に会社名＋郵便番号＋通り名で検索します。この際、 大文字・小文字の違いおよび空白は無視されます。
  • 一致する顧客が見つからない場合、Klacksは自動的に新しい顧客を作成します。

処理とライフサイクル

  • インポートされた受注は下書きとして作成され、プランナーまたは管理者による 確認と確定（シール）が必要です。その際、プランナーは必要に応じて資格要件も補完します。 ERP側は、これをDescriptionフィールドへのヒントとして併せて送信できます。
  • すでに確定済みの受注について、ERP側が後から変更後のバージョンを送信した 場合、Klacksは古い受注を終了日によって自動的にクローズし、これに紐づいた新しい下書き バージョンを作成します。旧受注に対してすでに計画済みで、かつロックされていない将来の 作業は削除され、プランナーに通知が送られます。
  • 変更のない繰り返し配信（例：夜間の全件エクスポート）は、何も処理を 発生させません。

エラー処理とアーカイブ

  • 処理済みのファイルは、ファイル置き場のサブフォルダーprocessed/に移動されます （アーカイブであり、削除ではありません）。これらはインポートページの処理済み領域に 表示されます。
  • 読み取り不能または無効なファイルは、サブフォルダーerror/に移動され、 エラー領域に表示されます。ここから再インポートによって受信フォルダーに 戻すことができます。
  • 不完全または無効な受注は拒否されます（例：曜日の指定がない、UntilDateが FromDateより前になっている、同一ファイル内でExternalOrderReference が重複している、など）。ただし、同じファイル内の他の受注はそのままインポートされます。
  • ファイル内に拒否された受注が1件でも含まれている場合、そのファイルは拒否理由とともに エラー領域に移動します。ただし、すでにインポート済みの受注はそのまま保持されます。
  • エラーは記録され、管理者に通知が送られます。
