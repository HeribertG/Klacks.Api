ERP 订单导入 – 手册

什么是ERP订单导入？

外部ERP系统以XML文件的形式向Klacks提供订单。 数据传输有三种方式：

  • 数据投放点（拉取）：ERP将文件放入数据投放点的 文件存储中 — 根据安装方式不同，可能是Klacks服务器上的一个目录（默认） 或S3兼容的对象存储。Klacks会按照配置的时间计划自动拉取这些文件。
  • 直接上传（推送）：ERP通过HTTP POST将文件发送到 /api/erp-import/upload，并使用ERP导入令牌作为Bearer令牌进行身份验证。 每个文件最大允许50 MB。
  • 手动上传：管理员可以直接在此页面将XML文件拖到 投放区（或点击该区域选择文件）。上传完成后导入会自动触发， 并在一分钟内开始；立即导入按钮可随时额外触发一次。

数据投放点

数据投放点是所有导入文件的中央收件箱。Klacks会自动管理它 — 无需任何人创建或配置。该页面以文件视图的形式显示其内容，分为三个区域：待处理 （等待下一次导入运行）、已处理（归档）和错误 （无法读取或无效的文件及其错误原因）。错误文件可通过 重新导入按钮移回待处理区。

  • 启用开关（导入已启用） — 暂停自动导入； 已存放的文件将保留不变。
  • 状态显示 — 最后一次轮询时间，以及最后一次错误（如有）。

访问令牌

  • 对于推送式送达，管理员可以创建访问令牌 — 仅在外部ERP系统 通过HTTPS推送文件时才需要。每个令牌都以前缀klacks_erp_开头。
  • 有效期可自行选择（1至730天，默认365天）。
  • 令牌明文仅在创建时显示一次。 之后将无法再次查看 — 请立即复制并妥善保存。
  • ERP导入令牌被有意设计为仅对导入端点有效。 如果令牌在ERP服务提供商处落入他人之手，也无法借此获得 对Klacks的其他API访问权限。
  • 令牌可随时撤销；访问权限会立即终止。

时间计划

数据投放点的轮询遵循一个Cron表达式（默认 0 * * * * = 每小时）以及所选的时区。两者 均在此页面上配置。无效的Cron表达式会导致导入 停止 — 因此系统会验证输入内容，无效值不会被 保存。

XML格式（参考）

根元素为ErpOrderImport，具有必填属性 schemaVersion（当前为1）和sourceSystemId。 sourceSystemId用于在文件中标识发送系统， 并确保在所有交付中稳定的客户对应关系 — 它必须对每个源系统保持长期不变。每个订单都位于一个 独立的<Order>元素中。一个文件可以包含任意数量的 订单。

元素 必填 格式 含义
ExternalOrderReference 是 文本 ERP系统的唯一订单参考号。
Description 否 文本 关于订单的自由文本（例如：出勤提示）；会显示在订单上。
Customer 是 元素 订单的客户数据（参见子元素）。
Customer/ExternalCustomerReference 否（推荐） 文本 外部客户参考号；确保所有导入中稳定的客户对应关系。
Customer/Company 是 文本 客户的公司名称。
Customer/Address/Street 是 文本 街道和门牌号。
Customer/Address/Zip 是 文本 邮政编码。
Customer/Address/City、Customer/Address/State、Customer/Address/Country 否 文本 城市、州/地区和国家。
FromDate 是 yyyy-MM-dd 订单开始日期。
UntilDate 否 yyyy-MM-dd 订单结束日期；缺失或为空 = 无限期。
StartTime、EndTime 是 HH:mm 出勤的开始和结束时间。
IsTimeRange 否 true/false（默认false） true = 工作所在的时间窗口；false = 从StartTime到EndTime的固定班次。为true时Duration为必填。
Duration 当IsTimeRange=true时 包含<Hours>和<Minutes>的元素（整数） 单次出勤的时长，例如在08:00–15:00的时间窗口内，20分钟出勤为0小时20分钟。对于固定班次为可选；若缺失该元素，则时长为StartTime到EndTime。
Quantity 否 整数（默认1） 出勤次数。
SumEmployees 否 整数（默认1） 所需员工人数。
Weekdays 是 属性monday … sunday，各为true/false 订单的星期几；至少一个星期几必须为true， 缺失的属性视为false。没有星期几的订单将被 拒绝。

提示：元素名称区分大小写。可通过此手册上方的 下载示例文件按钮获取完整的示例文件。

客户对应关系

Klacks会将每个订单分配给一个客户：

  • 首先通过源系统ID与外部客户参考号的组合进行匹配 — 一旦分配，该参考号将永久对应同一个客户。
  • 如果没有外部参考号，则在首次出现时通过公司名称+邮编+街道 进行搜索；此过程会忽略大小写和空格差异。
  • 如果没有找到匹配项，Klacks会自动新建该客户。

处理与生命周期

  • 导入的订单以草稿形式生成，必须由 排班员或管理员审核并封存。此时排班员还会补充 可能的资质要求 — ERP可以在Description字段中作为提示提供这些信息。
  • 如果ERP之后针对某个已封存的订单交付了已修改的 版本，Klacks会自动为旧订单设置结束日期，并创建一个 新的、关联的草稿版本。旧订单中已计划的、未来的、未锁定的 出勤将被移除，并通知排班员。
  • 未变更的重复交付（例如：每晚一次的完整导出） 不会触发任何操作。

错误处理与归档

  • 已处理的文件会移动到文件存储中的子文件夹 processed/（归档，不删除）；它们会显示在 导入页面的已处理区域中。
  • 无法读取或无效的文件会移动到子文件夹error/ 并显示在错误区域中；可从那里通过 重新导入移回待处理区。
  • 不完整或无效的订单将被拒绝（例如：没有星期几、 UntilDate早于FromDate，或同一文件中 ExternalOrderReference重复）；同一文件中的其余订单 仍会被导入。
  • 如果一个文件中至少有一个订单被拒绝，该文件会连同拒绝原因 移动到错误区域 — 已导入的订单 仍会保留。
  • 错误会被记录，并通知管理员。
