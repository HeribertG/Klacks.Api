身份提供商手册

简介

通过使用身份提供商，您可以通过LDAP、Active Directory、OAuth2/OpenID Connect等 外部目录服务进行用户身份验证。

支持的提供商类型：

  • LDAP - 标准轻量级目录访问协议
  • Active Directory - Microsoft Active Directory
  • OAuth2 - OAuth 2.0 授权框架
  • OpenID Connect - 基于OAuth 2.0的身份层

客户导入

启用"用于客户导入"后，将导入以下数据：

  • 姓名 - sn（姓氏）或 displayName
  • 名字 - givenName
  • 职位 - title（职位名称）
  • 公司 - company
  • 地址 - street/streetAddress、postalCode、l（城市）、st（省/州）、c（国家）
  • 性别 - Active Directory情况下，从personalTitle（Herr/Frau）获取

注意：使用OpenLDAP时，性别默认为"中性"，可手动修正。

通过目录登录

启用并保存"用于认证"后，用户即可使用其目录密码登录Klacks。 不会自动授予任何人访问权限：管理员需在 登录批准选项卡上逐个批准用户。

  • 该选项卡列出目录账户（最多1000个；可使用搜索来缩小列表范围）。
  • 勾选某个账户会创建一个没有角色、没有密码的新Klacks账户。现有的Klacks 账户绝不会被接管：如果该电子邮件地址已被某个Klacks账户使用，则该行无法 勾选。请先在用户管理中删除该账户或更改其电子邮件地址。
  • 取消勾选会停用该Klacks账户；再次勾选会重新启用，前提是该账户没有角色。 仍然拥有角色的已停用账户需在用户管理中重新启用。
  • 人员离职：有人离开时，请同时在Klacks中取消勾选。在目录中禁用该账户 会阻止新的登录，但已在运行的会话会继续有效，直至过期。
  • 在目录中没有电子邮件地址的账户无法被批准。
  • 无法在此选项卡上更改您自己的账户。
  • 目录凭据正确但未获批准的用户会收到提示：该账户 尚未获得批准，请联系管理员。

登录名

类型可接受的登录名
Active DirectorysAMAccountName、userPrincipalName或电子邮件地址
LDAPuid或电子邮件地址

Klacks使用绑定用户查找该用户，然后向目录校验密码，因此 登录名无需与电子邮件地址一致。

加密

389端口上的普通LDAP会以未加密方式发送密码；对于未启用SSL的LDAP提供商，表单会显示警告。 只要目录用于登录，请使用LDAPS（"使用SSL"，636端口）。

Active Directory：仅通过LDAPS登录

Klacks仅通过LDAPS（636端口）让用户登录Active Directory。没有SSL时，表单会显示警告， 任何人都无法登录，登录批准选项卡保持关闭。没有SSL时，客户导入和连接测试 仅在Klacks直接运行于Windows上时可用；在Docker（Linux）中，Active Directory的 所有操作都需要LDAPS。

  • 主机：域控制器证书中所示的完全限定名称（FQDN）， 例如dc01.example.local。IP地址无法使用，因为证书检查会比对名称。
  • 信任CA：运行Klacks的计算机必须信任签发域控制器证书的 证书颁发机构。Windows：将CA证书导入计算机的 受信任的根证书颁发机构存储区，例如certutil -addstore Root ca.cer （以管理员身份）。
  • 名称解析：如果无法通过DNS解析该FQDN，请添加hosts条目 （Windows：C:\Windows\System32\drivers\etc\hosts）。
  • Docker：将CA证书以PEM文件形式挂载到API容器中， 将环境变量LDAPTLS_CACERT设置为其路径，如果DNS无法解析， 则通过extra_hosts添加该FQDN。如果域控制器不发送CA 证书（自签名证书），则可将其自身的证书以PEM文件形式用作信任锚。 没有受信任的证书时，连接会被拒绝，并报告为连接错误。
  • 绑定账户：请以用户主体名称（UPN）输入，例如 svc-klacks@example.local。

导入哪些账户

  • 已禁用的账户和Active Directory系统账户绝不会被导入，也绝不会被列出。
  • 使用用户过滤器排除服务账户，例如仅限某个组的成员： (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

提示

使用Synology NAS作为LDAP服务器

您可以使用Synology NAS作为LDAP服务器。在这种情况下，需要安装"LDAP Server"软件包 或使用基于OpenLDAP的Docker容器。

  • 提供商类型："LDAP"（而非"Active Directory"）
  • 用户过滤器：(objectClass=inetOrgPerson)
  • 用户使用其uid或电子邮件地址登录
  • 建议优先使用LDAPS（636端口）

测试连接

请使用"测试连接"按钮来验证设置。它会显示用户过滤器找到的活动账户数量 （已禁用账户和系统账户不计入）以及一些示例用户名。数字后面的"+"表示目录服务器在其结果上限处停止， 即还有更多账户。
