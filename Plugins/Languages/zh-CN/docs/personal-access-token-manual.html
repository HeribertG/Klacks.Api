个人访问令牌手册

什么是个人访问令牌？

个人访问令牌（PAT）是长期有效的API密钥，可让外部工具和 服务安全地访问Klacks — 无需用户名和密码。

典型应用场景：

  • MCP（Model Context Protocol） — 允许像Claude Desktop这样的AI助手直接访问Klacksy技能
  • 通过MCP与Klacks协作的AI代理和助手

安全概念

Klacks绝不会存储明文令牌。创建后，数据库中仅存储 令牌的SHA-256哈希值。令牌本身仅在创建后 显示一次，之后将无法再次获取。

提示：创建后请立即记下或复制该令牌。如果丢失， 必须创建新令牌并撤销旧令牌。

创建令牌

逐步操作

  • 导航到配置 → 个人访问令牌
  • 点击创建新令牌
  • 指定一个有意义的名称（例如：Claude Desktop或AI代理规划）
  • 选择所需的有效期（1–730天，默认：365天）
  • 点击创建
  • 立即复制显示的令牌 — 它只会显示一次

令牌格式

klacks_pat_<随机字符串>

每个令牌都以前缀klacks_pat_开头，后跟一个加密安全的 随机字符串。

有效期

时长推荐用途
1–30天短期测试和开发
90–180天定期轮换的AI代理
365天（默认）长期集成（例如：Claude Desktop）
730天长期系统集成

访问模式

创建令牌时，您可以决定外部代理可以使用该令牌做什么：

  • 只读 （默认）— 代理只能查看和使用只读工具。任何更改数据的尝试都会被拒绝。
  • 读写 — 代理还可以更改数据，且无需有人逐一批准每项更改。请仅为您信任其进行更改的代理选择此模式。

模式会显示在令牌列表中，创建后无法更改；如有需要，请创建新令牌。现有令牌以及通过 OAuth 登录（例如 MCP 连接器）签发的令牌均为“读写”模式。

使用令牌

HTTP头部中的Bearer令牌

令牌会作为Bearer令牌，通过发往/mcp端点的每个MCP请求的Authorization头部传输：

Authorization: Bearer klacks_pat_...

为Claude Desktop配置MCP

MCP端点（/mcp）使Claude Desktop等AI助手能够直接 访问所有Klacksy技能 — 查询员工数据、安排班次、 管理组等等。

在Claude Desktop应用中的配置（claude_desktop_config.json）：

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<您的klacks域名>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

请将<您的klacks域名>替换为您Klacks安装的地址， 并将klacks_pat_...替换为您创建的令牌。

注意：令牌仅适用于AI代理的MCP访问（端点/mcp）。Klacks的REST API（例如/api/clients）不接受令牌，需要使用登录令牌。

管理与安全

令牌概览

在配置 → 个人访问令牌下，您可以查看所有令牌的 名称、创建日期、到期日期和最后使用时间。 明文令牌在此视图中永远不会显示。

撤销令牌

令牌可以随时撤销。撤销后，使用该令牌的所有请求 会立即被拒绝。请在以下情况下立即撤销令牌：

  • 令牌被意外泄露
  • 设备或服务不再使用
  • 您发现可疑活动

到期

已过期的令牌会自动被拒绝。Klacks会在概览中显示 未来30天内将要过期的令牌，以便您及时创建 新令牌。

安全建议

  • 为每个服务或工具使用单独的令牌
  • 选择有意义的名称，以便明确区分令牌
  • 切勿将令牌以明文形式存储在版本控制系统中
  • 定期轮换令牌
  • 一旦怀疑遭到滥用，立即撤销令牌

每个令牌都绑定到您的用户账户。通过MCP，令牌拥有您账户的权限，但最高只到主管（Supervisor）级别：即使您的账户是管理员，令牌也绝不会拥有管理员权限。此外，访问模式还限制了代理可以执行的操作：在“只读”模式下只能使用读取功能；在“读写”模式下，代理会在没有任何进一步确认的情况下执行更改。请像对待密码一样谨慎对待令牌。
