Manual Pembekal ID

Pengenalan

Dengan menggunakan Pembekal ID, anda boleh melaksanakan pengesahan pengguna melalui perkhidmatan direktori luaran seperti LDAP, Active Directory, OAuth2/OpenID Connect.

Jenis pembekal yang disokong:

  • LDAP - Protokol Akses Direktori Ringan Standard
  • Active Directory - Microsoft Active Directory
  • OAuth2 - Rangka Kerja Kebenaran OAuth 2.0
  • OpenID Connect - Lapisan Identiti di atas OAuth 2.0

Import Klien

Jika "Guna untuk import klien" diaktifkan, data berikut akan diimport:

  • Nama keluarga - sn (nama keluarga) atau displayName
  • Nama pertama - givenName
  • Jawatan - title (jawatan)
  • Syarikat - company
  • Alamat - street/streetAddress, postalCode, l (bandar), st (negeri), c (negara)
  • Jantina - Untuk Active Directory, diambil dari personalTitle (Herr/Frau)

Nota: Untuk OpenLDAP, jantina lalai ialah "Neutral" dan boleh diperbetulkan secara manual.

Log masuk melalui direktori

Apabila "Guna untuk pengesahan" diaktifkan dan disimpan, pengguna boleh log masuk ke Klacks dengan kata laluan direktori mereka. Tiada sesiapa mendapat akses secara automatik: pentadbir meluluskan setiap orang pada tab Kelulusan log masuk.

  • Tab ini menyenaraikan akaun direktori (paling banyak 1000; gunakan carian untuk mengecilkan senarai).
  • Menandakan satu akaun mencipta akaun Klacks baharu tanpa peranan dan tanpa kata laluan. Akaun Klacks sedia ada tidak pernah diambil alih: jika alamat e-mel sudah digunakan oleh akaun Klacks, baris itu tidak boleh ditandakan. Padam akaun tersebut atau tukar alamat e-melnya dalam pentadbiran pengguna terlebih dahulu.
  • Membuang tanda menyahaktifkan akaun Klacks; menandakannya semula mengaktifkannya semula, selagi akaun itu tidak mempunyai peranan. Akaun yang dinyahaktifkan tetapi masih mempunyai peranan diaktifkan semula dalam pentadbiran pengguna.
  • Penamatan perkhidmatan: apabila seseorang berhenti, buang juga tanda di Klacks. Menyahdayakan akaun dalam direktori menyekat log masuk baharu, tetapi sesi yang sedang berjalan diteruskan sehingga tamat tempoh.
  • Akaun tanpa alamat e-mel dalam direktori tidak boleh diluluskan.
  • Akaun anda sendiri tidak boleh diubah pada tab ini.
  • Seseorang yang mempunyai bukti kelayakan direktori yang betul tetapi tanpa kelulusan akan menerima mesej bahawa akaun itu belum diluluskan dan perlu menghubungi pentadbir.

Klacks mencari orang itu dengan pengguna ikatan dan kemudian menyemak kata laluan terhadap direktori, jadi nama log masuk tidak perlu sama dengan alamat e-mel.

Penyulitan

LDAP biasa pada port 389 menghantar kata laluan tanpa penyulitan; borang memaparkan amaran untuk pembekal LDAP tanpa SSL. Gunakan LDAPS ("Guna SSL", port 636) setiap kali direktori digunakan untuk log masuk.

Active Directory: log masuk hanya melalui LDAPS

Klacks melog masukkan pengguna ke Active Directory hanya melalui LDAPS (port 636). Tanpa SSL, borang memaparkan amaran, tiada sesiapa boleh log masuk dan tab kelulusan log masuk kekal tertutup. Tanpa SSL, import klien dan ujian sambungan hanya berfungsi apabila Klacks berjalan terus pada Windows; dalam Docker (Linux), Active Directory memerlukan LDAPS untuk semua fungsi.

  • Hos: nama yang layak sepenuhnya (FQDN) tepat seperti yang tertera dalam sijil pengawal domain, cth. dc01.example.local. Alamat IP tidak berfungsi, kerana semakan sijil membandingkan nama.
  • Percayai CA: komputer yang menjalankan Klacks mesti mempercayai pihak berkuasa sijil yang mengeluarkan sijil pengawal domain. Windows: import sijil CA ke dalam stor Trusted Root Certification Authorities komputer, cth. certutil -addstore Root ca.cer (sebagai pentadbir).
  • Resolusi nama: jika FQDN tidak dapat diselesaikan melalui DNS, tambahkan entri hosts (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: lekapkan sijil CA sebagai fail PEM ke dalam kontena API, tetapkan pemboleh ubah persekitaran LDAPTLS_CACERT kepada lokasinya, dan tambahkan FQDN dengan extra_hosts jika DNS tidak menyelesaikannya. Jika pengawal domain tidak menghantar sijil CA (sijil ditandatangani sendiri), sijilnya sendiri sebagai fail PEM berfungsi sebagai sauh kepercayaan. Tanpa sijil yang dipercayai, sambungan ditolak dan dilaporkan sebagai ralat sambungan.
  • Akaun ikatan: masukkannya sebagai nama prinsipal pengguna (UPN), cth. svc-klacks@example.local.

Akaun yang diimport

  • Akaun yang dinyahdayakan dan akaun sistem Active Directory tidak pernah diimport dan tidak pernah disenaraikan.
  • Kecualikan akaun perkhidmatan dengan penapis pengguna, cth. hanya ahli satu kumpulan: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Petua

Menggunakan Synology NAS sebagai Pelayan LDAP

Anda boleh menggunakan Synology NAS sebagai pelayan LDAP. Dalam kes ini, anda perlu memasang pakej "Pelayan LDAP" atau kontena Docker dengan OpenLDAP.

  • Jenis pembekal: "LDAP" (bukan "Active Directory")
  • Penapis pengguna: (objectClass=inetOrgPerson)
  • Pengguna log masuk dengan uid atau alamat e-mel mereka
  • Utamakan LDAPS (port 636)

Menguji Sambungan

Gunakan butang "Uji sambungan" untuk mengesahkan tetapan anda. Butang ini memaparkan bilangan akaun aktif yang ditemui oleh penapis pengguna (akaun yang dinyahdayakan dan akaun sistem tidak dikira) serta beberapa contoh nama pengguna. Tanda "+" selepas nombor bermakna pelayan direktori berhenti pada had hasilnya, jadi terdapat lebih banyak akaun.
