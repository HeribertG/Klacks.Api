Panduan Personal Access Token

Apakah itu Personal Access Token?

Personal Access Token (PAT) ialah kunci API tahan lama yang membolehkan alat dan perkhidmatan luaran mengakses Klacks dengan selamat — tanpa nama pengguna dan kata laluan.

Kes penggunaan biasa:

  • MCP (Model Context Protocol) — membenarkan pembantu AI seperti Claude Desktop mengakses Skill Klacksy secara terus
  • Skrip automasi dan saluran paip CI/CD
  • Alat pemantauan dan integrasi luaran

Konsep Keselamatan

Klacks tidak pernah menyimpan token dalam bentuk teks biasa. Selepas dicipta, hanya cincangan SHA-256 token yang disimpan dalam pangkalan data. Token itu sendiri hanya dipaparkan sekali sahaja sejurus selepas ia dicipta dan selepas itu tidak boleh diambil semula.

Nota: Catat atau salin token dengan segera selepas ia dicipta. Jika hilang, token baharu perlu dicipta dan token lama dibatalkan.

Mencipta Token

Langkah demi Langkah

  • Navigasi ke Konfigurasi → Personal Access Tokens
  • Klik Cipta Token Baharu
  • Berikan Nama yang jelas (cth. Claude Desktop atau CI-Pipeline)
  • Pilih Tempoh Sah yang dikehendaki (1–730 hari, lalai: 365 hari)
  • Klik Cipta
  • Salin token yang dipaparkan dengan segera — ia hanya dipaparkan sekali sahaja

Format Token

klacks_pat_<rentetan aksara rawak>

Setiap token bermula dengan awalan klacks_pat_ diikuti dengan rentetan aksara rawak yang selamat secara kriptografi.

Tempoh Sah

TempohPenggunaan Disyorkan
1–30 hariUjian dan pembangunan jangka pendek
90–180 hariSaluran paip CI/CD dengan putaran berkala
365 hari (lalai)Integrasi kekal (cth. Claude Desktop)
730 hariIntegrasi sistem jangka panjang

Menggunakan Token

Bearer Token dalam Header HTTP

Token dihantar sebagai bearer token dalam header Authorization bagi setiap permintaan API:

Authorization: Bearer klacks_pat_...

Mengkonfigurasi MCP dengan Claude Desktop

Endpoint MCP (/mcp) membolehkan pembantu AI seperti Claude Desktop mengakses semua Skill Klacksy secara terus — menyemak data pekerja, merancang syif, menguruskan kumpulan dan banyak lagi.

Konfigurasi dalam aplikasi Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<domain-klacks-anda>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

Gantikan <domain-klacks-anda> dengan alamat instalasi Klacks anda dan klacks_pat_... dengan token yang telah anda cipta.

Permintaan API Langsung (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<domain-klacks-anda>/api/clients

Pengurusan dan Keselamatan

Ringkasan Token

Di bawah Konfigurasi → Personal Access Tokens anda boleh melihat semua token anda berserta nama, tarikh dicipta, tarikh luput dan penggunaan terakhir. Token dalam bentuk teks biasa tidak pernah dipaparkan dalam paparan ini.

Membatalkan Token

Token boleh dibatalkan pada bila-bila masa. Selepas dibatalkan, semua permintaan dengan token tersebut akan ditolak dengan serta-merta. Batalkan token dengan segera jika:

  • Token secara tidak sengaja telah dikongsikan
  • Sesebuah peranti atau perkhidmatan tidak lagi digunakan
  • Anda mengesyaki aktiviti yang mencurigakan

Tamat Tempoh

Token yang telah luput akan ditolak secara automatik. Klacks memaparkan dalam ringkasan token yang akan luput dalam 30 hari akan datang, supaya anda dapat mencipta token baharu tepat pada masanya.

Tip Keselamatan

  • Gunakan token berasingan untuk setiap perkhidmatan atau alat
  • Pilih nama yang jelas supaya token dapat dikenal pasti dengan tepat
  • Jangan sekali-kali simpan token dalam bentuk teks biasa dalam sistem kawalan versi
  • Putarkan token secara berkala, terutamanya untuk penggunaan CI/CD
  • Batalkan token dengan segera jika disyaki disalahgunakan

Setiap token terikat kepada akaun pengguna anda dan mempunyai kebenaran yang sama seperti akaun anda. Layan token dengan tahap kewaspadaan yang sama seperti kata laluan anda.
