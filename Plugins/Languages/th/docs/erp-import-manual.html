คู่มือการนำเข้าใบสั่งงานจากระบบ ERP

การนำเข้าใบสั่งงานจาก ERP คืออะไร?

ระบบ ERP ภายนอกส่งใบสั่งงานเป็น ไฟล์ XML ไปยัง Klacks โดยมีวิธีการส่งข้อมูล 3 แบบ:

  • Drop-Point (การดึงข้อมูล): ระบบ ERP จะวางไฟล์ไว้ในที่จัดเก็บไฟล์ของ Drop-Point — ขึ้นอยู่กับการติดตั้ง อาจเป็นไดเรกทอรีบนเซิร์ฟเวอร์ Klacks (ค่าเริ่มต้น) หรือที่จัดเก็บอ็อบเจ็กต์ที่รองรับ S3 ระบบ Klacks จะดึงไฟล์ดังกล่าวโดยอัตโนมัติ ตามตารางเวลาที่กำหนดไว้
  • อัปโหลดโดยตรง (Push): ระบบ ERP ส่งไฟล์ผ่าน HTTP POST ไปยัง /api/erp-import/upload โดยยืนยันตัวตนด้วย ERP-Import-Token ในรูปแบบ Bearer-Token ขนาดไฟล์สูงสุดต่อไฟล์คือ 50 MB
  • อัปโหลดด้วยตนเอง: ผู้ดูแลระบบสามารถลากไฟล์ XML มาวางในพื้นที่วาง บนหน้านี้โดยตรง (หรือคลิกที่พื้นที่นั้นเพื่อเลือกไฟล์) หลังอัปโหลดแล้ว การนำเข้าจะเริ่มโดยอัตโนมัติภายในหนึ่งนาที และปุ่ม นำเข้าทันที สามารถกดเพื่อสั่งเริ่มได้ทุกเมื่อ

Drop-Point

Drop-Point คือกล่องรับไฟล์กลางสำหรับไฟล์นำเข้าทั้งหมด ระบบ Klacks จัดการโดยอัตโนมัติ — ไม่ต้องมีใครสร้างหรือกำหนดค่าเอง หน้านี้แสดงเนื้อหาของ Drop-Point ในรูปแบบมุมมองไฟล์ แบ่งเป็น 3 ส่วน: กล่องขาเข้า (รอรอบการนำเข้าถัดไป) ประมวลผลแล้ว (คลังเก็บ) และ ข้อผิดพลาด (ไฟล์ที่อ่านไม่ได้หรือไม่ถูกต้อง พร้อมสาเหตุของข้อผิดพลาด) สามารถย้ายไฟล์ที่มีข้อผิดพลาด กลับไปยังกล่องขาเข้าได้ผ่านปุ่ม นำเข้าอีกครั้ง

  • สวิตช์เปิดใช้งาน (การนำเข้าทำงานอยู่) — หยุดการนำเข้าอัตโนมัติชั่วคราว ไฟล์ที่วางไว้แล้วจะยังคงอยู่
  • แสดงสถานะ — เวลาที่ดึงข้อมูลล่าสุด และหากมี ข้อผิดพลาดล่าสุด

โทเคนสำหรับการเข้าถึง

  • สำหรับการส่งข้อมูลแบบ Push ผู้ดูแลระบบสามารถสร้างโทเคนสำหรับการเข้าถึงได้ — จำเป็น เฉพาะเมื่อระบบ ERP ภายนอกส่งไฟล์ผ่าน HTTPS โทเคนแต่ละตัวจะขึ้นต้นด้วย klacks_erp_
  • สามารถเลือกระยะเวลาที่ใช้งานได้ (1 ถึง 730 วัน ค่าเริ่มต้น 365 วัน)
  • ข้อความล้วนของโทเคนจะแสดง เพียงครั้งเดียวตอนสร้าง เท่านั้น หลังจากนั้นจะไม่สามารถเรียกดูได้อีก — กรุณาคัดลอกและเก็บไว้อย่างปลอดภัยทันที
  • โทเคนสำหรับการนำเข้า ERP ถูกออกแบบให้ ใช้ได้เฉพาะกับ endpoint การนำเข้าเท่านั้น หากโทเคนตกไปอยู่ในมือผู้ให้บริการ ERP ที่ไม่ถูกต้อง จะไม่สามารถใช้เข้าถึง API อื่นใดของ Klacks ได้
  • สามารถเพิกถอนโทเคนได้ทุกเมื่อ การเข้าถึงจะสิ้นสุดทันที

ตารางเวลา

การดึงข้อมูลจาก Drop-Point เป็นไปตาม นิพจน์ Cron (ค่าเริ่มต้น 0 * * * * = ทุกชั่วโมง) ใน เขตเวลา ที่เลือกไว้ ทั้งสองอย่างสามารถกำหนดค่าได้ในหน้านี้ นิพจน์ Cron ที่ไม่ถูกต้องจะทำให้การนำเข้าหยุดทำงาน — ดังนั้นข้อมูลที่ป้อนจะถูกตรวจสอบความถูกต้อง และค่าที่ไม่ถูกต้องจะไม่ถูกบันทึก

รูปแบบ XML (ข้อมูลอ้างอิง)

องค์ประกอบราก (root element) คือ ErpOrderImport พร้อมแอตทริบิวต์ที่จำเป็น schemaVersion (ปัจจุบันคือ 1) และ sourceSystemId sourceSystemId ใช้ระบุระบบต้นทางที่ส่งข้อมูล ภายในไฟล์ และช่วยให้การจับคู่ลูกค้าคงที่ตลอดทุกการส่งข้อมูล — ค่านี้ต้องคงที่ถาวรสำหรับระบบต้นทางแต่ละระบบ ใบสั่งงานแต่ละรายการอยู่ในองค์ประกอบ <Order> แยกกัน ไฟล์หนึ่งไฟล์สามารถมีใบสั่งงานได้ไม่จำกัดจำนวน

องค์ประกอบ จำเป็น รูปแบบ ความหมาย
ExternalOrderReference ใช่ ข้อความ หมายเลขอ้างอิงใบสั่งงานที่ไม่ซ้ำกันจากระบบ ERP
Description ไม่ ข้อความ ข้อความอิสระเกี่ยวกับใบสั่งงาน (เช่น หมายเหตุการปฏิบัติงาน) จะแสดงบนใบสั่งงาน
Customer ใช่ องค์ประกอบ ข้อมูลลูกค้าของใบสั่งงาน (ดูองค์ประกอบย่อย)
Customer/ExternalCustomerReference ไม่ (แนะนำ) ข้อความ หมายเลขอ้างอิงลูกค้าภายนอก ช่วยให้การจับคู่ลูกค้าคงที่ตลอดทุกการนำเข้า
Customer/Company ใช่ ข้อความ ชื่อบริษัทของลูกค้า
Customer/Address/Street ใช่ ข้อความ ชื่อถนนและเลขที่บ้าน
Customer/Address/Zip ใช่ ข้อความ รหัสไปรษณีย์
Customer/Address/City, Customer/Address/State, Customer/Address/Country ไม่ ข้อความ เมือง รัฐ/แคว้น และประเทศ
FromDate ใช่ yyyy-MM-dd วันที่เริ่มต้นของใบสั่งงาน
UntilDate ไม่ yyyy-MM-dd วันที่สิ้นสุดของใบสั่งงาน หากไม่ระบุหรือเว้นว่าง = ไม่มีกำหนด
StartTime, EndTime ใช่ HH:mm เวลาเริ่มต้นและสิ้นสุดของการปฏิบัติงาน
IsTimeRange ไม่ true/false (ค่าเริ่มต้น false) true = ช่วงเวลาที่ทำงานภายใน; false = กะทำงานตายตัวตั้งแต่ StartTime ถึง EndTime หากเป็น true ต้องระบุ Duration
Duration เมื่อ IsTimeRange=true องค์ประกอบที่มี <Hours> และ <Minutes> (จำนวนเต็ม) ระยะเวลาของการปฏิบัติงานแต่ละครั้ง เช่น 0 ชั่วโมง 20 นาที สำหรับการปฏิบัติงาน 20 นาทีในช่วงเวลา 08:00–15:00 สำหรับกะตายตัวเป็นทางเลือก หากไม่มีองค์ประกอบนี้ ระยะเวลาจะคำนวณจาก StartTime ถึง EndTime
Quantity ไม่ จำนวนเต็ม (ค่าเริ่มต้น 1) จำนวนครั้งของการปฏิบัติงาน
SumEmployees ไม่ จำนวนเต็ม (ค่าเริ่มต้น 1) จำนวนพนักงานที่ต้องการ
Weekdays ใช่ แอตทริบิวต์ monday … sunday แต่ละรายการเป็น true/false วันในสัปดาห์ของใบสั่งงาน; ต้องมีอย่างน้อยหนึ่งวันที่เป็น true แอตทริบิวต์ที่ไม่ระบุจะถือเป็น false ใบสั่งงานที่ไม่มีวันในสัปดาห์เลยจะถูกปฏิเสธ

หมายเหตุ: ชื่อองค์ประกอบมีความไวต่อตัวพิมพ์เล็ก-ใหญ่ (case-sensitive) สามารถดาวน์โหลดไฟล์ตัวอย่างฉบับสมบูรณ์ได้ผ่านปุ่ม ดาวน์โหลดไฟล์ตัวอย่าง เหนือคู่มือนี้

การจับคู่ลูกค้า

Klacks จับคู่ใบสั่งงานแต่ละรายการเข้ากับลูกค้าดังนี้:

  • ก่อนอื่นจะใช้การผสมผสานระหว่างรหัสระบบต้นทางและหมายเลขอ้างอิงลูกค้าภายนอก — เมื่อจับคู่แล้วครั้งหนึ่ง หมายเลขอ้างอิงนี้จะยังคงผูกกับลูกค้ารายเดิมตลอดไป
  • หากไม่มีหมายเลขอ้างอิงภายนอก ในการปรากฏครั้งแรกจะค้นหาจากบริษัท + รหัสไปรษณีย์ + ถนน โดยไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่และช่องว่าง
  • หากไม่พบผลลัพธ์ที่ตรงกัน Klacks จะสร้างลูกค้าใหม่โดยอัตโนมัติ

การประมวลผลและวงจรชีวิต

  • ใบสั่งงานที่นำเข้ามาจะถูกสร้างเป็น ฉบับร่าง และต้องได้รับการตรวจสอบ และปิดผนึกโดยผู้วางแผนหรือผู้ดูแลระบบ ในขั้นตอนนี้ผู้วางแผนจะเพิ่มข้อกำหนดคุณสมบัติ ที่จำเป็น (หากมี) — ระบบ ERP สามารถส่งข้อมูลนี้เป็นคำแนะนำในฟิลด์ Description ได้
  • หากระบบ ERP ส่งใบสั่งงานฉบับ ที่แก้ไขแล้ว ของใบสั่งงานที่ปิดผนึกไปแล้ว ในภายหลัง Klacks จะปิดใบสั่งงานเดิมโดยอัตโนมัติด้วยวันที่สิ้นสุด และสร้างฉบับร่างใหม่ ที่เชื่อมโยงกัน การปฏิบัติงานในอนาคตที่วางแผนไว้แล้วและยังไม่ถูกล็อกของใบสั่งงานเดิม จะถูกลบออก และผู้วางแผนจะได้รับการแจ้งเตือน
  • การส่งข้อมูลซ้ำที่ ไม่มีการเปลี่ยนแปลง (เช่น การส่งออกข้อมูลทั้งหมดทุกคืน) จะไม่ก่อให้เกิดการกระทำใด ๆ

การจัดการข้อผิดพลาดและคลังเก็บ

  • ไฟล์ที่ประมวลผลแล้วจะถูกย้ายไปยังโฟลเดอร์ย่อย processed/ ในที่จัดเก็บไฟล์ (คลังเก็บ ไม่ใช่การลบ) และจะปรากฏบนหน้า นำเข้าในส่วน ประมวลผลแล้ว
  • ไฟล์ที่อ่านไม่ได้หรือไม่ถูกต้องจะถูกย้ายไปยังโฟลเดอร์ย่อย error/ และปรากฏในส่วน ข้อผิดพลาด จากที่นั่นสามารถย้ายกลับไปยังกล่องขาเข้าได้ผ่าน นำเข้าอีกครั้ง
  • ใบสั่งงานที่ไม่สมบูรณ์หรือไม่ถูกต้องจะถูกปฏิเสธ (เช่น ไม่มีวันในสัปดาห์ มี UntilDate ก่อน FromDate หรือมี ExternalOrderReference ซ้ำกันในไฟล์เดียวกัน) ใบสั่งงานที่เหลือในไฟล์เดียวกันจะยังคงถูกนำเข้าตามปกติ
  • หากไฟล์มีใบสั่งงานที่ถูกปฏิเสธอย่างน้อยหนึ่งรายการ ไฟล์นั้นจะถูกย้ายไปยังส่วน ข้อผิดพลาด พร้อมสาเหตุการปฏิเสธ — ในขณะที่ใบสั่งงานที่นำเข้าไปแล้ว จะยังคงอยู่
  • ข้อผิดพลาดจะถูกบันทึกและผู้ดูแลระบบจะได้รับการแจ้งเตือน
