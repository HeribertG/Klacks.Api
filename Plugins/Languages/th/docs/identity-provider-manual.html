คู่มือผู้ให้บริการยืนยันตัวตน

บทนำ

ผู้ให้บริการยืนยันตัวตนช่วยให้สามารถยืนยันตัวตนผู้ใช้ผ่านบริการไดเรกทอรีภายนอก เช่น LDAP, Active Directory, OAuth2/OpenID Connect

ประเภทผู้ให้บริการที่รองรับ:

  • LDAP - โปรโตคอลเข้าถึงไดเรกทอรีน้ำหนักเบามาตรฐาน
  • Active Directory - Microsoft Active Directory
  • OAuth2 - กรอบการทำงานการอนุญาต OAuth 2.0
  • OpenID Connect - ชั้นยืนยันตัวตนบน OAuth 2.0

การนำเข้าลูกค้า

หากเปิดใช้งาน "ใช้สำหรับนำเข้าลูกค้า" ข้อมูลต่อไปนี้จะถูกนำเข้า:

  • นามสกุล - sn (นามสกุล) หรือ displayName
  • ชื่อ - givenName
  • ตำแหน่ง - title (ตำแหน่งงาน)
  • บริษัท - company
  • ที่อยู่ - street/streetAddress, postalCode, l (เมือง), st (จังหวัด), c (ประเทศ)
  • เพศ - สำหรับ Active Directory จะดึงจาก personalTitle (Herr/Frau)

หมายเหตุ: สำหรับ OpenLDAP เพศจะเป็น "กลาง" โดยค่าเริ่มต้น และสามารถแก้ไขด้วยตนเองได้

การลงชื่อเข้าใช้ผ่านไดเรกทอรี

เมื่อเปิดใช้และบันทึก "ใช้สำหรับยืนยันตัวตน" แล้ว ผู้คนจะลงชื่อเข้าใช้ Klacks ด้วยรหัสผ่านของไดเรกทอรีได้ แต่จะไม่มีใครได้รับสิทธิ์เข้าใช้โดยอัตโนมัติ: ผู้ดูแลระบบต้องอนุมัติแต่ละคนที่แท็บ การอนุมัติการลงชื่อเข้าใช้

  • แท็บนี้แสดงรายการบัญชีของไดเรกทอรี (สูงสุด 1000 บัญชี ใช้การค้นหาเพื่อจำกัดรายการให้แคบลง)
  • การติ๊กเลือกบัญชีจะสร้างบัญชี Klacks ใหม่ที่ไม่มีบทบาทและไม่มีรหัสผ่าน บัญชี Klacks ที่มีอยู่แล้วจะไม่ถูกนำมาใช้ต่อ: หากที่อยู่อีเมลถูกใช้โดยบัญชี Klacks อยู่แล้ว จะติ๊กเลือกแถวนั้นไม่ได้ ให้ลบบัญชีนั้นหรือเปลี่ยนอีเมลของบัญชีนั้นในการจัดการผู้ใช้ก่อน
  • การเอาเครื่องหมายติ๊กออกจะปิดใช้งานบัญชี Klacks ส่วนการติ๊กอีกครั้งจะเปิดใช้งานบัญชีอีกครั้ง หากบัญชีนั้นไม่มีบทบาท บัญชีที่ปิดใช้งานแต่ยังมีบทบาทอยู่ต้องเปิดใช้งานอีกครั้งในการจัดการผู้ใช้
  • เมื่อพนักงานลาออก: เมื่อมีคนลาออก ให้เอาเครื่องหมายติ๊กออกใน Klacks ด้วย การปิดใช้งานบัญชีใน ไดเรกทอรีจะบล็อกการลงชื่อเข้าใช้ครั้งใหม่ แต่เซสชันที่กำลังใช้งานอยู่จะยังคงทำงานต่อไปจนกว่าจะหมดอายุ
  • บัญชีที่ไม่มีที่อยู่อีเมลในไดเรกทอรีไม่สามารถอนุมัติได้
  • ไม่สามารถเปลี่ยนแปลงบัญชีของคุณเองในแท็บนี้ได้
  • ผู้ที่มีข้อมูลเข้าสู่ระบบของไดเรกทอรีถูกต้องแต่ยังไม่ได้รับอนุมัติ จะได้รับข้อความว่าบัญชีนี้ ยังไม่ได้รับอนุมัติและให้ติดต่อผู้ดูแลระบบ

ชื่อสำหรับลงชื่อเข้าใช้

ประเภทชื่อสำหรับลงชื่อเข้าใช้ที่ยอมรับ
Active DirectorysAMAccountName, userPrincipalName หรือที่อยู่อีเมล
LDAPuid หรือที่อยู่อีเมล

Klacks ค้นหาบุคคลด้วยผู้ใช้ Bind แล้วตรวจสอบรหัสผ่านกับไดเรกทอรี ดังนั้น ชื่อสำหรับลงชื่อเข้าใช้จึงไม่จำเป็นต้องตรงกับที่อยู่อีเมล

การเข้ารหัส

LDAP ธรรมดาบนพอร์ต 389 ส่งรหัสผ่านโดยไม่เข้ารหัส แบบฟอร์มจะแสดงคำเตือนสำหรับผู้ให้บริการ LDAP ที่ไม่ใช้ SSL ให้ใช้ LDAPS ("ใช้ SSL" พอร์ต 636) ทุกครั้งที่ใช้ไดเรกทอรีสำหรับการลงชื่อเข้าใช้

Active Directory: ลงชื่อเข้าใช้ผ่าน LDAPS เท่านั้น

Klacks ให้ผู้คนลงชื่อเข้าใช้ Active Directory ผ่าน LDAPS (พอร์ต 636) เท่านั้น หากไม่มี SSL แบบฟอร์มจะแสดงคำเตือน ไม่มีใครลงชื่อเข้าใช้ได้ และแท็บการอนุมัติการลงชื่อเข้าใช้จะยังคงปิดอยู่ หากไม่มี SSL การนำเข้าลูกค้าและ การทดสอบการเชื่อมต่อจะใช้ได้เฉพาะเมื่อ Klacks ทำงานบน Windows โดยตรงเท่านั้น ส่วนใน Docker (Linux) Active Directory ต้องใช้ LDAPS สำหรับทุกการทำงาน

  • โฮสต์: ชื่อที่ระบุครบถ้วน (FQDN) ตรงตามที่ปรากฏในใบรับรองของโดเมนคอนโทรลเลอร์ เช่น dc01.example.local ที่อยู่ IP ใช้ไม่ได้ เพราะการตรวจสอบใบรับรอง จะเปรียบเทียบชื่อ
  • เชื่อถือ CA: คอมพิวเตอร์ที่รัน Klacks ต้องเชื่อถือผู้ออกใบรับรอง (CA) ที่ ออกใบรับรองให้โดเมนคอนโทรลเลอร์ Windows: นำเข้าใบรับรองของ CA ลงในที่เก็บ Trusted Root Certification Authorities ของคอมพิวเตอร์ เช่น certutil -addstore Root ca.cer (ในฐานะผู้ดูแลระบบ)
  • การแปลงชื่อ: หาก DNS แปลง FQDN ไม่ได้ ให้เพิ่มรายการในไฟล์ hosts (Windows: C:\Windows\System32\drivers\etc\hosts)
  • Docker: เมานต์ใบรับรองของ CA เป็นไฟล์ PEM เข้าไปในคอนเทนเนอร์ API ตั้งค่าตัวแปรสภาพแวดล้อม LDAPTLS_CACERT เป็นพาธของไฟล์ และเพิ่ม FQDN ด้วย extra_hosts หาก DNS แปลงชื่อไม่ได้ หากโดเมนคอนโทรลเลอร์ไม่ส่งใบรับรองของ CA (ใบรับรองที่ลงนามด้วยตนเอง) ให้ใช้ใบรับรองของโดเมนคอนโทรลเลอร์เองเป็นไฟล์ PEM เป็นจุดยึดความเชื่อถือ หากไม่มีใบรับรองที่เชื่อถือได้ การเชื่อมต่อจะถูกปฏิเสธและรายงานเป็นข้อผิดพลาดการเชื่อมต่อ
  • บัญชี Bind: ป้อนเป็นชื่อหลักของผู้ใช้ (UPN) เช่น svc-klacks@example.local

บัญชีใดที่ถูกนำเข้า

  • บัญชีที่ปิดใช้งานและบัญชีระบบของ Active Directory จะไม่ถูกนำเข้าและไม่ถูกแสดงในรายการเลย
  • ยกเว้นบัญชีบริการด้วยตัวกรองผู้ใช้ เช่น เฉพาะสมาชิกของกลุ่มเดียว: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

เคล็ดลับ

ใช้ Synology NAS เป็นเซิร์ฟเวอร์ LDAP

คุณสามารถใช้ Synology NAS เป็นเซิร์ฟเวอร์ LDAP ได้ ในกรณีนี้ คุณต้องติดตั้ง แพ็กเกจ "LDAP Server" หรือคอนเทนเนอร์ Docker ที่ใช้ OpenLDAP

  • ประเภทผู้ให้บริการ: "LDAP" (ไม่ใช่ "Active Directory")
  • ตัวกรองผู้ใช้: (objectClass=inetOrgPerson)
  • ผู้ใช้ลงชื่อเข้าใช้ด้วย uid หรือที่อยู่อีเมล
  • แนะนำให้ใช้ LDAPS (พอร์ต 636)

ทดสอบการเชื่อมต่อ

ใช้ปุ่ม "ทดสอบการเชื่อมต่อ" เพื่อตรวจสอบการตั้งค่า ระบบจะแสดงจำนวนบัญชีที่ใช้งานอยู่ซึ่ง ตัวกรองผู้ใช้พบ (ไม่นับบัญชีที่ปิดใช้งานและบัญชีระบบ) และชื่อผู้ใช้ตัวอย่างบางส่วน เครื่องหมาย "+" หลังตัวเลขหมายความว่าเซิร์ฟเวอร์ไดเรกทอรีหยุดที่ขีดจำกัดผลลัพธ์ จึงยังมีบัญชีอื่นอีก
