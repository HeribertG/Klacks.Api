Personlige adgangstokens manual

Hvad er personlige adgangstokens?

Personlige adgangstokens (PAT'er) er langtidsholdbare API-nøgler, der giver eksterne værktøjer og tjenester sikker adgang til Klacks — uden brugernavn og adgangskode.

Typiske anvendelsestilfælde:

  • MCP (Model Context Protocol) — giver AI-assistenter som Claude Desktop direkte adgang til Klacksy-skills
  • Automatiseringsscripts og CI/CD-pipelines
  • Eksterne overvågnings- og integrationsværktøjer

Sikkerhedskoncept

Klacks gemmer aldrig tokenet i klartekst. Efter oprettelsen gemmes udelukkende en SHA-256-hash af tokenet i databasen. Selve tokenet vises kun én eneste gang, umiddelbart efter oprettelsen, og kan derefter ikke længere hentes.

Bemærk: Notér eller kopiér tokenet straks efter oprettelsen. Ved bortkomst skal der oprettes et nyt token, og det gamle skal tilbagekaldes.

Opret token

Trin for trin

  • Naviger til Konfiguration → Personlige adgangstokens
  • Klik på Opret nyt token
  • Giv tokenet et sigende navn (f.eks. Claude Desktop eller CI-pipeline)
  • Vælg den ønskede gyldighedsperiode (1–730 dage, standard: 365 dage)
  • Klik på Opret
  • Kopiér det viste token straks — det vises kun én gang

Tokenformat

klacks_pat_<tilfældig tegnfølge>

Hvert token begynder med præfikset klacks_pat_ efterfulgt af en kryptografisk sikker tilfældig tegnfølge.

Gyldighedsperiode

VarighedAnbefalet brug
1–30 dageKortsigtede tests og udvikling
90–180 dageCI/CD-pipelines med regelmæssig rotation
365 dage (standard)Permanente integrationer (f.eks. Claude Desktop)
730 dageLangsigtede systemintegrationer

Brug token

Bearer-token i HTTP-headeren

Tokenet sendes som bearer-token i Authorization-headeren for hver API-forespørgsel:

Authorization: Bearer klacks_pat_...

Konfigurér MCP med Claude Desktop

MCP-endpointet (/mcp) giver AI-assistenter som Claude Desktop direkte adgang til alle Klacksy-skills — hente medarbejderdata, planlægge vagter, administrere grupper og meget mere.

Konfiguration i Claude Desktop-appen (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<dit-klacks-domæne>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

Erstat <dit-klacks-domæne> med adressen på din Klacks-installation og klacks_pat_... med dit oprettede token.

Direkte API-forespørgsel (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<dit-klacks-domæne>/api/clients

Administration og sikkerhed

Oversigt over tokens

Under Konfiguration → Personlige adgangstokens ser du alle dine tokens med navn, oprettelsesdato, udløbsdato og seneste brug. Tokenet i klartekst vises aldrig i denne visning.

Tilbagekald token

Et token kan til enhver tid tilbagekaldes. Efter tilbagekaldelsen afvises alle forespørgsler med dette token øjeblikkeligt. Tilbagekald tokens straks, hvis:

  • Tokenet ved en fejl er blevet videregivet
  • En enhed eller tjeneste ikke længere bruges
  • Du bemærker mistænkelig aktivitet

Udløb

Udløbne tokens afvises automatisk. Klacks viser i oversigten tokens, der udløber inden for de næste 30 dage, så du i god tid kan oprette nye tokens.

Sikkerhedstip

  • Brug et separat token pr. tjeneste eller værktøj
  • Vælg sigende navne, så tokens entydigt kan tildeles
  • Gem aldrig tokens i klartekst i versionsstyringssystemer
  • Rotér tokens regelmæssigt, især ved CI/CD-brug
  • Tilbagekald tokens straks ved mistanke om misbrug

Hvert token er bundet til din brugerkonto og har de samme tilladelser som din konto. Behandl tokens med samme omhu som din adgangskode.
