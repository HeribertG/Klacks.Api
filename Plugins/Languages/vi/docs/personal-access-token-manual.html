Hướng dẫn Personal Access Tokens

Personal Access Tokens là gì?

Personal Access Tokens (PAT) là các khóa API dài hạn cho phép các công cụ và dịch vụ bên ngoài truy cập an toàn vào Klacks — không cần tên đăng nhập và mật khẩu.

Các trường hợp sử dụng điển hình:

  • MCP (Model Context Protocol) — cho phép các trợ lý AI như Claude Desktop truy cập trực tiếp vào các kỹ năng của Klacksy
  • Các kịch bản tự động hóa và pipeline CI/CD
  • Các công cụ giám sát và tích hợp bên ngoài

Khái niệm bảo mật

Klacks không bao giờ lưu trữ token dưới dạng văn bản thuần túy. Sau khi tạo, chỉ một hash SHA-256 của token được lưu trong cơ sở dữ liệu. Bản thân token chỉ được hiển thị một lần duy nhất ngay sau khi tạo và sau đó không thể truy xuất lại được nữa.

Lưu ý: Hãy ghi lại hoặc sao chép token ngay sau khi tạo. Nếu bị mất, phải tạo một token mới và thu hồi token cũ.

Tạo token

Từng bước

  • Điều hướng đến Cấu hình → Personal Access Tokens
  • Nhấp vào Tạo token mới
  • Đặt một tên có ý nghĩa (ví dụ: Claude Desktop hoặc CI-Pipeline)
  • Chọn thời hạn hiệu lực mong muốn (1–730 ngày, mặc định: 365 ngày)
  • Nhấp vào Tạo
  • Sao chép ngay token được hiển thị — nó chỉ được hiển thị một lần

Định dạng Token

klacks_pat_<chuỗi ký tự ngẫu nhiên>

Mỗi token bắt đầu bằng tiền tố klacks_pat_ theo sau là một chuỗi ký tự ngẫu nhiên an toàn về mặt mật mã.

Thời hạn hiệu lực

Thời hạnKhuyến nghị sử dụng
1–30 ngàyKiểm thử và phát triển ngắn hạn
90–180 ngàyPipeline CI/CD với luân chuyển định kỳ
365 ngày (mặc định)Tích hợp lâu dài (ví dụ: Claude Desktop)
730 ngàyTích hợp hệ thống dài hạn

Sử dụng Token

Bearer Token trong header HTTP

Token được truyền dưới dạng Bearer Token trong header Authorization của mỗi yêu cầu API:

Authorization: Bearer klacks_pat_...

Cấu hình MCP với Claude Desktop

Endpoint MCP (/mcp) cho phép các trợ lý AI như Claude Desktop truy cập trực tiếp vào tất cả các kỹ năng của Klacksy — truy vấn dữ liệu nhân viên, lập kế hoạch ca làm việc, quản lý nhóm và nhiều hơn nữa.

Cấu hình trong ứng dụng Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<tên-miền-klacks-của-bạn>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

Thay thế <tên-miền-klacks-của-bạn> bằng địa chỉ của phiên bản Klacks của bạn và klacks_pat_... bằng token bạn đã tạo.

Yêu cầu API trực tiếp (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<tên-miền-klacks-của-bạn>/api/clients

Quản lý và bảo mật

Tổng quan các Token

Tại Cấu hình → Personal Access Tokens, bạn có thể xem tất cả các token của mình với tên, ngày tạo, ngày hết hạn và lần sử dụng cuối cùng. Token dạng văn bản thuần túy không bao giờ được hiển thị trong chế độ xem này.

Thu hồi Token

Một token có thể được thu hồi bất cứ lúc nào. Sau khi thu hồi, tất cả các yêu cầu với token này sẽ ngay lập tức bị từ chối. Hãy thu hồi token ngay khi:

  • Token đã bị vô tình chia sẻ
  • Một thiết bị hoặc dịch vụ không còn được sử dụng nữa
  • Bạn nhận thấy hoạt động đáng ngờ

Hết hạn

Các token đã hết hạn sẽ tự động bị từ chối. Klacks hiển thị trong phần tổng quan các token sẽ hết hạn trong 30 ngày tới, để bạn có thể kịp thời tạo các token mới.

Mẹo bảo mật

  • Sử dụng một token riêng cho mỗi dịch vụ hoặc công cụ
  • Chọn tên có ý nghĩa để có thể gán token một cách rõ ràng
  • Không bao giờ lưu trữ token dưới dạng văn bản thuần túy trong hệ thống quản lý phiên bản
  • Luân chuyển token định kỳ, đặc biệt khi sử dụng với CI/CD
  • Thu hồi token ngay lập tức nếu nghi ngờ bị lạm dụng

Mỗi token được gắn với tài khoản người dùng của bạn và có cùng quyền hạn như tài khoản của bạn. Hãy xử lý token với sự cẩn trọng giống như mật khẩu của bạn.
