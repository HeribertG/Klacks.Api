Manual Personal Access Tokens

Ce sunt Personal Access Tokens?

Personal Access Tokens (PAT) sunt chei API de lungă durată care permit instrumentelor și serviciilor externe accesul securizat la Klacks — fără nume de utilizator și parolă.

Cazuri de utilizare tipice:

  • MCP (Model Context Protocol) — permite asistenților AI precum Claude Desktop accesul direct la skill-urile Klacksy
  • Agenți și asistenți AI care lucrează cu Klacks prin MCP

Concept de securitate

Klacks nu stochează niciodată tokenul în clar. După creare, în baza de date se salvează exclusiv un hash SHA-256 al tokenului. Tokenul în sine este afișat o singură dată, imediat după creare, și ulterior nu mai poate fi recuperat.

Notă: Notați sau copiați tokenul imediat după creare. În caz de pierdere, trebuie creat un token nou, iar cel vechi trebuie revocat.

Crearea unui token

Pas cu pas

  • Navigați la Configurare → Personal Access Tokens
  • Faceți clic pe Creare token nou
  • Alegeți un nume sugestiv (de ex. Claude Desktop sau Agent AI planificare)
  • Selectați durata de valabilitate dorită (1–730 de zile, implicit: 365 de zile)
  • Faceți clic pe Creare
  • Copiați imediat tokenul afișat — acesta este afișat o singură dată

Formatul tokenului

klacks_pat_<șir de caractere aleatoriu>

Fiecare token începe cu prefixul klacks_pat_ urmat de un șir de caractere aleatoriu, generat criptografic securizat.

Durata de valabilitate

DuratăUtilizare recomandată
1–30 de zileTeste și dezvoltare pe termen scurt
90–180 de zileAgenți AI cu rotație regulată
365 de zile (implicit)Integrări permanente (de ex. Claude Desktop)
730 de zileIntegrări de sistem pe termen lung

Mod de acces

La creare stabiliți ce poate face un agent extern cu tokenul:

  • Doar citire (implicit) — agentul vede și folosește exclusiv instrumente de citire. Orice încercare de a modifica date este respinsă.
  • Citire și scriere — agentul poate în plus să modifice date fără ca o persoană să aprobe fiecare modificare în parte. Alegeți acest mod doar pentru agenții cărora le încredințați modificări.

Modul este afișat în lista de tokenuri și nu poate fi schimbat ulterior; la nevoie creați un token nou. Tokenurile existente și cele emise printr-o autentificare OAuth (de ex. un conector MCP) au modul „Citire și scriere”.

Utilizarea tokenului

Bearer token în header-ul HTTP

Tokenul este transmis ca Bearer token în header-ul Authorization al fiecărei cereri MCP către endpoint-ul /mcp:

Authorization: Bearer klacks_pat_...

Configurarea MCP cu Claude Desktop

Endpoint-ul MCP (/mcp) permite asistenților AI precum Claude Desktop accesul direct la toate skill-urile Klacksy — interogarea datelor angajaților, planificarea turelor, gestionarea grupurilor și multe altele.

Configurare în aplicația Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<domeniul-dvs-klacks>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Înlocuiți <domeniul-dvs-klacks> cu adresa instalării dvs. Klacks și klacks_pat_... cu tokenul creat de dvs.

Notă: Tokenurile funcționează numai pentru accesul MCP al agenților IA (endpoint /mcp). API-ul REST Klacks (de ex. /api/clients) nu le acceptă; acesta cere tokenul de autentificare.

Administrare și securitate

Prezentare generală a tokenurilor

La secțiunea Configurare → Personal Access Tokens puteți vedea toate tokenurile dvs. cu nume, data creării, data expirării și ultima utilizare. Tokenul în clar nu este afișat niciodată în această vizualizare.

Revocarea unui token

Un token poate fi revocat oricând. După revocare, toate cererile efectuate cu acest token sunt respinse imediat. Revocați tokenurile imediat atunci când:

  • Tokenul a fost divulgat din greșeală
  • Un dispozitiv sau serviciu nu mai este utilizat
  • Observați activități suspecte

Expirare

Tokenurile expirate sunt respinse automat. Klacks afișează în prezentarea generală tokenurile care expiră în următoarele 30 de zile, pentru ca dvs. să puteți crea la timp tokenuri noi.

Recomandări de securitate

  • Utilizați un token separat pentru fiecare serviciu sau instrument
  • Alegeți nume sugestive, pentru a putea identifica tokenurile fără echivoc
  • Nu stocați niciodată tokenurile în clar în sisteme de control al versiunilor
  • Rotiți tokenurile regulat
  • Revocați tokenurile imediat în cazul suspiciunii de utilizare abuzivă

Fiecare token este legat de contul dvs. de utilizator. Prin MCP, tokenul dispune de permisiunile contului dvs., dar limitate cel mult la nivelul de supervizor: chiar dacă contul dvs. este de administrator, tokenul nu are niciodată drepturi de administrator. În plus, modul de acces limitează ce poate face agentul: cu «Doar citire» folosește numai funcții de citire; cu «Citire și scriere» efectuează modificări fără nicio confirmare suplimentară. Tratați tokenurile cu aceeași grijă ca și parola dvs.
