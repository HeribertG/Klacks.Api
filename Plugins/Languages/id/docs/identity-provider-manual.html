Panduan Identity Provider

Pendahuluan

Dengan menggunakan Identity Provider, Anda dapat melakukan autentikasi pengguna melalui layanan direktori eksternal seperti LDAP, Active Directory, OAuth2/OpenID Connect.

Jenis penyedia yang didukung:

  • LDAP - Protokol Akses Direktori Ringan Standar
  • Active Directory - Microsoft Active Directory
  • OAuth2 - Kerangka Otorisasi OAuth 2.0
  • OpenID Connect - Lapisan identitas di atas OAuth 2.0

Impor Klien

Jika "Gunakan untuk impor klien" diaktifkan, data berikut akan diimpor:

  • Nama belakang - sn (nama keluarga) atau displayName
  • Nama depan - givenName
  • Jabatan - title (nama jabatan)
  • Perusahaan - company
  • Alamat - street/streetAddress, postalCode, l (kota), st (provinsi), c (negara)
  • Jenis kelamin - Untuk Active Directory, diambil dari personalTitle (Herr/Frau)

Catatan: Untuk OpenLDAP, jenis kelamin secara default ditetapkan "Netral" dan dapat diperbaiki secara manual.

Login melalui direktori

Jika "Gunakan untuk autentikasi" diaktifkan dan disimpan, orang dapat login ke Klacks dengan kata sandi direktori mereka. Tidak ada yang mendapat akses secara otomatis: administrator menyetujui setiap orang di tab Persetujuan login.

  • Tab ini mencantumkan akun direktori (maksimal 1000; gunakan pencarian untuk mempersempit daftar).
  • Mencentang akun membuat akun Klacks baru tanpa peran dan tanpa kata sandi. Akun Klacks yang sudah ada tidak pernah diambil alih: jika alamat e-mail sudah digunakan oleh akun Klacks, baris tersebut tidak dapat dicentang. Hapus akun itu atau ubah alamat e-mailnya di administrasi pengguna terlebih dahulu.
  • Menghapus centang menonaktifkan akun Klacks; mencentang lagi mengaktifkannya kembali, selama akun tersebut tidak memiliki peran. Akun nonaktif yang masih memiliki peran diaktifkan kembali di administrasi pengguna.
  • Saat karyawan keluar: ketika seseorang keluar, hapus juga centangnya di Klacks. Menonaktifkan akun di direktori memblokir login baru, tetapi sesi yang sudah berjalan tetap berlanjut hingga kedaluwarsa.
  • Akun tanpa alamat e-mail di direktori tidak dapat disetujui.
  • Akun Anda sendiri tidak dapat diubah di tab ini.
  • Orang dengan kredensial direktori yang benar tetapi tanpa persetujuan akan mendapat pesan bahwa akun belum disetujui dan harus menghubungi administrator.

Klacks mencari orang tersebut dengan pengguna bind lalu memeriksa kata sandi ke direktori, sehingga nama login tidak harus sama dengan alamat e-mail.

Enkripsi

LDAP biasa pada port 389 mengirim kata sandi tanpa enkripsi; formulir menampilkan peringatan untuk penyedia LDAP tanpa SSL. Gunakan LDAPS ("Gunakan SSL", port 636) setiap kali direktori digunakan untuk login.

Active Directory: login hanya melalui LDAPS

Klacks mengautentikasi login ke Active Directory hanya melalui LDAPS (port 636). Tanpa SSL formulir menampilkan peringatan, tidak ada yang dapat login, dan tab Persetujuan login tetap tertutup. Tanpa SSL, impor klien dan uji koneksi hanya berfungsi jika Klacks berjalan langsung di Windows; di Docker (Linux) Active Directory memerlukan LDAPS untuk semuanya.

  • Host: nama lengkap (FQDN) persis seperti yang tercantum di sertifikat domain controller, mis. dc01.example.local. Alamat IP tidak berfungsi, karena pemeriksaan sertifikat membandingkan nama.
  • Percayai CA: komputer yang menjalankan Klacks harus mempercayai otoritas sertifikat yang menerbitkan sertifikat domain controller. Windows: impor sertifikat CA ke penyimpanan Otoritas Sertifikasi Akar Tepercaya (Trusted Root Certification Authorities) milik komputer, mis. certutil -addstore Root ca.cer (sebagai administrator).
  • Resolusi nama: jika FQDN tidak dapat di-resolve melalui DNS, tambahkan entri hosts (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: mount sertifikat CA sebagai file PEM ke dalam container API, atur variabel lingkungan LDAPTLS_CACERT ke path-nya, dan tambahkan FQDN dengan extra_hosts jika DNS tidak meresolusinya. Jika domain controller tidak mengirim sertifikat CA (sertifikat self-signed), sertifikatnya sendiri sebagai file PEM berfungsi sebagai trust anchor. Tanpa sertifikat tepercaya, koneksi ditolak dan dilaporkan sebagai kesalahan koneksi.
  • Akun bind: masukkan sebagai user principal name (UPN), mis. svc-klacks@example.local.

Akun yang diimpor

  • Akun nonaktif dan akun sistem Active Directory tidak pernah diimpor dan tidak pernah ditampilkan dalam daftar.
  • Kecualikan akun layanan dengan filter pengguna, mis. hanya anggota satu grup: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Tips

Menggunakan Synology NAS sebagai Server LDAP

Anda dapat menggunakan Synology NAS sebagai server LDAP. Dalam hal ini, Anda perlu menginstal paket "LDAP Server" atau container Docker dengan OpenLDAP.

  • Jenis penyedia: "LDAP" (bukan "Active Directory")
  • Filter pengguna: (objectClass=inetOrgPerson)
  • Pengguna login dengan uid atau alamat e-mail mereka
  • Utamakan LDAPS (port 636)

Menguji Koneksi

Gunakan tombol "Uji koneksi" untuk memverifikasi konfigurasi. Tombol ini menampilkan jumlah akun aktif yang ditemukan filter pengguna (akun nonaktif dan akun sistem tidak dihitung) dan beberapa contoh nama pengguna. Tanda "+" setelah angka berarti server direktori berhenti pada batas hasilnya, sehingga masih ada akun lain.
