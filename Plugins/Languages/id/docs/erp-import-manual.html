Impor Pesanan ERP – Panduan

Apa itu impor pesanan ERP?

Sistem ERP eksternal mengirimkan pesanan sebagai file XML ke Klacks. Ada tiga cara untuk transmisi:

  • Drop-Point (pengambilan): ERP menempatkan file di penyimpanan file drop-point – tergantung instalasi, sebuah direktori di server Klacks (standar) atau penyimpanan objek yang kompatibel dengan S3. Klacks mengambil file secara otomatis sesuai jadwal yang dikonfigurasi.
  • Unggah langsung (push): ERP mengirim file melalui HTTP POST ke /api/erp-import/upload dan mengautentikasi dirinya dengan token impor ERP sebagai bearer token. Maksimal 50 MB diizinkan per file.
  • Unggah manual: Administrator menyeret file XML langsung ke zona penyimpanan di halaman ini (atau mengklik zona tersebut untuk memilih sebuah file). Setelah diunggah, impor otomatis dipicu dan dimulai dalam satu menit; tombol Impor sekarang juga dapat memicunya kapan saja.

Drop-Point

Drop-point adalah kotak surat pusat untuk semua file impor. Klacks mengelolanya secara otomatis – tidak ada yang perlu membuatnya atau mengonfigurasinya. Halaman ini menampilkan isinya sebagai tampilan file dengan tiga area: Masuk (menunggu proses impor berikutnya), Diproses (arsip), dan Kesalahan (file yang tidak dapat dibaca atau tidak valid beserta alasan kesalahan). File kesalahan dapat dipindahkan kembali ke folder masuk melalui tombol Impor ulang.

  • Sakelar aktif (impor aktif) – menjeda impor otomatis; file yang sudah tersimpan tetap dipertahankan.
  • Tampilan status – waktu pengambilan terakhir dan, jika ada, kesalahan terakhir.

Token akses

  • Untuk pengiriman push, administrator dapat membuat token akses — hanya diperlukan jika sistem ERP eksternal mengirimkan file melalui HTTPS. Setiap token dimulai dengan prefiks klacks_erp_.
  • Masa berlaku dapat dipilih (1 hingga 730 hari, standar 365 hari).
  • Teks biasa token hanya ditampilkan satu kali saat pembuatan. Setelah itu tidak dapat diambil lagi – salin segera dan simpan dengan aman.
  • Token impor ERP sengaja dibuat hanya valid untuk endpoint impor. Jika sebuah token jatuh ke tangan yang salah di pihak penyedia ERP, tidak ada akses API lain ke Klacks yang dimungkinkan dengan token tersebut.
  • Token dapat dicabut kapan saja; akses berakhir seketika.

Jadwal

Pengambilan drop-point mengikuti ekspresi cron (standar 0 * * * * = setiap jam) dalam zona waktu yang dipilih. Keduanya dikonfigurasi di halaman ini. Ekspresi cron yang tidak valid akan menghentikan impor – oleh karena itu input divalidasi dan nilai yang tidak valid tidak akan disimpan.

Format XML (referensi)

Elemen root adalah ErpOrderImport dengan atribut wajib schemaVersion (saat ini 1) dan sourceSystemId. sourceSystemId mengidentifikasi sistem pengirim dalam file dan memastikan pemetaan klien yang stabil di seluruh pengiriman – nilai ini harus tetap konstan secara permanen per sistem sumber. Setiap pesanan berada dalam elemen <Order> tersendiri. Sebuah file boleh berisi jumlah pesanan berapa pun.

Elemen Wajib Format Arti
ExternalOrderReference Ya Teks Referensi pesanan unik dari sistem ERP.
Description Tidak Teks Teks bebas tentang pesanan (misalnya: petunjuk penugasan); ditampilkan pada pesanan.
Customer Ya Elemen Data klien dari pesanan (lihat sub-elemen).
Customer/ExternalCustomerReference Tidak (disarankan) Teks Referensi klien eksternal; memastikan pemetaan klien yang stabil di semua impor.
Customer/Company Ya Teks Nama perusahaan klien.
Customer/Address/Street Ya Teks Jalan dan nomor rumah.
Customer/Address/Zip Ya Teks Kode pos.
Customer/Address/City, Customer/Address/State, Customer/Address/Country Tidak Teks Kota, kanton/wilayah, dan negara.
FromDate Ya yyyy-MM-dd Awal pesanan.
UntilDate Tidak yyyy-MM-dd Akhir pesanan; jika tidak ada atau kosong = tidak terbatas waktu.
StartTime, EndTime Ya HH:mm Waktu mulai dan selesai penugasan.
IsTimeRange Tidak true/false (standar false) true = jendela waktu tempat pekerjaan dilakukan; false = shift tetap dari StartTime sampai EndTime. Jika true, Duration wajib diisi.
Duration Jika IsTimeRange=true Elemen dengan <Hours> dan <Minutes> (bilangan bulat) Durasi penugasan tunggal, misalnya 0 j 20 mnt untuk penugasan 20 menit dalam jendela waktu 08:00–15:00. Untuk shift tetap bersifat opsional; jika elemen tidak ada, berlaku durasi dari StartTime sampai EndTime.
Quantity Tidak Bilangan bulat (standar 1) Jumlah penugasan.
SumEmployees Tidak Bilangan bulat (standar 1) Jumlah karyawan yang diperlukan.
Weekdays Ya Atribut monday … sunday, masing-masing true/false Hari dalam seminggu untuk pesanan; setidaknya satu hari harus true, sebuah atribut yang tidak ada dihitung sebagai false. Pesanan tanpa hari dalam seminggu akan ditolak.

Catatan: Nama elemen bersifat case-sensitive. File contoh lengkap dapat diunduh melalui tombol Unduh file contoh di atas panduan ini.

Pemetaan klien

Klacks memetakan setiap pesanan ke seorang klien:

  • Pertama melalui kombinasi ID sistem sumber dan referensi klien eksternal – setelah dipetakan sekali, referensi ini tetap ditugaskan secara permanen ke klien yang sama.
  • Tanpa referensi eksternal, pada kemunculan pertama pencarian dilakukan melalui perusahaan + kode pos + jalan; huruf besar/kecil dan spasi diabaikan dalam proses ini.
  • Jika tidak ditemukan kecocokan, Klacks secara otomatis membuat klien baru.

Pemrosesan & Siklus hidup

  • Pesanan yang diimpor muncul sebagai draf dan harus diperiksa serta disegel oleh perencana atau administrator. Perencana juga melengkapi persyaratan kualifikasi apa pun — ERP dapat menyertakan ini sebagai petunjuk dalam bidang Description.
  • Jika ERP kemudian mengirimkan versi yang diubah dari sebuah pesanan yang sudah disegel, Klacks secara otomatis menutup pesanan lama dengan tanggal akhir dan membuat versi draf baru yang terhubung. Penugasan masa depan yang sudah dijadwalkan dan tidak terkunci dari pesanan lama akan dihapus dan perencana diberi tahu.
  • Pengiriman ulang yang tidak berubah (misalnya ekspor penuh setiap malam) tidak memicu apa pun.

Penanganan kesalahan & Arsip

  • File yang diproses dipindahkan dalam penyimpanan file ke subfolder processed/ (arsip, tidak dihapus); file tersebut muncul di halaman impor pada area Diproses.
  • File yang tidak dapat dibaca atau tidak valid dipindahkan ke subfolder error/ dan muncul di area Kesalahan; dari sana file dapat dipindahkan kembali ke folder masuk melalui Impor ulang.
  • Pesanan yang tidak lengkap atau tidak valid akan ditolak (misalnya tanpa hari dalam seminggu, dengan UntilDate sebelum FromDate, atau dengan ExternalOrderReference ganda dalam file yang sama); pesanan lain dalam file yang sama tetap diimpor.
  • Jika sebuah file berisi setidaknya satu pesanan yang ditolak, file tersebut dipindahkan dengan alasan penolakan ke area Kesalahan — pesanan yang sudah diimpor tetap dipertahankan.
  • Kesalahan dicatat dan administrator diberi tahu.
