Panduan Personal Access Tokens

Apa itu Personal Access Tokens?

Personal Access Tokens (PAT) adalah kunci API berumur panjang yang memungkinkan alat dan layanan eksternal mengakses Klacks secara aman — tanpa nama pengguna dan kata sandi.

Kasus penggunaan umum:

  • MCP (Model Context Protocol) — memungkinkan asisten AI seperti Claude Desktop mengakses langsung skill Klacksy
  • Agen dan asisten AI yang bekerja dengan Klacks melalui MCP

Konsep keamanan

Klacks tidak pernah menyimpan token dalam bentuk teks biasa. Setelah pembuatan, hanya hash SHA-256 dari token yang disimpan di database. Token itu sendiri hanya ditampilkan satu kali tepat setelah pembuatan dan setelah itu tidak dapat diambil lagi.

Catatan: Catat atau salin token segera setelah pembuatan. Jika hilang, token baru harus dibuat dan yang lama dicabut.

Membuat token

Langkah demi langkah

  • Navigasikan ke Konfigurasi → Personal Access Tokens
  • Klik Buat token baru
  • Berikan nama yang deskriptif (misalnya Claude Desktop atau Agen AI perencanaan)
  • Pilih masa berlaku yang diinginkan (1–730 hari, standar: 365 hari)
  • Klik Buat
  • Salin token yang ditampilkan segera — token hanya ditampilkan satu kali

Format token

klacks_pat_<rangkaian karakter acak>

Setiap token dimulai dengan prefiks klacks_pat_ diikuti oleh rangkaian karakter acak yang aman secara kriptografis.

Masa berlaku

DurasiPenggunaan yang disarankan
1–30 hariPengujian jangka pendek dan pengembangan
90–180 hariAgen AI dengan rotasi rutin
365 hari (standar)Integrasi permanen (misalnya Claude Desktop)
730 hariIntegrasi sistem jangka panjang

Mode akses

Saat membuat token, Anda menentukan apa yang boleh dilakukan agen eksternal dengan token tersebut:

  • Hanya baca (bawaan) — agen hanya melihat dan menggunakan alat baca. Setiap upaya mengubah data akan ditolak.
  • Baca dan tulis — agen juga dapat mengubah data tanpa persetujuan seseorang untuk setiap perubahan. Pilih mode ini hanya untuk agen yang Anda percayai untuk melakukan perubahan.

Mode ditampilkan di daftar token dan tidak dapat diubah setelahnya; buat token baru jika perlu. Token yang sudah ada dan token yang diterbitkan melalui login OAuth (mis. konektor MCP) memiliki mode “Baca dan tulis”.

Menggunakan token

Bearer token dalam header HTTP

Token dikirim sebagai bearer token dalam header Authorization pada setiap permintaan MCP ke endpoint /mcp:

Authorization: Bearer klacks_pat_...

Mengonfigurasi MCP dengan Claude Desktop

Endpoint MCP (/mcp) memungkinkan asisten AI seperti Claude Desktop mengakses langsung semua skill Klacksy — menanyakan data karyawan, menjadwalkan shift, mengelola grup, dan banyak lagi.

Konfigurasi di aplikasi Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<domain-klacks-anda>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Ganti <domain-klacks-anda> dengan alamat instalasi Klacks Anda dan klacks_pat_... dengan token yang Anda buat.

Catatan: Token hanya berlaku untuk akses MCP bagi agen AI (endpoint /mcp). REST API Klacks (misalnya /api/clients) tidak menerimanya; REST API memerlukan token login.

Manajemen dan keamanan

Ikhtisar token

Di Konfigurasi → Personal Access Tokens Anda dapat melihat semua token Anda dengan nama, tanggal pembuatan, tanggal kedaluwarsa, dan penggunaan terakhir. Token dalam bentuk teks biasa tidak pernah ditampilkan di tampilan ini.

Mencabut token

Token dapat dicabut kapan saja. Setelah dicabut, semua permintaan dengan token tersebut akan langsung ditolak. Cabut token segera jika:

  • Token secara tidak sengaja dibagikan
  • Perangkat atau layanan tidak lagi digunakan
  • Anda melihat aktivitas mencurigakan

Kedaluwarsa

Token yang kedaluwarsa akan otomatis ditolak. Klacks menampilkan dalam ikhtisar token yang akan kedaluwarsa dalam 30 hari ke depan, agar Anda dapat membuat token baru tepat waktu.

Tips keamanan

  • Gunakan token terpisah untuk setiap layanan atau alat
  • Pilih nama yang deskriptif agar token dapat diidentifikasi dengan jelas
  • Jangan pernah menyimpan token dalam bentuk teks biasa di sistem kontrol versi
  • Rotasi token secara rutin
  • Cabut token segera jika dicurigai disalahgunakan

Setiap token terikat pada akun pengguna Anda. Melalui MCP, token memiliki izin akun Anda, tetapi dibatasi paling tinggi pada tingkat supervisor: meskipun akun Anda adalah administrator, token tidak pernah memiliki hak administrator. Selain itu, mode akses membatasi apa yang boleh dilakukan agen: dengan "Hanya baca" agen hanya menggunakan fungsi baca; dengan "Baca dan tulis" agen melakukan perubahan tanpa konfirmasi tambahan. Perlakukan token dengan kehati-hatian yang sama seperti kata sandi Anda.
