ID 프로바이더 매뉴얼

소개

ID 프로바이더를 사용하면 LDAP, Active Directory, OAuth2/OpenID Connect 등 외부 디렉토리 서비스를 통해 사용자 인증을 수행할 수 있습니다.

지원 프로바이더 유형:

  • LDAP - 표준 경량 디렉토리 액세스 프로토콜
  • Active Directory - Microsoft Active Directory
  • OAuth2 - OAuth 2.0 인가 프레임워크
  • OpenID Connect - OAuth 2.0 기반 ID 레이어

클라이언트 가져오기

"클라이언트 가져오기에 사용"을 활성화한 경우 다음 데이터를 가져옵니다:

  • 성 - sn (성) 또는 displayName
  • 이름 - givenName
  • 직책 - title (직책명)
  • 회사 - company
  • 주소 - street/streetAddress, postalCode, l (시/구), st (도/광역시), c (국가)
  • 성별 - Active Directory의 경우 personalTitle (Herr/Frau)에서 가져옴

참고: OpenLDAP의 경우 성별은 기본적으로 "중립"으로 설정되며 수동으로 수정할 수 있습니다.

디렉토리를 통한 로그인

"인증에 사용"을 활성화하고 저장하면 사용자는 디렉토리 비밀번호로 Klacks에 로그인할 수 있습니다. 자동으로 접근 권한을 얻는 사람은 없으며, 관리자가 로그인 승인 탭에서 각 사용자를 승인합니다.

  • 이 탭에는 디렉토리 계정이 표시됩니다(최대 1000개, 검색으로 목록을 좁힐 수 있습니다).
  • 계정을 체크하면 역할과 비밀번호가 없는 새 Klacks 계정이 생성됩니다. 기존 Klacks 계정은 절대 인수되지 않습니다. 이메일 주소가 이미 Klacks 계정에서 사용 중이면 해당 행은 체크할 수 없습니다. 먼저 사용자 관리에서 그 계정을 삭제하거나 이메일 주소를 변경하세요.
  • 체크를 해제하면 Klacks 계정이 비활성화되고, 다시 체크하면 역할이 없는 한 계정이 다시 활성화됩니다. 역할이 남아 있는 비활성 계정은 사용자 관리에서 다시 활성화합니다.
  • 퇴사 처리: 누군가 퇴사하면 Klacks에서도 체크를 해제하세요. 디렉토리에서 계정을 비활성화하면 새로운 로그인은 차단되지만, 이미 실행 중인 세션은 만료될 때까지 계속됩니다.
  • 디렉토리에 이메일 주소가 없는 계정은 승인할 수 없습니다.
  • 본인 계정은 이 탭에서 변경할 수 없습니다.
  • 디렉토리 자격 증명은 올바르지만 승인되지 않은 사람에게는 계정이 승인되지 않았으며 관리자에게 문의해야 한다는 메시지가 표시됩니다.

로그인 이름

유형허용되는 로그인 이름

Klacks는 바인드 사용자로 해당 사용자를 검색한 다음 디렉토리에서 비밀번호를 확인하므로, 로그인 이름이 이메일 주소와 일치할 필요는 없습니다.

암호화

포트 389의 일반 LDAP는 비밀번호를 암호화하지 않고 전송합니다. SSL이 없는 LDAP 프로바이더에는 양식에 경고가 표시됩니다. 디렉토리를 로그인에 사용하는 경우에는 항상 LDAPS("SSL 사용", 포트 636)를 사용하세요.

Active Directory: LDAPS를 통한 로그인만 지원

Klacks는 LDAPS(포트 636)를 통해서만 Active Directory에 사용자를 로그인시킵니다. SSL이 없으면 양식에 경고가 표시되고, 아무도 로그인할 수 없으며 로그인 승인 탭은 닫힌 상태로 유지됩니다. SSL이 없는 경우 클라이언트 가져오기와 연결 테스트는 Klacks가 Windows에서 직접 실행될 때만 동작하며, Docker(Linux)에서는 Active Directory의 모든 기능에 LDAPS가 필요합니다.

  • 호스트: 도메인 컨트롤러 인증서에 표시된 것과 정확히 동일한 정규화된 이름(FQDN)입니다. 예: dc01.example.local. 인증서 검사가 이름을 비교하므로 IP 주소는 동작하지 않습니다.
  • CA 신뢰: Klacks를 실행하는 컴퓨터는 도메인 컨트롤러 인증서를 발급한 인증 기관을 신뢰해야 합니다. Windows: CA 인증서를 컴퓨터의 신뢰할 수 있는 루트 인증 기관 저장소로 가져옵니다. 예: certutil -addstore Root ca.cer (관리자 권한으로 실행).
  • 이름 확인: FQDN을 DNS로 확인할 수 없으면 hosts 항목을 추가하세요 (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: CA 인증서를 PEM 파일로 API 컨테이너에 마운트하고, 환경 변수 LDAPTLS_CACERT를 해당 경로로 설정하며, DNS로 확인되지 않으면 FQDN을 extra_hosts로 추가하세요. 도메인 컨트롤러가 CA 인증서를 보내지 않는 경우(자체 서명 인증서)에는 해당 도메인 컨트롤러 자신의 인증서를 PEM 파일로 사용하면 신뢰 앵커로 동작합니다. 신뢰할 수 있는 인증서가 없으면 연결이 거부되고 연결 오류로 표시됩니다.
  • 바인드 계정: 사용자 계정 이름(UPN) 형식으로 입력하세요. 예: svc-klacks@example.local.

가져오는 계정

  • 비활성화된 계정과 Active Directory 시스템 계정은 가져오지 않으며 목록에도 표시되지 않습니다.
  • 사용자 필터로 서비스 계정을 제외하세요. 예를 들어 한 그룹의 구성원만 허용: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

팁

Synology NAS를 LDAP 서버로 사용

Synology NAS를 LDAP 서버로 사용할 수 있습니다. 이 경우 "LDAP 서버" 패키지 또는 OpenLDAP를 사용한 Docker 컨테이너를 설치해야 합니다.

  • 프로바이더 유형: "LDAP" ("Active Directory"가 아님)
  • 사용자 필터: (objectClass=inetOrgPerson)
  • 사용자는 uid 또는 이메일 주소로 로그인합니다
  • LDAPS(포트 636) 사용을 권장합니다

연결 테스트

"연결 테스트" 버튼을 사용하여 설정을 확인하세요. 사용자 필터로 찾은 활성 계정의 수(비활성 계정과 시스템 계정은 포함되지 않음)와 몇 가지 샘플 사용자명이 표시됩니다. 숫자 뒤의 "+"는 디렉토리 서버가 결과 한도에서 멈췄다는 뜻이며, 더 많은 계정이 있습니다.
