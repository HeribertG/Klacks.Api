ERP 주문 가져오기 – 매뉴얼

ERP 주문 가져오기란?

외부 ERP 시스템은 주문 데이터를 XML 파일 형태로 Klacks에 전달합니다. 전송 방식에는 세 가지가 있습니다:

  • 드롭 포인트(가져오기 대기): ERP가 드롭 포인트의 파일 저장소에 파일을 저장합니다 – 설치 방식에 따라 Klacks 서버의 디렉터리(기본값) 또는 S3 호환 오브젝트 스토리지가 사용됩니다. Klacks는 설정된 일정에 따라 파일을 자동으로 가져옵니다.
  • 직접 업로드(푸시): ERP가 HTTP POST로 /api/erp-import/upload에 파일을 전송하며, 이때 ERP 가져오기 토큰을 Bearer 토큰으로 사용하여 인증합니다. 파일당 최대 50 MB까지 허용됩니다.
  • 수동 업로드: 관리자가 이 페이지의 업로드 영역으로 XML 파일을 직접 드래그하거나(또는 영역을 클릭하여 파일을 선택), 업로드 후 가져오기가 자동으로 실행되어 1분 이내에 시작됩니다. 지금 가져오기 버튼으로 언제든지 추가로 실행할 수도 있습니다.

드롭 포인트

드롭 포인트는 모든 가져오기 파일이 모이는 중앙 우편함입니다. Klacks가 자동으로 관리하므로 별도로 생성하거나 설정할 필요가 없습니다. 이 페이지는 드롭 포인트의 내용을 수신함(다음 가져오기 실행 대기), 처리 완료(보관함), 오류(읽을 수 없거나 유효하지 않은 파일과 오류 원인) 세 영역으로 나누어 보여줍니다. 오류 파일은 다시 가져오기 버튼으로 수신함으로 되돌릴 수 있습니다.

  • 활성 스위치(가져오기 활성화) – 자동 가져오기를 일시 중지합니다; 이미 저장된 파일은 그대로 유지됩니다.
  • 상태 표시 – 마지막 가져오기 실행 시각과, 있는 경우 마지막 오류를 표시합니다.

액세스 토큰

  • 푸시 방식으로 전달할 경우 관리자가 액세스 토큰을 생성할 수 있습니다 – 외부 ERP 시스템이 HTTPS로 파일을 전송할 때만 필요합니다. 모든 토큰은 klacks_erp_ 접두사로 시작합니다.
  • 유효 기간은 선택할 수 있습니다(1일에서 730일까지, 기본값 365일).
  • 토큰의 원문은 생성 시 단 한 번만 표시됩니다. 이후에는 다시 조회할 수 없으므로 즉시 복사하여 안전하게 보관해야 합니다.
  • ERP 가져오기 토큰은 의도적으로 가져오기 엔드포인트에서만 사용할 수 있습니다. ERP 서비스 제공업체에서 토큰이 유출되더라도 Klacks의 다른 API에는 접근할 수 없습니다.
  • 토큰은 언제든지 취소할 수 있으며, 취소 즉시 접근 권한이 종료됩니다.

일정

드롭 포인트 가져오기는 선택한 시간대에서 Cron 표현식(기본값 0 * * * * = 매시간)을 따릅니다. 두 설정 모두 이 페이지에서 구성합니다. 잘못된 Cron 표현식은 가져오기를 중단시킬 수 있으므로 입력값이 검증되며, 유효하지 않은 값은 저장되지 않습니다.

XML 형식(참조)

루트 요소는 ErpOrderImport이며, 필수 속성으로 schemaVersion(현재 1)과 sourceSystemId를 가집니다. sourceSystemId는 파일 내에서 전송 시스템을 식별하며 모든 전송 건에 걸쳐 안정적인 고객 매칭을 보장합니다 – 소스 시스템별로 항상 동일한 값을 유지해야 합니다. 각 주문은 별도의 <Order> 요소로 표현됩니다. 하나의 파일에는 원하는 수만큼 주문을 포함할 수 있습니다.

요소 필수 여부 형식 의미
ExternalOrderReference 필수 텍스트 ERP 시스템의 고유 주문 참조 번호.
Description 선택 텍스트 주문에 대한 자유 텍스트(예: 작업 안내); 주문 화면에 표시됩니다.
Customer 필수 요소 주문에 속한 고객 데이터(하위 요소 참조).
Customer/ExternalCustomerReference 선택(권장) 텍스트 외부 고객 참조 번호; 모든 가져오기에 걸쳐 안정적인 고객 매칭을 보장합니다.
Customer/Company 필수 텍스트 고객의 회사명.
Customer/Address/Street 필수 텍스트 도로명과 건물 번호.
Customer/Address/Zip 필수 텍스트 우편번호.
Customer/Address/City, Customer/Address/State, Customer/Address/Country 선택 텍스트 도시, 주/지역, 국가.
FromDate 필수 yyyy-MM-dd 주문 시작일.
UntilDate 선택 yyyy-MM-dd 주문 종료일; 없거나 비어 있으면 기한 없음을 의미합니다.
StartTime, EndTime 필수 HH:mm 근무 시작 시각과 종료 시각.
IsTimeRange 선택 true/false(기본값 false) true = 근무가 이루어지는 시간대 범위; false = StartTime부터 EndTime까지의 고정 근무. true인 경우 Duration이 필수입니다.
Duration IsTimeRange=true일 때 필수 <Hours>와 <Minutes>(정수)를 포함하는 요소 개별 근무의 소요 시간, 예를 들어 08:00–15:00 시간대 범위 내 20분 근무의 경우 0시간 20분. 고정 근무의 경우 선택 사항이며, 이 요소가 없으면 StartTime부터 EndTime까지의 시간이 적용됩니다.
Quantity 선택 정수(기본값 1) 근무 건수.
SumEmployees 선택 정수(기본값 1) 필요한 직원 수.
Weekdays 필수 monday … sunday 속성, 각각 true/false 주문이 적용되는 요일; 최소 하나의 요일은 true여야 하며, 속성이 없으면 false로 간주됩니다. 요일이 지정되지 않은 주문은 거부됩니다.

참고: 요소 이름은 대소문자를 구분합니다. 이 매뉴얼 상단의 예제 파일 다운로드 버튼을 통해 완전한 예제 파일을 받을 수 있습니다.

고객 매칭

Klacks는 각 주문을 다음 순서로 고객에게 매칭합니다:

  • 먼저 소스 시스템 ID와 외부 고객 참조 번호의 조합으로 매칭합니다 – 한 번 매칭되면 이 참조 번호는 영구적으로 동일한 고객에게 연결됩니다.
  • 외부 참조 번호가 없는 경우 최초 등록 시 회사명 + 우편번호 + 도로명으로 검색합니다; 이때 대소문자와 공백은 무시됩니다.
  • 일치하는 항목이 없으면 Klacks가 자동으로 신규 고객을 생성합니다.

처리 및 생명주기

  • 가져온 주문은 초안 상태로 생성되며, 플래너 또는 관리자가 검토하여 확정해야 합니다. 이때 플래너는 필요한 자격 요건도 함께 추가합니다 – ERP는 이를 Description 필드에 안내로 함께 제공할 수 있습니다.
  • 이미 확정된 주문에 대해 ERP가 나중에 변경된 버전을 전송하면, Klacks는 기존 주문을 종료일로 자동 마감하고 연결된 새 초안 버전을 생성합니다. 기존 주문에서 이미 계획되어 있던 미래의, 잠기지 않은 근무는 삭제되며 플래너에게 알림이 전송됩니다.
  • 변경되지 않은 반복 전송(예: 야간 전체 내보내기)은 아무런 동작도 유발하지 않습니다.

오류 처리 및 보관

  • 처리된 파일은 파일 저장소의 processed/ 하위 폴더로 이동됩니다(삭제가 아닌 보관); 가져오기 페이지의 처리 완료 영역에 표시됩니다.
  • 읽을 수 없거나 유효하지 않은 파일은 error/ 하위 폴더로 이동되며 오류 영역에 표시됩니다; 이곳에서 다시 가져오기 버튼으로 수신함으로 되돌릴 수 있습니다.
  • 불완전하거나 유효하지 않은 주문은 거부됩니다(예: 요일이 지정되지 않은 경우, UntilDate가 FromDate보다 앞서는 경우, 동일 파일 내에 ExternalOrderReference가 중복되는 경우 등); 같은 파일 내의 나머지 주문은 그대로 가져옵니다.
  • 파일에 거부된 주문이 하나라도 포함되어 있으면 해당 파일은 거부 사유와 함께 오류 영역으로 이동합니다 – 이미 가져온 주문은 그대로 유지됩니다.
  • 오류는 기록되며 관리자에게 알림이 전송됩니다.
