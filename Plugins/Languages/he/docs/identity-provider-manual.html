מדריך ספק זהות

מבוא

באמצעות ספקי זהות ניתן לבצע אימות משתמשים דרך שירותי ספרייה חיצוניים כגון LDAP, Active Directory, OAuth2/OpenID Connect.

סוגי ספקים נתמכים:

  • LDAP - פרוטוקול גישה קלת משקל לספרייה
  • Active Directory - Microsoft Active Directory
  • OAuth2 - מסגרת הרשאות OAuth 2.0
  • OpenID Connect - שכבת זהות מעל OAuth 2.0

ייבוא לקוחות

כאשר "השתמש לייבוא לקוחות" מופעל, הנתונים הבאים מיובאים:

  • שם משפחה - sn (שם משפחה) או displayName
  • שם פרטי - givenName
  • תפקיד - title (שם התפקיד)
  • חברה - company
  • כתובת - street/streetAddress, postalCode, l (עיר), st (מדינה/מחוז), c (מדינה)
  • מין - ב-Active Directory, נלקח מ-personalTitle (Herr/Frau)

הערה: ב-OpenLDAP, המין מוגדר כברירת מחדל כ"ניטרלי" וניתן לתקן ידנית.

כניסה דרך הספרייה

כאשר "השתמש לאימות" מופעל ונשמר, אנשים יכולים להיכנס ל-Klacks עם סיסמת הספרייה שלהם. אף אחד לא מקבל גישה אוטומטית: המנהל מאשר כל אדם בלשונית אישור כניסה.

  • הלשונית מציגה את חשבונות הספרייה (עד 1000; ניתן לצמצם את הרשימה באמצעות החיפוש).
  • סימון חשבון יוצר חשבון Klacks חדש ללא תפקיד וללא סיסמה. חשבונות Klacks קיימים לעולם אינם מאומצים או מקושרים: אם כתובת האימייל כבר בשימוש בחשבון Klacks, לא ניתן לסמן את השורה. יש למחוק תחילה את אותו חשבון או לשנות את כתובת האימייל שלו בניהול המשתמשים.
  • הסרת הסימון משביתה את חשבון Klacks; סימון חוזר מפעיל אותו מחדש, כל עוד אין לו תפקיד. חשבון מושבת שעדיין יש לו תפקידים מופעל מחדש בניהול המשתמשים.
  • עזיבת עובד: כאשר מישהו עוזב, יש להסיר את הסימון גם ב-Klacks. השבתת החשבון בספרייה חוסמת כניסות חדשות, אך הפעלות שכבר פעילות נמשכות עד שתוקפן פוקע.
  • לא ניתן לאשר חשבון ללא כתובת אימייל בספרייה.
  • לא ניתן לשנות את החשבון שלך בלשונית זו.
  • אדם עם פרטי הזדהות נכונים בספרייה אך ללא אישור מקבל הודעה שהחשבון לא אושר ושעליו לפנות למנהל.

שמות כניסה

סוגשמות כניסה מתקבלים
Active DirectorysAMAccountName, userPrincipalName או כתובת אימייל
LDAPuid או כתובת אימייל

Klacks מאתר את האדם באמצעות משתמש החיבור ואז בודק את הסיסמה מול הספרייה, ולכן שם הכניסה אינו חייב להתאים לכתובת האימייל.

הצפנה

LDAP רגיל בפורט 389 שולח סיסמאות ללא הצפנה; הטופס מציג אזהרה עבור ספק LDAP ללא SSL. יש להשתמש ב-LDAPS ("השתמש ב-SSL", פורט 636) בכל פעם שהספרייה משמשת לכניסה.

Active Directory: כניסה רק דרך LDAPS

Klacks מאמת כניסה של אנשים מול Active Directory רק דרך LDAPS (פורט 636). ללא SSL הטופס מציג אזהרה, אף אחד לא יכול להיכנס והלשונית אישור כניסה נשארת סגורה. ללא SSL, ייבוא לקוחות ובדיקת החיבור פועלים רק כאשר Klacks רץ ישירות על Windows; ב-Docker (Linux) Active Directory דורש LDAPS לכל פעולה.

  • מארח: השם המלא (FQDN) בדיוק כפי שהוא מופיע באישור של בקר התחום, למשל dc01.example.local. כתובת IP אינה עובדת, מכיוון שבדיקת האישור משווה את השם.
  • אמון ב-CA: המחשב שמריץ את Klacks חייב לתת אמון ברשות האישורים שהנפיקה את אישור בקר התחום. Windows: יש לייבא את אישור ה-CA למאגר רשויות אישורי שורש מהימנות (Trusted Root Certification Authorities) של המחשב, למשל certutil -addstore Root ca.cer (כמנהל).
  • פענוח שמות: אם לא ניתן לפענח את ה-FQDN דרך DNS, יש להוסיף רשומה בקובץ hosts (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: יש לטעון (mount) את אישור ה-CA כקובץ PEM לתוך מכולת ה-API, להגדיר את משתנה הסביבה LDAPTLS_CACERT לנתיב שלו, ולהוסיף את ה-FQDN באמצעות extra_hosts אם DNS אינו מפענח אותו. אם בקר התחום אינו שולח אישור CA (אישור בחתימה עצמית), האישור שלו עצמו כקובץ PEM משמש כעוגן אמון. ללא אישור מהימן החיבור נדחה ומדווח כשגיאת חיבור.
  • חשבון החיבור (Bind): יש להזין אותו כשם עיקרי של משתמש (UPN), למשל svc-klacks@example.local.

אילו חשבונות מיובאים

  • חשבונות מושבתים וחשבונות מערכת של Active Directory לעולם אינם מיובאים ואינם מוצגים ברשימה.
  • יש להוציא חשבונות שירות באמצעות מסנן המשתמשים, למשל רק חברים בקבוצה אחת: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

טיפים

שימוש ב-Synology NAS כשרת LDAP

ניתן להשתמש ב-Synology NAS כשרת LDAP. במקרה זה, יש להתקין את חבילת "שרת LDAP" או מכולת Docker עם OpenLDAP.

  • סוג ספק: "LDAP" (לא "Active Directory")
  • מסנן משתמשים: (objectClass=inetOrgPerson)
  • משתמשים נכנסים עם uid או עם כתובת האימייל שלהם
  • מומלץ להעדיף LDAPS (פורט 636)

בדיקת חיבור

השתמש בכפתור "בדוק חיבור" כדי לאמת את ההגדרות. הוא מציג את מספר החשבונות הפעילים שמסנן המשתמשים מוצא (חשבונות מושבתים וחשבונות מערכת אינם נספרים) ומספר שמות משתמשים לדוגמה. סימן "+" אחרי המספר פירושו ששרת הספרייה עצר במגבלת התוצאות שלו, ולכן יש עוד חשבונות.
