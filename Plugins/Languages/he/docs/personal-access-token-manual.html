מדריך Personal Access Tokens

מהם Personal Access Tokens?

Personal Access Tokens (PATs) הם מפתחות API ארוכי טווח, המאפשרים לכלים ולשירותים חיצוניים גישה מאובטחת ל-Klacks — ללא שם משתמש וסיסמה.

מקרי שימוש נפוצים:

  • MCP (Model Context Protocol) — מאפשר לעוזרי AI כמו Claude Desktop גישה ישירה ליכולות (Skills) של Klacksy
  • סקריפטים לאוטומציה וצינורות CI/CD
  • כלי ניטור ואינטגרציה חיצוניים

עקרון האבטחה

Klacks לעולם אינו שומר את האסימון בטקסט גלוי. לאחר היצירה נשמר במסד הנתונים אך ורק ערך גיבוב (Hash) מסוג SHA-256 של האסימון. האסימון עצמו מוצג פעם אחת בלבד, מיד לאחר היצירה, ולא ניתן לשלוף אותו לאחר מכן.

הערה: רשמו או העתיקו את האסימון מיד לאחר יצירתו. במקרה של אובדן יש ליצור אסימון חדש ולבטל את הישן.

יצירת אסימון

שלב אחר שלב

  • נווטו אל תצורה ← Personal Access Tokens
  • לחצו על יצירת אסימון חדש
  • הזינו שם ברור ומתאר (לדוגמה Claude Desktop או CI-Pipeline)
  • בחרו את משך התוקף הרצוי (1–730 ימים, ברירת מחדל: 365 ימים)
  • לחצו על יצירה
  • העתיקו את האסימון המוצג מיד — הוא מוצג פעם אחת בלבד

פורמט האסימון

klacks_pat_<רצף תווים אקראי>

כל אסימון מתחיל בקידומת klacks_pat_ ולאחריה רצף תווים אקראי מאובטח קריפטוגרפית.

משך התוקף

משךשימוש מומלץ
1–30 ימיםבדיקות ופיתוח לטווח קצר
90–180 ימיםצינורות CI/CD עם רוטציה סדירה
365 ימים (ברירת מחדל)אינטגרציות קבועות (לדוגמה Claude Desktop)
730 ימיםאינטגרציות מערכת לטווח ארוך

שימוש באסימון

אסימון Bearer בכותרת HTTP

האסימון מועבר כאסימון Bearer בכותרת Authorization של כל בקשת API:

Authorization: Bearer klacks_pat_...

הגדרת MCP עם Claude Desktop

נקודת הקצה של MCP (/mcp) מאפשרת לעוזרי AI כמו Claude Desktop גישה ישירה לכל יכולות (Skills) של Klacksy — שאילתת נתוני עובדים, תכנון משמרות, ניהול קבוצות ועוד רבים.

תצורה באפליקציית Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<הדומיין-של-klacks-שלכם>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

החליפו את <הדומיין-של-klacks-שלכם> בכתובת ההתקנה שלכם ב-Klacks ואת klacks_pat_... באסימון שיצרתם.

בקשת API ישירה (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<הדומיין-של-klacks-שלכם>/api/clients

ניהול ואבטחה

סקירת האסימונים

תחת תצורה ← Personal Access Tokens תוכלו לראות את כל האסימונים שלכם עם שם, תאריך יצירה, תאריך תפוגה ותאריך שימוש אחרון. האסימון בטקסט גלוי לעולם אינו מוצג בתצוגה זו.

ביטול אסימון

ניתן לבטל אסימון בכל עת. לאחר הביטול, כל הבקשות עם אסימון זה יידחו מיידית. בטלו אסימונים מיד כאשר:

  • האסימון נחשף בשוגג
  • מכשיר או שירות אינם בשימוש עוד
  • אתם מבחינים בפעילות חשודה

תפוגה

אסימונים שפג תוקפם נדחים אוטומטית. Klacks מציג בתצוגה הכללית אסימונים שיפוג תוקפם ב-30 הימים הקרובים, כדי שתוכלו ליצור אסימונים חדשים בזמן.

עצות אבטחה

  • השתמשו באסימון נפרד עבור כל שירות או כלי
  • בחרו שמות ברורים ומתארים, כדי שניתן יהיה לשייך אסימונים בבירור
  • לעולם אל תשמרו אסימונים בטקסט גלוי במערכות בקרת גרסאות
  • בצעו רוטציה סדירה של אסימונים, במיוחד בשימוש עם CI/CD
  • בטלו אסימונים מיד בעת חשד לשימוש לרעה

כל אסימון קשור לחשבון המשתמש שלכם ובעל אותן הרשאות כמו החשבון שלכם. התייחסו לאסימונים באותה זהירות כמו לסיסמה שלכם.
