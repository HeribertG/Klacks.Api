Trening Klacksy - instrukcja

Czym jest narzędzie treningowe?

Narzędzie treningowe steruje nawigacją wewnątrz strony chatbota Klacksy. Gdy użytkownik powie lub napisze „Klacksy pokaż mi adresy", Klacksy nawiguje do odpowiedniej strony i przewija do właściwej sekcji.

Aby to działało, Klacksy potrzebuje dla każdego kotwicznego punktu na stronie listy synonimów w każdym języku (np. „adresy", „klienci", „kontakty" dla celu addresses).

Karta „Cele"

Lista wszystkich znalezionych w frontendzie punktów kotwicznych (atrybuty HTML data-klacksy-target). Filtr statusu:

  • pending: punkt kotwiczny istnieje, ale jeszcze bez synonimów
  • generated: synonimy zostały wygenerowane automatycznie, wymagają sprawdzenia
  • reviewed: synonimy zatwierdzone przez administratora
  • needs-review: oznaczone do ponownego sprawdzenia

Kliknięcie celu otwiera edytor synonimów poniżej. Tam można synonimy dodawać, usuwać i zatwierdzać przyciskiem „Zapisz jako sprawdzone".

Karta „Informacje zwrotne"

Pokazuje wpisy użytkowników, których Klacksy nie potrafił przypisać (nie znaleziono pasującego synonimu). Na podstawie tej listy można rozpoznać, jakich synonimów jeszcze brakuje.

Karta „Metryki"

Przegląd wszystkich celów według statusu. Pomaga śledzić postęp treningu.

Potok kompilacji (CLI)

Gdy szablony otrzymały nowe punkty kotwiczne data-klacksy-target, trzeba zregenerować manifest i wstępne synonimy. Poniższe polecenia uruchamiają się też automatycznie w CI i w Husky pre-commit: 

cd C:\SourceCode\Klacks.Ui

# 1. Skanuj szablony → navigation-targets.json ze wszystkimi kotwicami
npm run scan:targets

# 2a. Generuj wstępne synonimy (wszystkie 4 podstawowe + 22 języki wtyczek, ~2,5 h)
npm run generate:synonyms

# 2b. Tylko podstawowe języki (de/en/fr/it) — szybko, ok. 9 min
npm run generate:synonyms -- --core-only

# 2c. Uzupełnij tylko brakujące języki wtyczek — ok. 45 min
npm run generate:synonyms -- --plugins-only

# 3. Sprawdź spójność wake-word
npm run wake-word-lint

Ważne: przy npm run musi wystąpić --, aby opcje zostały przekazane do skryptu. Bez -- npm połyka flagę i skrypt działa w trybie standardowym.

Alternatywa bez npm: npx tsx tools/generate-synonyms.ts --core-only.

Klucz API

Klucz API LLM jest wyszukiwany w tej kolejności:

  1. Zmienna środowiskowa SYNONYM_LLM_API_KEY
  2. Tabela bazy danych llm_providers (dostawca deepseek, is_enabled = true) — automatycznie przez wywołanie psql
  3. W przeciwnym razie komunikat o błędzie

Domyślnym dostawcą jest DeepSeek. Inny dostawca przez SYNONYM_LLM_PROVIDER_ID=anthropic (lub inny skonfigurowany dostawca LLM w ustawieniach).

Krok 1 - scan:targets

Przeszukuje wszystkie szablony Angular pod kątem atrybutów data-klacksy-target i tworzy manifest Application/Skills/Definitions/navigation-targets.json. Każdy nowy punkt kotwiczny pojawia się następnie na karcie „Cele" ze statusem pending.

Krok 2 - generate:synonyms

Tworzy dla każdego nowego punktu kotwicznego wstępne synonimy na podstawie data-klacksy-label-key i kategorii. Status następnie: generated (musi zostać sprawdzony przez administratora).

Skrypt zapisuje punkty kontrolne manifestu co 5 celów, dzięki czemu przerwanie nie powoduje utraty już wygenerowanych danych.

Krok 3 - wake-word-lint

Sprawdza spójność wariantu wake-word (Cześć Klacksy / Hej Klacksy / ...) we wszystkich językach. Zapobiega temu, aby synonimy nadpisywały wake-word.

Tryb głosowy

Ikona mikrofonu w czacie aktywuje tryb głosowy. Gdy jest aktywny:

  • Mikrofon nasłuchuje, ciągle transkrybuje
  • Przy krótkiej ciszy → automatyczne wysłanie dotychczasowej transkrypcji

Ważne: jak tylko zaczniesz pisać w polu tekstowym, tryb głosowy zostaje automatycznie zakończony — w przeciwnym razie mikrofon nadpisywałby Twój wpisany tekst własnymi transkrypcjami i wysyłał go przedwcześnie.

Typowy cykl treningowy

  1. Dodaj punkt kotwiczny w szablonie: 
    <div data-klacksy-target="addresses"
     data-klacksy-label-key="nav.addresses"
     data-klacksy-route="/workplace/client">
  2. npm run scan:targets && npm run generate:synonyms
  3. Uruchom ponownie API (pamięć podręczna jest wczytywana ponownie przy starcie)
  4. Otwórz kartę „Cele" → nowe cele pojawiają się ze statusem generated
  5. Sprawdź/uzupełnij synonimy → „Zapisz jako sprawdzone" → status reviewed
  6. Przetestuj z Klacksy, np. „Klacksy pokaż mi adresy"
  7. Jeśli Klacksy nie dopasuje → karta „Informacje zwrotne" → uzupełnij brakujący synonim
  8. Monitoruj kartę „Metryki", aż wszystko będzie reviewed
