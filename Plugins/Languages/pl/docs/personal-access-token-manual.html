Instrukcja Personal Access Tokens

Czym są Personal Access Tokens?

Personal Access Tokens (PAT) to długotrwałe klucze API, które umożliwiają zewnętrznym narzędziom i usługom bezpieczny dostęp do Klacks — bez nazwy użytkownika i hasła.

Typowe zastosowania:

  • MCP (Model Context Protocol) — umożliwia asystentom AI, takim jak Claude Desktop, bezpośredni dostęp do umiejętności Klacksy
  • Skrypty automatyzacji i potoki CI/CD
  • Zewnętrzne narzędzia monitoringu i integracji

Koncepcja bezpieczeństwa

Klacks nigdy nie zapisuje tokenu w postaci jawnej. Po utworzeniu w bazie danych zapisywany jest wyłącznie hash SHA-256 tokenu. Sam token jest wyświetlany tylko jeden raz, bezpośrednio po utworzeniu, i później nie można go już odczytać.

Uwaga: zapisz lub skopiuj token natychmiast po utworzeniu. W razie utraty trzeba utworzyć nowy token, a stary unieważnić.

Tworzenie tokenu

Krok po kroku

  • Przejdź do Konfiguracja → Personal Access Tokens
  • Kliknij Utwórz nowy token
  • Nadaj czytelną nazwę (np. Claude Desktop lub CI-Pipeline)
  • Wybierz żądany okres ważności (1–730 dni, domyślnie: 365 dni)
  • Kliknij Utwórz
  • Skopiuj wyświetlony token natychmiast — jest pokazywany tylko raz

Format tokenu

klacks_pat_<losowy ciąg znaków>

Każdy token zaczyna się od prefiksu klacks_pat_, po którym następuje kryptograficznie bezpieczny losowy ciąg znaków.

Okres ważności

Czas trwaniaZalecane zastosowanie
1–30 dniKrótkoterminowe testy i rozwój
90–180 dniPotoki CI/CD z regularną rotacją
365 dni (domyślnie)Trwałe integracje (np. Claude Desktop)
730 dniDługoterminowe integracje systemowe

Używanie tokenu

Token Bearer w nagłówku HTTP

Token jest przesyłany jako token Bearer w nagłówku Authorization każdego zapytania API:

Authorization: Bearer klacks_pat_...

Konfiguracja MCP z Claude Desktop

Punkt końcowy MCP (/mcp) umożliwia asystentom AI, takim jak Claude Desktop, bezpośredni dostęp do wszystkich umiejętności Klacksy — odpytywanie danych pracowników, planowanie zmian, zarządzanie grupami i wiele więcej.

Konfiguracja w aplikacji Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<twoja-domena-klacks>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

Zastąp <twoja-domena-klacks> adresem Twojej instalacji Klacks oraz klacks_pat_... utworzonym przez siebie tokenem.

Bezpośrednie zapytanie API (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<twoja-domena-klacks>/api/clients

Zarządzanie i bezpieczeństwo

Przegląd tokenów

W Konfiguracja → Personal Access Tokens widzisz wszystkie swoje tokeny z nazwą, datą utworzenia, datą wygaśnięcia i ostatnim użyciem. Token w postaci jawnej nigdy nie jest wyświetlany w tym widoku.

Unieważnianie tokenu

Token można w każdej chwili unieważnić. Po unieważnieniu wszystkie zapytania z tym tokenem są natychmiast odrzucane. Unieważnij tokeny natychmiast, gdy:

  • Token został przypadkowo przekazany dalej
  • Urządzenie lub usługa nie są już używane
  • Zauważysz podejrzaną aktywność

Wygaśnięcie

Wygasłe tokeny są automatycznie odrzucane. Klacks pokazuje w przeglądzie tokeny, które wygasną w ciągu najbliższych 30 dni, abyś mógł na czas utworzyć nowe tokeny.

Wskazówki bezpieczeństwa

  • Używaj osobnego tokenu dla każdej usługi lub narzędzia
  • Wybieraj czytelne nazwy, aby móc jednoznacznie przypisać tokeny
  • Nigdy nie przechowuj tokenów w postaci jawnej w systemach kontroli wersji
  • Regularnie rotuj tokeny, zwłaszcza przy zastosowaniu w CI/CD
  • Natychmiast unieważniaj tokeny w przypadku podejrzenia nadużycia

Każdy token jest powiązany z Twoim kontem użytkownika i ma takie same uprawnienia jak Twoje konto. Traktuj tokeny z taką samą starannością jak swoje hasło.
