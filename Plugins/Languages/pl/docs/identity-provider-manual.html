Podręcznik dostawcy tożsamości

Wprowadzenie

Dostawcy tożsamości umożliwiają uwierzytelnianie użytkowników za pośrednictwem zewnętrznych usług katalogowych, takich jak LDAP, Active Directory lub OAuth2/OpenID Connect.

Obsługiwane typy dostawców:

  • LDAP - Lightweight Directory Access Protocol
  • Active Directory - Microsoft Active Directory
  • OAuth2 - Framework autoryzacji OAuth 2.0
  • OpenID Connect - Warstwa tożsamości na bazie OAuth 2.0

Import klientów

Gdy opcja "Użyj do importu klientów" jest aktywowana, importowane są następujące dane:

  • Nazwisko - sn (nazwisko) lub displayName
  • Imię - givenName
  • Tytuł - title (tytuł zawodowy)
  • Firma - company
  • Adres - street/streetAddress, postalCode, l (miasto), st (województwo), c (kraj)
  • Płeć - Na podstawie personalTitle (Pan/Pani) w Active Directory

Uwaga: W OpenLDAP płeć jest domyślnie ustawiona na "Neutralna" i może być ręcznie skorygowana.

Logowanie przez katalog

Gdy opcja "Użyj do uwierzytelniania" jest włączona i zapisana, użytkownicy mogą logować się do Klacks hasłem z katalogu. Nikt nie otrzymuje dostępu automatycznie: administrator zatwierdza każdą osobę na karcie Zatwierdzenie logowania.

  • Karta wyświetla konta z katalogu (maksymalnie 1000; użyj wyszukiwania, aby zawęzić listę).
  • Zaznaczenie konta tworzy nowe konto Klacks bez roli i bez hasła. Istniejące konta Klacks nigdy nie są przejmowane: jeśli adres e-mail jest już używany przez konto Klacks, wiersza nie można zaznaczyć. Najpierw usuń to konto lub zmień jego adres e-mail w administracji użytkownikami.
  • Odznaczenie dezaktywuje konto Klacks; ponowne zaznaczenie aktywuje je ponownie, o ile konto nie ma roli. Zdezaktywowane konto, które nadal ma role, jest ponownie aktywowane w administracji użytkownikami.
  • Odejście z firmy: gdy ktoś odchodzi, odznacz go również w Klacks. Wyłączenie konta w katalogu blokuje nowe logowania, ale już trwające sesje działają dalej do czasu ich wygaśnięcia.
  • Konta bez adresu e-mail w katalogu nie można zatwierdzić.
  • Własnego konta nie można zmienić na tej karcie.
  • Osoba z poprawnymi danymi logowania do katalogu, ale bez zatwierdzenia, otrzymuje komunikat, że konto nie zostało zatwierdzone i że należy skontaktować się z administratorem.

Nazwy logowania

TypAkceptowane nazwy logowania
Active DirectorysAMAccountName, userPrincipalName lub adres e-mail
LDAPuid lub adres e-mail

Klacks wyszukuje osobę za pomocą użytkownika bind, a następnie sprawdza hasło w katalogu, dlatego nazwa logowania nie musi być zgodna z adresem e-mail.

Szyfrowanie

Zwykły LDAP na porcie 389 wysyła hasła bez szyfrowania; formularz wyświetla ostrzeżenie dla dostawcy LDAP bez SSL. Używaj LDAPS ("Użyj SSL", port 636) zawsze, gdy katalog jest używany do logowania.

Active Directory: logowanie wyłącznie przez LDAPS

Klacks loguje osoby do Active Directory wyłącznie przez LDAPS (port 636). Bez SSL formularz wyświetla ostrzeżenie, nikt nie może się zalogować, a karta zatwierdzania logowania pozostaje zamknięta. Bez SSL import klientów i test połączenia działają tylko wtedy, gdy Klacks działa bezpośrednio w systemie Windows; w Docker (Linux) Active Directory wymaga LDAPS dla wszystkich funkcji.

  • Host: pełna nazwa kwalifikowana (FQDN) dokładnie taka, jak w certyfikacie kontrolera domeny, np. dc01.example.local. Adres IP nie działa, ponieważ weryfikacja certyfikatu porównuje nazwę.
  • Zaufanie do CA: komputer, na którym działa Klacks, musi ufać urzędowi certyfikacji, który wystawił certyfikat kontrolera domeny. Windows: zaimportuj certyfikat CA do magazynu komputera Zaufane główne urzędy certyfikacji, np. certutil -addstore Root ca.cer (jako administrator).
  • Rozpoznawanie nazw: jeśli FQDN nie może zostać rozpoznany przez DNS, dodaj wpis w pliku hosts (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: zamontuj certyfikat CA jako plik PEM w kontenerze API, ustaw zmienną środowiskową LDAPTLS_CACERT na jego ścieżkę i dodaj FQDN przez extra_hosts, jeśli DNS go nie rozpoznaje. Jeśli kontroler domeny nie wysyła certyfikatu CA (certyfikat z podpisem własnym), jako punkt zaufania działa jego własny certyfikat w postaci pliku PEM. Bez zaufanego certyfikatu połączenie jest odrzucane i zgłaszane jako błąd połączenia.
  • Konto bind: wpisz je jako user principal name (UPN), np. svc-klacks@example.local.

Które konta są importowane

  • Wyłączone konta i konta systemowe Active Directory nigdy nie są importowane ani wyświetlane.
  • Wyklucz konta usługowe za pomocą filtra użytkowników, np. tylko członkowie jednej grupy: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Wskazówki

Synology NAS jako serwer LDAP

Synology NAS może być używany jako serwer LDAP. W tym celu należy zainstalować pakiet "LDAP Server" lub kontener Docker z OpenLDAP.

  • Typ dostawcy: "LDAP" (nie "Active Directory")
  • Filtr użytkowników: (objectClass=inetOrgPerson)
  • Użytkownicy logują się za pomocą uid lub adresu e-mail
  • Preferuj LDAPS (port 636)

Testowanie połączenia

Użyj przycisku "Testuj połączenie", aby zweryfikować konfigurację. Wyświetla on liczbę aktywnych kont znalezionych przez filtr użytkowników (konta wyłączone i systemowe nie są liczone) oraz kilka przykładowych nazw użytkowników. Znak "+" po liczbie oznacza, że serwer katalogowy zatrzymał się na swoim limicie wyników, więc kont jest więcej.
