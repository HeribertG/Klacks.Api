Import zamówień ERP – instrukcja

Czym jest import zamówień ERP?

Zewnętrzne systemy ERP dostarczają zamówienia do Klacks jako pliki XML. Do przesyłania są trzy sposoby:

  • Punkt odbioru (Drop-Point, odbiór): ERP umieszcza pliki w magazynie plików punktu odbioru – w zależności od instalacji jest to katalog na serwerze Klacks (standard) lub magazyn obiektowy kompatybilny z S3. Klacks automatycznie pobiera pliki zgodnie ze skonfigurowanym harmonogramem.
  • Bezpośrednie przesyłanie (Push): ERP wysyła plik przez HTTP POST do /api/erp-import/upload i uwierzytelnia się przy tym tokenem importu ERP jako tokenem Bearer. Na plik dozwolone jest maksymalnie 50 MB.
  • Ręczne przesyłanie: administratorzy przeciągają pliki XML bezpośrednio na tej stronie do strefy przesyłania (lub klikają w strefę, aby wybrać plik). Po przesłaniu import zostaje uruchomiony automatycznie i rozpoczyna się w ciągu minuty; przycisk Importuj teraz uruchamia go dodatkowo w dowolnym momencie.

Punkt odbioru

Punkt odbioru to centralna skrzynka na wszystkie pliki importu. Klacks zarządza nim automatycznie – nikt nie musi go tworzyć ani konfigurować. Strona pokazuje jego zawartość jako widok plików z trzema obszarami: Przychodzące (czeka na kolejny przebieg importu), Przetworzone (archiwum) i Błąd (pliki nieczytelne lub nieprawidłowe wraz z powodem błędu). Pliki błędów można za pomocą przycisku Importuj ponownie przenieść z powrotem do przychodzących.

  • Przełącznik aktywności (Import aktywny) – wstrzymuje automatyczny import; już umieszczone pliki pozostają zachowane.
  • Wskaźnik statusu – ostatni czas pobierania i, jeśli istnieje, ostatni błąd.

Tokeny dostępu

  • Do przesyłania Push administratorzy mogą tworzyć tokeny dostępu — potrzebne tylko wtedy, gdy zewnętrzny system ERP dostarcza pliki przez HTTPS. Każdy token zaczyna się prefiksem klacks_erp_.
  • Okres ważności można wybrać (od 1 do 730 dni, domyślnie 365 dni).
  • Token w postaci jawnej jest wyświetlany tylko raz podczas tworzenia. Później nie można go już odczytać – skopiuj go natychmiast i przechowuj bezpiecznie.
  • Token importu ERP jest celowo ważny tylko dla punktu końcowego importu. Jeśli token trafi w niepowołane ręce u dostawcy usług ERP, nie daje to żadnego innego dostępu API do Klacks.
  • Tokeny można w każdej chwili unieważnić; dostęp kończy się natychmiast.

Harmonogram

Pobieranie z punktu odbioru odbywa się według wyrażenia cron (domyślnie 0 * * * * = co godzinę) w wybranej strefie czasowej. Obie te wartości są konfigurowane na tej stronie. Nieprawidłowe wyrażenie cron zatrzymałoby import – dlatego wpis jest walidowany, a nieprawidłowe wartości nie są zapisywane.

Format XML (dokumentacja referencyjna)

Elementem głównym jest ErpOrderImport z obowiązkowymi atrybutami schemaVersion (aktualnie 1) i sourceSystemId. sourceSystemId identyfikuje dostarczający system w plikach i zapewnia stabilne przypisanie klienta przez wszystkie dostawy – musi pozostać trwale stały dla danego systemu źródłowego. Każde zamówienie znajduje się we własnym elemencie <Order>. Plik może zawierać dowolną liczbę zamówień.

Element Obowiązkowy Format Znaczenie
ExternalOrderReference Tak Tekst Unikalna referencja zamówienia systemu ERP.
Description Nie Tekst Dowolny tekst do zamówienia (np. wskazówki dotyczące przypisania); jest wyświetlany na zamówieniu.
Customer Tak Element Dane klienta zamówienia (patrz podelementy).
Customer/ExternalCustomerReference Nie (zalecane) Tekst Zewnętrzna referencja klienta; zapewnia stabilne przypisanie klienta przez wszystkie importy.
Customer/Company Tak Tekst Nazwa firmy klienta.
Customer/Address/Street Tak Tekst Ulica i numer domu.
Customer/Address/Zip Tak Tekst Kod pocztowy.
Customer/Address/City, Customer/Address/State, Customer/Address/Country Nie Tekst Miejscowość, kanton/region i kraj.
FromDate Tak yyyy-MM-dd Początek zamówienia.
UntilDate Nie yyyy-MM-dd Koniec zamówienia; brak lub puste = bezterminowo.
StartTime, EndTime Tak HH:mm Czas początku i końca przypisania.
IsTimeRange Nie true/false (domyślnie false) true = okno czasowe, w którym się pracuje; false = stała zmiana od StartTime do EndTime. Przy true wymagane jest Duration.
Duration Przy IsTimeRange=true Element z <Hours> i <Minutes> (liczby całkowite) Czas trwania pojedynczego przypisania, np. 0 h 20 min dla 20-minutowego przypisania w oknie czasowym 08:00–15:00. Przy stałej zmianie opcjonalne; jeśli elementu brakuje, obowiązuje czas trwania od StartTime do EndTime.
Quantity Nie Liczba całkowita (domyślnie 1) Liczba przypisań.
SumEmployees Nie Liczba całkowita (domyślnie 1) Liczba wymaganych pracowników.
Weekdays Tak Atrybuty monday … sunday, każdy true/false Dni tygodnia zamówienia; co najmniej jeden dzień tygodnia musi być true, brakujący atrybut liczy się jako false. Zamówienia bez dnia tygodnia są odrzucane.

Uwaga: nazwy elementów rozróżniają wielkość liter. Kompletny plik przykładowy można pobrać przyciskiem Pobierz plik przykładowy powyżej tej instrukcji.

Przypisanie klienta

Klacks przypisuje każde zamówienie do klienta:

  • Najpierw przez kombinację ID systemu źródłowego i zewnętrznej referencji klienta – raz przypisana referencja pozostaje trwale przypisana do tego samego klienta.
  • Bez zewnętrznej referencji przy pierwszym wystąpieniu wyszukiwanie odbywa się przez firmę + kod pocztowy + ulicę; wielkość liter i spacje są przy tym ignorowane.
  • Jeśli nie znaleziono dopasowania, Klacks automatycznie tworzy nowego klienta.

Przetwarzanie i cykl życia

  • Zaimportowane zamówienia powstają jako szkic i muszą zostać sprawdzone i zapieczętowane przez planistów lub administratorów. Przy tym planista uzupełnia również ewentualne wymagania kwalifikacyjne — ERP może je dostarczyć jako wskazówkę w polu Description.
  • Jeśli ERP dostarczy później zmienioną wersję już zapieczętowanego zamówienia, Klacks automatycznie zamyka stare zamówienie datą końcową i tworzy nową, powiązaną wersję szkicu. Już zaplanowane przyszłe, niezablokowane przypisania starego zamówienia zostają usunięte, a planiści powiadomieni.
  • Niezmienione powtarzające się dostawy (np. nocny pełny eksport) nie wywołują żadnej akcji.

Obsługa błędów i archiwum

  • Przetworzone pliki są przenoszone w magazynie plików do podfolderu processed/ (archiwum, bez usuwania); pojawiają się na stronie importu w obszarze Przetworzone.
  • Nieczytelne lub nieprawidłowe pliki trafiają do podfolderu error/ i pojawiają się w obszarze Błąd; stamtąd można je za pomocą przycisku Importuj ponownie przenieść z powrotem do przychodzących.
  • Niekompletne lub nieprawidłowe zamówienia są odrzucane (np. bez dnia tygodnia, z UntilDate przed FromDate lub z podwójnym ExternalOrderReference w tym samym pliku); pozostałe zamówienia z tego samego pliku są mimo to importowane.
  • Jeśli plik zawiera co najmniej jedno odrzucone zamówienie, trafia on wraz z powodem odrzucenia do obszaru Błąd — już zaimportowane zamówienia pozostają przy tym zachowane.
  • Błędy są rejestrowane, a administratorzy są powiadamiani.
