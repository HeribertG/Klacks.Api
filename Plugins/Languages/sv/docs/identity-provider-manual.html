Handbok för identitetsleverantör

Inledning

Identitetsleverantörer möjliggör autentisering av användare via externa katalogtjänster som LDAP, Active Directory eller OAuth2/OpenID Connect.

Stödda leverantörstyper:

  • LDAP - Lightweight Directory Access Protocol
  • Active Directory - Microsoft Active Directory
  • OAuth2 - OAuth 2.0-auktoriseringsramverk
  • OpenID Connect - Identitetslager ovanpå OAuth 2.0

Kundimport

När "Använd för kundimport" är aktiverat importeras följande data:

  • Efternamn - sn (efternamn) eller displayName
  • Förnamn - givenName
  • Titel - title (jobbtitel)
  • Företag - company
  • Adress - street/streetAddress, postalCode, l (stad), st (län), c (land)
  • Kön - Från personalTitle (Herr/Fru) i Active Directory

Obs: I OpenLDAP är könet som standard "Neutralt" och kan korrigeras manuellt.

Inloggning via katalogen

När "Använd för autentisering" är aktiverat och sparat kan personer logga in i Klacks med sitt lösenord i katalogen. Ingen får åtkomst automatiskt: administratören godkänner varje person på fliken Godkännande av inloggning.

  • Fliken listar katalogens konton (högst 1000; använd sökningen för att begränsa listan).
  • Genom att kryssa i ett konto skapas ett nytt Klacks-konto utan roll och utan lösenord. Befintliga Klacks-konton tas aldrig över: om e-postadressen redan används av ett Klacks-konto går raden inte att kryssa i. Ta först bort det kontot eller ändra dess e-postadress i användaradministrationen.
  • Om kryssningen tas bort inaktiveras Klacks-kontot; kryssas det i igen aktiveras det på nytt, så länge det inte har någon roll. Ett inaktiverat konto som fortfarande har roller aktiveras på nytt i användaradministrationen.
  • Avslutad anställning: när någon slutar, ta bort kryssningen i Klacks också. Att inaktivera kontot i katalogen blockerar nya inloggningar, men sessioner som redan pågår fortsätter tills de går ut.
  • Ett konto utan e-postadress i katalogen kan inte godkännas.
  • Ditt eget konto kan inte ändras på den här fliken.
  • En person med korrekta inloggningsuppgifter i katalogen men utan godkännande får meddelandet att kontot inte är godkänt och att personen ska kontakta administratören.

Kryptering

Vanlig LDAP på port 389 skickar lösenord okrypterade; formuläret visar en varning för en LDAP-leverantör utan SSL. Använd LDAPS ("Använd SSL", port 636) så snart katalogen används för inloggning.

Active Directory: inloggning endast via LDAPS

Klacks loggar in personer i Active Directory endast via LDAPS (port 636). Utan SSL visar formuläret en varning, ingen kan logga in och fliken för godkännande av inloggning förblir stängd. Utan SSL fungerar klientimport och anslutningstest bara när Klacks körs direkt på Windows; i Docker (Linux) kräver Active Directory LDAPS för allt.

  • Värd: det fullständiga namnet (FQDN) exakt som det står i domänkontrollantens certifikat, t.ex. dc01.example.local. En IP-adress fungerar inte, eftersom certifikatkontrollen jämför namnet.
  • Lita på CA:n: datorn som kör Klacks måste lita på den certifikatutfärdare som utfärdade domänkontrollantens certifikat. Windows: importera CA-certifikatet till datorns lager Trusted Root Certification Authorities, t.ex. certutil -addstore Root ca.cer (som administratör).
  • Namnuppslagning: om FQDN inte kan matchas via DNS, lägg till en post i hosts-filen (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker: montera CA-certifikatet som PEM-fil i API-containern, sätt miljövariabeln LDAPTLS_CACERT till dess sökväg och lägg till FQDN med extra_hosts om DNS inte löser upp det. Om domänkontrollanten inte skickar något CA-certifikat (självsignerat certifikat) fungerar dess eget certifikat som PEM-fil som förtroendeankare. Utan ett betrott certifikat nekas anslutningen och rapporteras som anslutningsfel.
  • Bind-konto: ange det som användarens huvudnamn (UPN), t.ex. svc-klacks@example.local.

Vilka konton importeras

  • Inaktiverade konton och systemkonton i Active Directory importeras och listas aldrig.
  • Uteslut tjänstekonton med användarfiltret, t.ex. bara medlemmar i en grupp: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Tips

Synology NAS som LDAP-server

En Synology NAS kan användas som LDAP-server. För detta måste paketet "LDAP Server" eller en Docker-container med OpenLDAP installeras.

  • Leverantörstyp: "LDAP" (inte "Active Directory")
  • Användarfilter: (objectClass=inetOrgPerson)
  • Användare loggar in med sitt uid eller sin e-postadress
  • Föredra LDAPS (port 636)

Testa anslutningen

Använd knappen "Testa anslutning" för att verifiera konfigurationen. Den visar antalet aktiva konton som användarfiltret hittar (inaktiverade konton och systemkonton räknas inte) och några exempelanvändarnamn. Ett "+" efter antalet betyder att katalogservern stannade vid sin resultatgräns, så det finns fler konton.
