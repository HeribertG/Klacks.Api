Handbok för Personal Access Tokens

Vad är Personal Access Tokens?

Personal Access Tokens (PAT) är långlivade API-nycklar som ger externa verktyg och tjänster säker åtkomst till Klacks — utan användarnamn och lösenord.

Typiska användningsfall:

  • MCP (Model Context Protocol) — låter AI-assistenter som Claude Desktop få direkt åtkomst till Klacksy-skills
  • AI-agenter och assistenter som arbetar med Klacks via MCP

Säkerhetskoncept

Klacks lagrar aldrig token i klartext. Efter skapandet sparas endast en SHA-256-hash av token i databasen. Själva token visas endast en enda gång direkt efter skapandet och kan därefter inte hämtas igen.

Obs: Notera eller kopiera token direkt efter skapandet. Vid förlust måste en ny token skapas och den gamla återkallas.

Skapa token

Steg för steg

  • Navigera till Konfiguration → Personal Access Tokens
  • Klicka på Skapa nytt token
  • Ange ett tydligt namn (t.ex. Claude Desktop eller AI-agent schemaläggning)
  • Välj önskad giltighetstid (1–730 dagar, standard: 365 dagar)
  • Klicka på Skapa
  • Kopiera det visade token genast — det visas endast en gång

Token-format

klacks_pat_<slumpmässig teckensträng>

Varje token börjar med prefixet klacks_pat_ följt av en kryptografiskt säker slumpmässig teckensträng.

Giltighetstid

VaraktighetRekommenderad användning
1–30 dagarKortsiktiga tester och utveckling
90–180 dagarAI-agenter med regelbunden rotation
365 dagar (standard)Permanenta integrationer (t.ex. Claude Desktop)
730 dagarLångsiktiga systemintegrationer

Åtkomstläge

När du skapar token bestämmer du vad en extern agent får göra med den:

  • Endast läsning (standard) — agenten ser och använder enbart läsande verktyg. Varje försök att ändra data avvisas.
  • Läsning och skrivning — agenten kan dessutom ändra data utan att en person godkänner varje enskild ändring. Välj bara detta läge för agenter som du anförtror ändringar.

Läget visas i tokenöversikten och kan inte ändras i efterhand; skapa vid behov en ny token. Befintliga tokens och tokens som utfärdats via en OAuth-inloggning (t.ex. en MCP-koppling) har läget ”Läsning och skrivning”.

Använda token

Bearer-token i HTTP-headern

Token skickas som bearer-token i Authorization-headern i varje MCP-anrop till endpointen /mcp:

Authorization: Bearer klacks_pat_...

Konfigurera MCP med Claude Desktop

MCP-endpointen (/mcp) ger AI-assistenter som Claude Desktop direkt åtkomst till alla Klacksy-skills — hämta medarbetardata, planera skift, hantera grupper med mera.

Konfiguration i appen Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<din-klacks-domän>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Ersätt <din-klacks-domän> med adressen till din Klacks-installation och klacks_pat_... med ditt skapade token.

Observera: Token fungerar bara för AI-agenters MCP-åtkomst (endpoint /mcp). Klacks REST-API (t.ex. /api/clients) accepterar dem inte; det kräver inloggningstoken.

Hantering och säkerhet

Översikt över token

Under Konfiguration → Personal Access Tokens ser du alla dina token med namn, skapandedatum, utgångsdatum och senaste användning. Token i klartext visas aldrig i denna vy.

Återkalla token

Ett token kan återkallas när som helst. Efter återkallelsen avvisas alla förfrågningar med detta token omedelbart. Återkalla token genast om:

  • Token av misstag har lämnats ut
  • En enhet eller tjänst inte längre används
  • Du upptäcker misstänkt aktivitet

Utgång

Utgångna token avvisas automatiskt. Klacks visar i översikten token som löper ut inom de kommande 30 dagarna, så att du i god tid kan skapa nya token.

Säkerhetstips

  • Använd ett separat token per tjänst eller verktyg
  • Välj tydliga namn så att token kan identifieras entydigt
  • Spara aldrig token i klartext i versionshanteringssystem
  • Rotera token regelbundet
  • Återkalla token genast vid misstanke om missbruk

Varje token är kopplat till ditt användarkonto. Via MCP har token ditt kontos behörigheter, men högst på supervisornivå: även om ditt konto är administratör har token aldrig administratörsbehörighet. Åtkomstläget begränsar dessutom vad agenten får göra: med ”Endast läsning” använder den bara läsfunktioner; med ”Läsning och skrivning” utför den ändringar utan ytterligare bekräftelse. Hantera token med samma omsorg som ditt lösenord.
